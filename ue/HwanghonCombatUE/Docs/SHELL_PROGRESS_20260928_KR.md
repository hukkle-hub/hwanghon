# 사무소·훈련장 실행 흐름 진행 기록 — 2026-09-28

## 구현 범위

`HW_Lobby`에서 지하 훈련장에 출격해 실제 `HW_Training` 월드로 이동한다.
기존 전투 컴포넌트를 사용하는 공격·강타·회피·점프·반격·락온과 누르는 동안 동작하는 이동 버튼을 연결했다.
승리/패배 결과, 저장 실패 후 재시도, 새 RunId로 재도전, 사무소 복귀를 제공한다.
훈련 종료 확인 중에는 전투가 멈추며 취소하면 재개한다. 중도 종료는 클리어를 추가하지 않는다.

의뢰 6개는 기존 콘텐츠의 이름·해금·완료·보수 상태를 표시한다. 실행 가능한 전투는 훈련장 하나다.
보수 수령은 기존 프로필의 일회 수령·중복 방지·저장 재시도 규칙을 사용한다.
플레이어와 훈련체는 기본 도형으로 만든 임시 모델이다. 최종 캐릭터·애니메이션·의뢰 맵·장비/상점 화면은 남아 있다.
전투 피해량·기력·타이밍은 변경하지 않았다.

휴대폰 세로 화면에서 플레이어가 잘리는 문제를 훈련 전용 카메라로 수정했다.
좁은 화면의 버튼은 64px 이상을 유지하고, 목록/설명만 패널 안에서 스크롤한다.
그래픽 품질 적용이 창 해상도를 덮어쓰던 문제도 수정했다.

## 검증 결과와 한계

- 프로젝트 목표: UE **5.5** 유지. 설치된 UE **5.8.1**의 Windows 호환성 진단 빌드 성공.
- Unreal 자동화: **28/28**, 테스트별 경고 0. 컴파일에는 엔진 API 폐기 예정/권장 외 MSVC 버전 경고가 있다.
- `ResetRun`의 로비 이동 보호 조건을 고의로 제거하면 `ShellLobbyAcknowledgment`가 실패함을 확인했다. 원본 복구·재컴파일 후 전체 28개를 통과했다.
- 실제 Slate 포인터 입력으로 출격·락온·공격 명중·저장 재시도·재도전·복귀·종료 취소/확정을 확인했다.
- 1672×952 전체 실행 및 저장 재로드, 390×844 전체 실행, 844×390 전체 실행: **4/4**, PNG **25장**.
- 각 PNG의 실제 치수, 버튼 최소 64px, 화면 바깥/비정상 잘림, 클릭 대상 완전 노출을 검사했다. 목록 경계의 정상적인 세로 스크롤 잘림은 별도 기록한다.
- 각 전체 실행에서 훈련 기록은 0→1로만 증가했다. 패배·중도 종료는 기록을 추가하지 않았고 프로세스를 다시 시작해도 1회가 유지됐다.
- 원격 main `1f305ba`의 병행 변경을 병합한 후 `npm test`: **556/556**. 빌드 검증 스크립트 **43/43**, 구조 검사 및 Python 구문 검사 통과.

위 결과는 실제 Android 기기나 UE 5.5 실행의 증거가 아니다. 포인터 입력 자동화이며 멀티터치 실기기 검증도 남아 있다.
명중 검사는 플레이어를 보스 근처로 자동 배치한 뒤 실제 공격 버튼을 클릭한다. 승리/패배 전환에는 스크립트 치명 피해를 사용한다.
저장 실패 주입과 QA 저장 슬롯은 일반 사용자 저장과 분리되며 Shipping에서는 드라이버가 제외된다.
