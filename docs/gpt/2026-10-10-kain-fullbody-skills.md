원본 손 회전을 그대로 무기에 복사하지 않는다. 하나의 강체 대검에 두 손바닥을 17 cm 간격으로 고정하고, 팔꿈치 방향·손목 꺾임·몸통 간격을 함께 풀었다. 두 손을 따로 따라가게 하거나 뼈 길이를 늘려 맞추지 않았다. 120 Hz로 구운 팔/대검 경로를 재생하고, 런타임에는 보간 오차만 보정한다. 기존 메시의 손 쥠 모양 보정은 그대로 사용하며 **새 손가락 뼈 애니메이션을 만든 것은 아니다.**

전신 소스의 준비·타격·회수를 짧은 기존 판정 시간에 압축하지 않는다. `dungeons.js`의 카인 전용 시간표와 솔로/레이드 판정을 함께 늘렸다. 공격속도 70/100/160에서 시간이 일치한다. 철벽은 온라인에도 완전한 제스처를 보내되 기존 3초·피해 감소 60% 버프는 그대로다. 피해량·재사용 대기시간·스태미나·기존 무기 길이(준비된 대검 1.9 m)는 변경하지 않았다.

## 범위 구분 / 다음 작업

이번 새 전신 납품은 **카인 스킬 4종 + 궁극기**다. 카인 기존 평타·강타·카운터·이동/회피 클립은 이 작업에서 새 전신 소스로 교체하지 않았다. 실제 필드 평타의 왼손 이격 약 7.6 cm는 남아 있으므로 ‘카인 모든 전투 모션 완료’라고 하지 않는다. 류·세라는 새 스킬이 활성화되지 않았다. 원래 몸/코트의 스킨 늘어남 문제도 별도다.

모션 데이터 모듈 전체(아인 포함)는 4,496,942 bytes, gzip 1,933,589 bytes. 원본 및 모바일 LOD 로딩/동작은 확인했으나 Galaxy S25 Ultra 실기기 성능·발열·배터리 검수는 아직 하지 않았다. PC 브라우저 FPS를 안드로이드 성능으로 대체하지 않는다.

`kain-motion-audit.glb`는 검사 전용 복사본이다. 실제 무기·런타임 손 쥠 보정이 빠져 있어 게임용 완성 GLB로 전달하면 안 된다. 게임 반영물은 기존 몸/무기 GLB + 이번 JS 모션/양손 보정 모듈이다.

## 재생성 순서

`build-kain-skill-library.mjs <source-directory>` → 완료 후 `bake-kain-skill-grip.mjs` → 완료 후 `check-kain-skill-joints.mjs` → 검수/전체 시험/UE 콘텐츠 내보내기. 서로 동시에 실행하면 뒤 작업이 아직 구워지지 않은 데이터를 읽을 수 있으므로 순서를 지킨다. 원본 GLB는 변경하지 않는다.

재배포는 디렉터가 승인한 기존 다민 workspace 서비스에 한다. main push 자동 배포를 사용하고 별도 중복 배포를 걸지 않는다. 무료 임시 프로필 저장소의 재시작 초기화 위험은 기존 승인 범위이며, Render/Pages의 실제 반영 커밋을 각각 확인한다.

앞 납품의 팔 외형 검수 판단은 성급했다. 앞의 아래팔 축 간격만으로는 상완이 가슴에 묻히는 것을 잡지 못했고, 4개의 좁은 세로 카메라는 상완을 화면 밖으로 잘랐다. 이번에는 실제 스킨 표면 검사와 상완 간격을 추가하고, 해당 지적의 도약 타격 구간을 확대 렌더로 재확인했다.

- `kain-hand-ik.js`: 어깨 접점 자체를 제외한 상완도 몸통 축에서 떨어지도록 풂. 손목 제한을 우선 보존한다. 도약 타격 준비~회수 구간에만 팔꿈치 높이 선호를 부드럽게 적용한다(경첩 뒤집기/뼈 늘리기 아님).

- 원본/모바일 5종 × 각 241 표본: 상완 축 간격 >18 cm, 양 팔꿈치 간격 >40 cm, 기존 손 접점/손목/속도/칼날 접점 검사 통과.
