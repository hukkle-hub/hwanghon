# 파티 모집 화면 — 설계 시트 03 을 화면으로

「파티 모집 화면도 시트대로 만들어.」

## 1. 이 시트만 구현이 없었다

설계 시트 14장 중 **03-party 「파티 모집 / 인력사무실」** 하나만 대응 화면이
없었다. `party.html` 이 온라인 허브로 바뀌면서 그 자리가 비었고, 문서 26 §6 에
「미구현」으로 적어 둔 채였다.

`recruit.html` + `js/recruit.js` 로 만들었다. 다른 화면과 같은 규약
(1672×952, 상단바, 하단 네비, `data-mpane`).

## 2. 시트의 3열을 그대로

```
┌ 파티 모집 / 인력사무실 ──────────────────── 75,300 · 접속 N/100 ┐
│           파티 찾기  |  내 파티                                  │

│ 지하 훈련장│  ┌1P─┐┌2P─┐┌3P─┐┌4P─┐          │ 보스 아트         │
│ 갈대습지 S │  │초상││초상││모집││모집│          │ 격파 대상         │

│ …  7곳     │  │Lv·전투력  │    │    │          │ 주요 적 · 보수    │

```

- **임무 목록**(좌): 던전 7곳. 고르면 오른쪽 상세와 «새 파티» 의 출격 지역이
  따라간다. 줄마다 그 지역에 **공개 모집이 몇 개 있는지**를 배지로 보여 준다.
- **파티 찾기**: 고른 지역의 모집 목록. 그 지역에 없으면 전체를 보여 주고
  그렇다고 말한다 — 빈 화면을 주지 않는다.
- **내 파티**: 4인 카드. 초상은 전신 아트, 아래에 이름·캐릭터·**Lv·전투력**,
  머리에 `1P~4P` 와 상태(파티장 / 준비 완료 / 준비 중 / 재접속 대기).
  빈 칸은 점선으로 「방 코드를 전달해 동료를 부르세요」.
- 파티에 들어가면 **내 파티** 탭으로 저절로 넘어간다. 출격하면 전투 화면
  (`party.html`)으로 넘긴다.

## 3. 서버 — 한 필드만 더했다

방 프로토콜(`create`/`join`/`ready`/`start`/`leave`/`board`/`partyPurpose`)은
**이미 다 있었다.** 시트가 보여 주는 것 중 서버에 없던 건 파티원의
**레벨·전투력** 하나였다.

```js
const POWER=st=>Math.round((st?.atk||0)*6+(st?.hp||0)*0.3);
function roomState(room){const lobby=!room.raid; … lobby?lobbyInfo(id):{} …}
```

**대기 중인 방에서만** 프로필을 읽는다. 전투 중에는 방 상태가 초당 20회까지
방송되므로 거기서 DB 를 읽으면 안 된다.

> 시트의 카드에는 카운터·부위파괴·정제·드랍·제작 **5줄 등급표**도 있다.
> 그 등급은 지금 로컬 저장(`TW_GRADE`)에만 있고 서버에는 없다. 없는 값을
> 지어내지 않고 **레벨·전투력까지만** 실었다. 넣으려면 서버가 등급을
> 계산해 내려보내야 한다 — 지시를 받고 한다.

## 4. 만들면서 밟은 것 셋

1. **합류해도 2P 칸이 계속 «모집 중» 이었다.** 방 상태는 «바뀐 곳만» 보내는
   패치(`party-wire`)로 오는데 `recruit.html` 이 그 스크립트를 안 읽고 있었다.
   패치를 못 풀어 상태가 영영 갱신되지 않았다.
2. **`hidden` 속성이 안 먹고 있었다.** `.btn` 이 `display:inline-flex` 를 정해
   버려서 「코드 복사」·「파티 나가기」, 쉘터의 「공개 모집」·「공지 저장」이
   숨겨지지 않고 계속 보였다. `ui.css` 에 `[hidden]{display:none!important}`.
3. 그 `!important` 가 **내가 방금 넣은 인라인 `display:grid`를 이겼다** —
   파티 칸이 통째로 안 보였다. display 를 스타일시트로 옮겨 해결.
   (2번을 고치자마자 3번이 났다. 고친 뒤 반드시 다시 돌려 봐야 한다.)

`.field` 안의 `select` 에 규칙이 없어 「공개 — 모집 목록에 올린다」가 잘리던
것도 같이 고쳤다.

## 6. 남은 셋을 마저 넣었다

「남은 것들도 다 반영해.」 §6 에 적어 둔 셋을 전부 붙였다. 셋 다 **서버에 없던
축**이라 서버부터 고쳤다.

### 6.1 카드의 5줄 등급표

오프라인은 `js/grade.js` 가 `save.stats` 의 카운터를 세어 등급을 낸다. 서버는
그 기록을 **한 번도 프로필에 쌓지 않았다** — `raid.result.players` 에 한 판치가
잠깐 있다가 사라졌다. 그래서 §3 에 「없는 값을 지어내지 않았다」고 적었던 것이다.

`server/rpg-store.cjs` 에 같은 점수식·같은 임계값을 넣고, 누적을 시작했다.

```js
TECH:['C','B','A','S','SS'],
TECH_TH:{counter:[0,15,45,120,300],break:[0,20,60,150,350],
         refine:[0,12,40,110,260],drop:[0,15,50,140,320],craft:[0,10,35,100,240]},
bumpSkill(p,patch){…}          // 프로필 안의 누적 카운터 p.skill
techScores(st){…} techGrades(id){…}
```

쌓는 자리는 넷이다 — 클리어 정산(`queueRewards`: 카운터·퍼펙트·부위 파괴·획득
아이템·희귀), 제작(`craft`), 강화 성공(`enhance`), 수리(`repair`), 소모품
사용(`consume`). 부위 파괴 **비율**의 분모가 없어서 `server/raid.cjs` 의
결과에 `breakable`(그 보스의 파괴 가능 부위 수)을 함께 실었다.

대기 중인 방에서만 읽는다 (`lobbyInfo`). 등급이 안 오면 카드는 그 표를 아예
그리지 않는다 — 없는 값을 C 로 채우면 「아직 안 왔다」와 「정말 C」를 구별할 수
없다.

### 6.2 필터 바

시트 그대로 여섯 칸: **난이도 · 역할 · 전투력 제한 · 모집 중만 보기 ·
내 직업만 보기 · 새로 고침**. 전부 **서버가 실제로 내려 주는 값**으로만 거른다.

| 칸 | 기준 | 어디서 왔나 |
|---|---|---|
| 난이도 | 던전 `diff` 의 등급 (`의뢰 S · 외곽지대` → S) | 이미 있던 데이터 |
| 역할 | 방에 그 캐릭터가 있는가 | `board` 에 `chars` 추가 |
| 전투력 제한 | 조건 없는 방만 / 내 전투력으로 가능 | `board` 에 `minPower` 추가 |
| 모집 중만 보기 | `count < 4` | `board` 가 **가득 찬 방도** 보내게 바꿈 |
| 내 직업만 보기 | 내 캐릭터가 아직 없는 방 (= 내 자리가 비었다) | `chars` |
| 새로 고침 | `{type:'board'}` (1초 1회) | 새 명령 |

`board` 가 가득 찬 방을 빼고 보내고 있어서 「모집 중만 보기」가 아무것도 안
거르는 장식이 될 뻔했다. 방을 다 보내고 화면이 거르게 바꿨고, 같은 목록을 쓰는
`js/party-online.js` 의 「참가」 단추는 `count>=4` 면 잠그도록 함께 고쳤다.

### 6.3 모집 조건 (최소 전투력 · 음성 채팅)

모집 설정 아래 두 줄. **최소 전투력은 서버가 지킨다** — 화면에서 지우고 보내도
`join()` 이 막는다 (파티장 본인은 제외). 음성 채팅은 목록과 방 머리에 표시만
한다.

```js
function join(room,profile){
  if(room.minPower&&room.leader!==profile.id&&POWER(profile.stats)<room.minPower)
    throw Error('이 파티는 전투력 '+room.minPower.toLocaleString()+' 이상만 참가할 수 있습니다.');
```

## 7. 마지막 둘 — 임무 목록과 임무 상세

「남은 두 개도 다 반영해.」 둘 다 **새 데이터를 만들 필요가 없었다.**
`js/world.js` 의 `QUESTS` 에 `art` · `area/sub` · `lv` · `tags` · `recCp` ·
`rewards` 가 처음부터 다 있었다. 화면이 그걸 안 읽고 있었을 뿐이다.

### 7.1 임무 목록 — 썸네일 · 종류 탭 · 갱신

시트 그대로 한 줄이 **썸네일 + 임무명 + 지역 + Lv + 모집 배지**가 되고,
위에 종류 탭 넷, 아래에 「임무 목록 갱신」이 붙었다.

종류는 **겹칠 수 있는 «보기»** 다 (분류가 아니다). 셋 다 있는 데이터를 읽는다.

| 탭 | 무엇을 보나 | 근거 |
|---|---|---|
| 전체 | 7곳 | — |
| 스토리 | 아직 안 깬 곳 = 본편에서 다음에 갈 곳 | 프로필의 `clears` |
| 의뢰 | 난이도가 「의뢰 …」 인 곳 (훈련장 제외) | 던전의 `diff` |
| 토벌 | 의뢰 태그에 「토벌」 이 붙은 변이체 사냥 | `world.js` 의 `tags` |

클래스 이름 하나로 한 번 막혔다. `.mtabs` 를 썼는데 그 이름은 `css/mobile.css`
가 **모바일 페인 탭 바**로 이미 쓰고 있었고 (`.mtabs{display:none}` 이 기본),
데스크톱에서 종류 탭이 통째로 안 보였다. `.ktabs` 로 바꿨다.

### 7.2 임무 상세 — 권장 전투력 · 보상 정보 4칸

`recCp` 를 그대로 싣고, 내 전투력이 모자라면 **붉게** 말한다. 보상 4칸은
`rewards` 네 칸(EXP · 재화 · 재료 둘)을 인력사무실과 **같은 컴포넌트**로
그린다 — 그래서 `.rewards`/`.rw` 를 `office.html` 의 로컬 스타일에서
`css/ui.css` 로 옮겼다 (두 화면이 같이 쓴다).

두 블록을 넣자 오른쪽 열이 **230px 넘쳐서** 권장 전투력·보상이 화면 밖으로
밀려났다. 시트에 없던 것부터 걷어 냈다.

- 「격파 대상」 두 줄 → 아트 위 캡션으로 접었다 (시트에 없다)
- 「의뢰 보수」 한 블록 → 권장 전투력과 한 줄에 좌·우로 앉혔다
- 아트 96→76px, 구분선·라벨 여백을 이 화면에서만 조였다
- 「방 코드 합류」 입력과 「참가」 를 한 줄로 접었다

7개 의뢰를 다 눌러 `scrollHeight - clientHeight` 를 재서 **전부 0** 인 것을
확인했다. 눈으로 보고 「들어간 것 같다」로 끝내지 않는다.
