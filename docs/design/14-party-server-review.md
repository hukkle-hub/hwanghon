# 황혼 협동 파티 서버 구현 기록

검증 환경: 2026-09-18, Node.js v24.19.0. 이전 던전 구현 커밋 `0acefe0` 위에 추가한 변경입니다.

## 구현한 사용자 흐름

서버 접속 → 닉네임 등록 → 방 생성 또는 코드 참가 → 2–4명 전원 준비 → 파티장 출격 → 공유 던전 조사 → 보스전 → 동료 소생 또는 전멸 재도전 → 파티원별 보상 저장 → 같은 파티로 다음 출격.

기존 `party.html`의 가상 인원 목록을 실제 WebSocket 접속 인원으로 교체했습니다. 각 플레이어는 독립적으로 아인을 조작합니다. 다른 캐릭터와 직업 선택은 후속 범위입니다. 기존 아인·낫·허수아비·모르버스 GLB와 정화장 보스 리그, 전투 모션 어댑터를 재사용합니다.

## 서버와 클라이언트의 책임

| 구성 | 책임 |
|---|---|
| `server/index.cjs` | HTTP 정적 자산, WebSocket 세션, 방·준비·파티장, 90초 재접속, 입력 순서·빈도 제한 |
| `server/content.cjs` | 기존 캐릭터·전투 규칙·아레나·던전 정의를 서버에서 읽기 |
| `server/raid.cjs` | 하나의 던전 세계와 보스, 독립된 플레이어 상태, 공격·회피·카운터·파괴·소생·보상 결과 |
| `server/store.cjs` | 접속 키 해시, 프로필·보상·출격 정산 영수증 저장, 중복 지급 방지 |
| `js/party-online.js` | 조작 의도 전송, 상태 보간, 실제 접속자 UI, 기존 3D 모델과 모션 재생 |
| `party.html`, `css/party-online.css` | 모집·던전·전투·결과 화면, 모바일 스틱·동시 터치 버튼 |

서버는 10ms 단위로 시뮬레이션하고 상태를 초당 20회 전송합니다. 클라이언트는 이동 방향·공격·회피·조사 같은 의도를 보냅니다. 좌표·피해·체력·보상 값을 클라이언트가 직접 확정할 수 없습니다. 입력 순번이 이전 입력보다 작거나 같으면 무시합니다. 이동 방향은 정규화하고, 마지막 이동 입력 이후 250ms가 지나면 정지합니다.

기존 싱글 전투 파일 자체를 다중 실행하는 방식이 아니라 공유 세계 전용 `Raid`를 추가했습니다. 기존 `RULES`, `SKILLS`, `ARENAS`, `world-sim`, `boss-director`, `dungeon-run`은 공유합니다. 따라서 이후 전투 수치 변경 시 싱글과 파티 테스트를 함께 실행해야 합니다.

## 전투와 탐색

- 보스 체력과 파괴 부위 체력은 출격 인원에 따라 `1 + 0.65 × (인원 - 1)` 배율을 적용합니다. 출격 중 이탈해도 배율은 바뀌지 않습니다.
- 보스는 생존·접속 중인 파티원의 거리와 누적 위협을 보고 표적을 선택합니다. 공격을 예고한 뒤에는 공격 범위를 확정합니다. 해당 범위에 들어온 모든 플레이어가 각각 피격/회피/방어 판정을 받습니다.
- 일반 공격은 단계별 저효율 계수를 적용합니다. 카운터는 2.5배, 마지막 40ms의 퍼펙트는 3배 보상 계수입니다. 성공한 카운터는 공유 보스의 공격을 한 번 중단합니다. 같은 공격에 여러 명이 중복 카운터 보상을 받지 않습니다.
- 실제 위협을 회피한 뒤 0.85초 내의 반격은 2.2배, 방어 후 반격은 1.5배 보상 계수입니다. 빈 공간에서 회피만 반복해서 보상을 만들 수 없습니다. 이후 약점·장갑·격추 계수가 함께 적용됩니다.
- 타격은 입력 순간이 아닌 모션 접촉 시점에 발생하며, 그때 사거리·시선·공격 방향을 다시 확인합니다.
- 부위 파괴는 공유 상태를 바꾸고 해당 패턴을 제거하거나 약화합니다. 허수아비의 별도 탈착 장식 메시 연출은 온라인 화면에서 아직 생략되어 HUD와 경직으로 표시합니다. 모르버스·정화장 보스의 기존 `piece_` 노드는 파괴 시 숨깁니다.
- 밸브·조사·정비는 공동 완료 기록입니다. 보급품은 성공한 출격의 보상에 한 번 합산하여 파티원 각각에게 지급합니다. 정비 지점은 한 번 사용되며 주변 생존자를 함께 회복합니다.
- 소생은 거리·벽·생존 시간·시전자 행동을 검사합니다. 3초 유지, 체력 30%, 각 플레이어 출격당 최대 2회이며 다운 후 20초가 지나면 소생할 수 없습니다. 전멸한 파티는 파티장이 재도전합니다.
- 전원이 끊기면 전투 시간을 멈춥니다. 한 명이라도 접속 중이면 끊긴 캐릭터도 전장에 남아 피해를 받을 수 있습니다. 서버가 계속 실행 중이고 90초 이내이면 같은 키로 복귀합니다.

## 보상과 저장

별도 게스트 프로필에 골드·XP·재료·클리어 횟수·출격별 정산 영수증을 저장합니다. 기본 경로는 `.party-data/profiles.json`, `DATA_DIR`로 변경 가능합니다. 접속 키는 32바이트 난수이고 서버에는 SHA-256 해시만 저장합니다. 방 참가자에게 다른 사람의 키를 전송하지 않습니다.

임시 파일 작성 후 교체하는 방식으로 저장합니다. 보상 저장이 실패하면 메모리 변경도 되돌리고 결과 화면에 저장 대기를 표시하며 5초마다 재시도합니다. 같은 출격 ID에는 중복 지급하지 않습니다. 실패 중 프로세스 종료 또는 방 자체가 사라지는 경우까지 복구하는 트랜잭션 저널은 아직 없습니다. 운영 시 영구 디스크 및 백업이 필요합니다.

싱글 브라우저 저장을 서버가 신뢰해서 가져오지 않습니다. 따라서 기존 싱글 장비·제작·강화 및 의뢰 완료와 협동 프로필 사이의 동기화는 후속 구현입니다. 현재 파티원은 모두 기본 아인 전투 스탯을 사용합니다.

## 배포 범위와 후속 작업

`PARTY_QUICKSTART.md`에 PC/휴대폰 동일 Wi-Fi 접속, Docker Compose 및 Render 배포 절차를 넣었습니다. `render.yaml`은 무료 단일 인스턴스의 플레이테스트 설정이며 자동 배포를 끕니다. Render 배포 스킬의 기본 무료 요금제 지침을 적용했습니다. 무료 인스턴스에서는 재시작·재배포·유휴 종료 시 파일 저장이 사라지므로 `EPHEMERAL_STORAGE=1`로 게임 화면에 초기화 가능성을 표시합니다. 영구 운영은 유료 디스크 또는 별도 DB 구성과 비용 확인이 필요합니다. 파일 생성만으로 서비스가 생성되지는 않습니다.

현재는 단일 Node 프로세스의 소규모 협동 개발 빌드입니다. 설정상 접속/방 상한은 부하 측정으로 보장한 동시 수용 인원이 아닙니다. 방·던전은 메모리에만 있으므로 서버 재시작/배포 시 출격이 종료됩니다. 여러 인스턴스 운영, 회원 계정·기기 이전, 저장 DB·관리 도구, 대규모 부하·악용 대응, 매치메이킹, 관전/중도 합류는 미구현입니다.

카운터는 서버 도착 시각으로 판정합니다. 높은 지연 환경의 40ms 퍼펙트 판정을 위한 입력 시각 검증·지연 보정과 실제 기기 테스트가 우선 후속 과제입니다. 전역 히트스톱·랜덤 치명·출혈 등 일부 싱글 전투 세부 효과도 파티 서버에 아직 이식하지 않았습니다.

공식 배포 근거: [Render WebSockets](https://render.com/docs/websocket), [Blueprint 명세](https://render.com/docs/blueprint-spec), [영구 디스크](https://render.com/docs/disks). Render 플러그인은 연결 및 설치 완료 상태로 확인했습니다. 다만 이 실행 세션에는 서비스 조회·생성 도구가 노출되지 않아 공개 서비스 생성은 완료하지 못했습니다. Render 연결 진단 스킬은 설치 후 도구 재로딩/새 스레드를 안내합니다. 기존 GitHub 쓰기 연결도 403으로 차단되어 변경본 업로드는 완료되지 않았습니다. 배포 전에 변경 커밋이 GitHub에 존재하는지 확인해야 합니다.
