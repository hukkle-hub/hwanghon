# 황혼 — 보스전 재설계 v0.1 (연계 · 지연타 · 타격감 · 모션)

> 2026-09-19 · 목적: 바닥 게이지를 걷어내고 «모션으로 읽는» 보스전으로 바꾼 뒤,
> 읽을 모션 자체를 만들어 준다. 연계·지연타(무엇을 읽나) → 모션(어떻게 보이나) →
> 타격감(맞췄을 때 무엇이 돌아오나) 세 축을 한 묶음으로 본다.
>
> 이 문서는 우리 엔진(`js/combat.js` · `js/game3d.js` · `server/raid.cjs`) 기준의 **설계 선택**이다.
> 참고작의 내부 구현을 재현했다는 뜻이 아니고, 아래 수치는 우리 검수 목표값이다.

## 0. 왜 지금인가

`8a19cb6` 에서 훈련장(d01) 밖의 바닥 예고에서 «차오르는 게이지»와 «카운터 흰색 점등»을 없앴다.
이제 타격 시점을 알려 주는 것은 **보스 공격 클립의 스크럽**뿐이다. 그런데 지금 보스는
예고 하나당 타격 하나라, 읽을 것이 한 박자밖에 없다. 읽기를 요구해 놓고 읽을 거리를 주지
않은 상태다. 연계와 지연타가 들어가야 앞의 변경이 완성된다.

## 1. 조사에서 가져온 규칙

### 1-1. 연계 문자열과 지연타 (소울라이크 계열)

- 딜레이(지연) 공격은 다크 소울 1 → 엘든 링으로 갈수록 늘었고, **불만의 원인은 딜레이 자체가
  아니라 «예고 없는 딜레이»** 였다. 공격 모션이 너무 빨라 반응할 수 없으면 암기 게임이 된다.
- 라단은 공격 문자열 수가 많고, 분기가 넓고, **반격 창이 좁고 활성 구간이 길다**. 2차 타격을
  과하게 반복해 사실상 회피 불가능한 구간을 만드는 것이 주된 비판점이었다.
- 반대로 다크 소울 3의 노예기사 게일은 **연계가 3~6타로 짧고, 중요한 지연타는 하나뿐이며,
  마무리 타격이 확실히 예고되고 그 뒤에 반격할 큰 틈**이 있다. 평가가 가장 좋은 쪽이다.
- 세키로에서도 «위험» 표시가 모션을 가리는 순간이 문제로 지적됐다. 표시가 모션을 덮으면
  모션 읽기는 성립하지 않는다.

**우리가 채택하는 선**

| 규칙 | 값 | 이유 |
|---|---|---|
| 연계 길이 | **2~3타**, 광란 페이즈에서만 최대 4타 | 게일 쪽. 6타는 우리 모바일 조작에서 과하다 |
| 지연타 빈도 | 보스당 **패턴 하나**에만 | "중요한 지연타는 하나" |
| 지연타 표현 | 모션이 **눈에 띄게 멈춘다** (0.25~0.45초) | 예고 없는 딜레이가 아니게 만드는 유일한 장치 |
| 반격 창 | **연계 마지막 타격**에 열린다. 중간 타격은 회피 전용 | 마무리가 예고되고 뒤에 틈이 있는 구조 |
| 마무리 후딜 | 연계 길이에 비례해 길어진다 (1타 0.8초 → 3타 1.5초) | 길게 몰아쳤으면 그만큼 돌려준다 |
| 화면 표시 | 바닥은 범위만. 모션을 가리는 표시는 만들지 않는다 | 세키로의 실패 사례 |

### 1-2. 타격감 (game feel)

- **히트스톱**은 충돌 순간 화면 전체를 1~5프레임, 대략 **40~80ms** 멈추는 것으로, 어떤
  애니메이션보다 무게를 잘 전달한다. 세기에 비례해야 한다.
- **화면 흔들림**은 **타격 방향을 따라** 주고 **지수 감쇠**로 빨리 가라앉힌다. 상시 흔들림은
  가독성을 해치고 멀미를 만든다.
- 히트스톱 · 흔들림 · 파티클 · 소리는 **같은 프레임**에 나가야 한다.
- 맞은 쪽은 반드시 **반응**한다. 섬광 → 경직/넉백/다운. "맞았다"가 즉시 읽혀야 한다.
- 이 모든 게 절차적이고 싸다. 최종 아트 없이도 회색 상자로 먼저 완성할 수 있다.

**우리 수치표** (`RULES.hitstop` 을 계층으로 확장 — 아래가 실제로 들어간 값)

| 상황 | 히트스톱 | 흔들림(축) | 파티클 | 진동 |
|---|---|---|---|---|
| 약타 1~2타 | 0.06초 | 없음 | 8, 타격 벡터 | — |
| 약타 3~4타 | 0.09초 | 0.003 · 120ms | 14, 타격 벡터 | 10ms |
| 스매시·궁극기 | 0.15초 | 0.008 · 240ms | 26, 타격 벡터 | 25ms |
| 튕겨내기 | 0.16초 | 0.010 · 300ms | 30, 보스→플레이어 축 | [20,30] |
| 퍼펙트 | 0.20초 | 0.012 · 340ms | 40, 보스→플레이어 축 | [20,40,20] |
| 부위 파괴 | 0.24초 | 0.014 · 400ms | 48, 부위 바깥 방향 | [30,40,30] |
| 피격(방어) | 0.05초 | 0.004 · 200ms | 10 | 15ms |
| 피격(직격) | 0.09초 | 0.012 · 300ms | 18, 보스→플레이어 | 60ms |

기존 값은 `hitstop:{hit:0.08, counter:0.16, brk:0.24}` 로, 약타와 스매시가 같았다.
"4연타가 전부 같은 무게로 느껴진다"의 원인이다.

**왜 40~80ms 를 그대로 쓰지 않았나.** 우리 `js/combat.js` 에서 히트스톱은 시뮬레이션 전체를
멈추므로 **공격 간격까지 줄인다.** 약타를 0.04초로 내리면 마구 누르기만 해도 훈련장이 뚫려
`tests/combat.test.cjs` 의 "spam 은 실패한다" 가 깨진다. 그래서 4연타+스매시 한 사이클의
합계를 기존(0.40초)과 비슷하게 유지하면서(0.06+0.06+0.09+0.09+0.15 = 0.45초) **비율만**
2.5배로 벌렸다. 약타와 스매시의 무게 차이는 살리고 난이도는 건드리지 않는다.

**피격 정지는 규칙이 아니라 연출이다.** 맞았을 때의 정지를 `P.hitstop` 에 넣으면 보스의
후딜까지 멈춰 전투 밸런스가 바뀐다(실제로 두 개의 밸런스 테스트가 깨졌다). 그래서
`damaged` 이벤트에 `stop` 값만 실어 보내고, 렌더러가 `slowmo()` 로 짧게 멈춘다.

### 1-3. 모션

- 우리 리그는 Three.js `AnimationMixer` 다. 상체·하체 분리나 «숨쉬기 덧입히기» 는
  `AnimationUtils.makeClipAdditive` 로 클립을 가산형으로 바꾼 뒤 `AdditiveAnimationBlendMode`
  로 얹는 것이 정석이다. 블렌드 모드만 바꾸면 스케일이 깨진다.
- 예고 모션은 `bossOnce(clip, speed)` 로 재생한 뒤 예고 진행률로 **스크럽**하고 있다
  (`js/game3d.js` 의 `boss.oneshot.time = dur*hitFrac*progress`). 지금은 progress 가 선형이라
  모션이 곧 카운트다운이다. **이징을 넣어 선형이 아니게** 만들어야 «모션으로 읽되 초를 세게
  하지는 않는다» 가 성립한다.

**윈드업 곡선** — 예고 진행률 `t`(0→1) 를 모션 진행률 `w` 로 바꾸는 함수를 비트마다 둔다.

| 종류 | 곡선 | 체감 |
|---|---|---|
| `ease` (기본) | `w = t²` 로 시작이 느리고 끝이 빠르다 | 천천히 들어올렸다 확 내려친다 |
| `hold` (지연타) | `at` 까지 올라가고 `dur` 동안 **정지**, 남은 구간에서 마저 | 들어올린 채 «버틴다» — 성급한 회피를 부른다 |
| `linear` | 기존 | 훈련장 전용 |

## 2. 보스별 적용안

`chain[]` 은 첫 타격 뒤에 이어지는 비트다. `gap` 은 앞 타격이 끝난 뒤 다음 예고까지의 간격.

### d02 모르버스 (갈대습지) — «달려들고 후려치는» 짐승 리듬
| 패턴 | 구성 | 비고 |
|---|---|---|
| 돌진 베기 | 2연격 | 두 번째만 튕기기 가능 |
| 대지 강타 | **지연타** `hold{at:.58, dur:.35}` | 보스당 하나뿐인 지연타 |
| 꼬리 휘두르기 | 단타, 넓은 원 | 회피 전용(주황) |
| 광폭 포효 | 단타 + 후딜 1.3초 | 확실한 반격 창 |
| (광란) 피의 광란 | **3연격** | 마지막만 튕기기 가능 |

### d03 오염 수문기 (2경구 정화장) — «기계적으로 반복되는» 압력 리듬
| 패턴 | 구성 | 비고 |
|---|---|---|
| 압력 망치 | 내려찍기 → 되돌림 2연격 | 배관 파괴 시 1타로 |
| 고압 분사 | 3연속 직선 | 1·2타는 회피 전용, 3타에서 반격 창 |
| 배출관 쓸기 | **지연타** `hold{at:.6, dur:.3}` | |
| 과압 폭발 | 단타, 전역 | 기존 유지 |

### d04 과부하 계전기 (3경구 변전소) — «충전하고 방전하는» 전기 리듬
| 패턴 | 구성 | 비고 |
|---|---|---|
| 접점 내려찍기 | 좌 → 우 → 중앙 3연격 (광란에서만 3타) | 접점 파괴로 해당 타격이 빠진다 |
| 모선 방전 | **지연타** `hold{at:.5, dur:.45}` — 코일이 부푼 채 버틴다 | 가장 긴 지연 |
| 접점 쓸기 | 2회전 | 1타는 회피 전용, 2타에서 반격 창 |
| 과부하 방전 | 단타, 전역 | 기존 유지 |

### d01 훈련장 — **단타 유지**
가르치는 곳이다. `tell:'teach'` 와 함께 연계도 넣지 않는다.

## 5. 구현 결과와 실측 (2026-09-19)

### 도중에 찾은 버그 — 보스가 단조로웠던 진짜 이유

`js/boss-director.js` 의 `pick()` 이 **직전 패턴을 제외한 짧은 목록에 index 를 씌우고**
있었다. 후보가 3개일 때 목록이 2개로 줄면서 `index % 2` 가 되어, **두 패턴만 무한히
왕복하고 세 번째 패턴은 영영 나오지 않았다.** d03 을 80초 돌린 표본에서 `배출관 쓸기` 가
단 한 번도 나오지 않은 것으로 확인했다. 전체 후보를 순환하면서 직전 패턴만 건너뛰도록
고쳤고, 고친 뒤 같은 조건에서 바로 나왔다. d02·d03 이 "단조롭다" 는 체감의 큰 몫이
연출이 아니라 이 버그였다.

### 헤드리스 실측

| 항목 | 결과 |
|---|---|
| 연계 | d04 `접점 내려찍기 1/2 (ctr=false)` → `link` → `2/2 (ctr=true)`. d03 `압력 망치 1/2 → 2/2` 동일 |
| 비트별 모션 | 1타 `atk_slam`(우 접점) → 2타 `atk_slam_l`(좌 접점). 좌우 원투로 읽힌다 |
| 지연타 | d03 `배출관 쓸기` 에서 windup 이 0.600 에 고정된 구간 **게임시간 0.30초** (표본 t=7.73→8.03, prog 는 0.53→0.66 으로 계속 진행) |
| 모션 ≠ 초읽기 | `|windup − prog|` 평균 0.12~0.17, 최대 0.25 |
| 히트스톱 계층 | 관측 0.09 / 0.06 (약타·연타). 스매시·카운터는 봇이 쓰지 않아 미관측, 값은 표 그대로 |
| 회귀 | `npm test` 97/97. 봇 2인이 d01~d03 전 페이즈를 연계·지연타 포함해 클리어 |

측정 스크립트는 스크래치패드의 `bossprobe.mjs` (씬 그래프와 스냅샷을 직접 샘플링). 헤드리스는
실시간의 약 10% 로 돌기 때문에 «초» 는 모두 게임 시간 기준이다.

### 온라인 반영

`server/raid.cjs` 에 같은 `chain`/`hold`/`windup` 규칙을 넣었다(서버 권위). 스냅샷에
`windup` 과 `pattern.hold` 를 실어 보내고, `js/party-online.js` 가 같은 식으로 보스 모션을
스크럽한다. 온라인에서도 카운터 창 «흰색 점등» 과 "지금 카운터" 문구는 훈련장 전용으로 내렸다.

## 7. 애니메이션 파이프라인 (`tools/3d/rig_char.py`)

캐릭터당 **클립 21 → 27종**. 새로 넣은 것: `skill1~4`, `exec`(처형), `counter`(칼 맞대기).

|---|---|

## 8. 연출

- **카운터** — 무기가 맞물리는 지점에서 불꽃이 **접촉면과 수직인 옆 방향**으로 뿜어지고,
  퍼펙트는 0.30초 / 일반은 0.22초 동안 화면이 거의 멈춘다. 그 뒤 서서히 풀리면서 보스가
  뒤로 밀린다(퍼펙트 34, 일반 24). 카메라는 타격 축으로 흔들리고 줌이 한 번 들어간다.
- **처형** — 자세가 무너져 격추되면 붙어서 `F`. 버튼이 붉게 맥동한다. 카메라가 보스 머리
  쪽으로 0.55초 붙었다가, 내리꽂는 순간 0.36초 정지 + 화면 섬광 + 파티클 70 + 링,
  `E X E C U T E` 배너. 격추 1회당 한 번, 배율 4.5배.
- **페이즈 전환** — 입력을 끊고(cine) 카메라를 보스에 0.8초 붙인 뒤, 부위 폭발·포효·기둥
  VFX 와 `P H A S E 2` / `F I N A L` 배너, 0.35 슬로우모션. 2.85초 뒤 다음 페이즈 시작.
- **스킬 단계** — 레벨 1~5 가 연출 규모에 그대로 들어간다(`g = 1 + (lv−1)×0.22`).
  4레벨부터 아크가 커지고, 3레벨부터 광역기에 두 번째 링이 붙는다. 분기(A/B)는 색과
  버프 링 크기로 구분된다. 데미지 숫자 옆에 `Lv3 · A` 처럼 표기.
- **회피** — 스틱 방향을 바라보는 방향 기준으로 돌려 `roll`/`dodgeB`/`dodgeL`/`dodgeR` 중
  맞는 것을 고른다. 그림자 걸음은 구르기가 아니라 `skill2`(도약)로 나간다.
- **몬스터헌터식 타격 정지** — 히트스톱 동안 시뮬레이션은 멈추지만 FX 는 실시간으로 돌아간다.
  그 «멈춘 프레임» 에 충격 표식(스프라이트 + 링)이 남았다가, 정지가 풀리면서 궤도가 이어진다.
  세기별로 크기가 다르다(약타 1.1 → 치명 2.0 → 스매시 2.8 → 퍼펙트 카운터 3.4).
- **피격 가시성** — 보스 피격 흔들림 폭을 0.05 → 0.085 로, 섬광을 0.12 → 0.2 로 올렸다.

## 13. 락온 카메라와 페이즈 2 아레나 변화 (v0.3)

### 락온 카메라

전투 중 **기본으로 켜져 있고** `T` 또는 화면 버튼으로 끈다.

- **보스를 놓치지 않는다.** 시점 추종이 `dt×1.6` → `dt×4.5` 로 빨라지고, 드래그로 돌린
  시점도 락온 중에는 바로 회수된다 (끄면 예전처럼 자유 시점).
- **멀어지면 물러난다.** 플레이어–보스 거리에 따라 카메라가 최대 **1.45배** 뒤로 빠지고,
  바라보는 지점이 둘의 가운데 쪽(0.28→0.50)으로 옮겨가 **둘 다 화면에 남는다.**
- **조준 부위에 표식**이 붙어 맥동한다. 격추·처형 가능할 때는 주황으로 바뀐다.

### 페이즈 2 아레나 변화

아레나마다 `stageFx[페이즈]` 를 둔다. 페이즈가 시작될 때 **조명·안개·하늘색**이 바뀌고,
바닥에 **위험 구역**이 생긴다. 구역은 «경고 → 발동 → 꺼짐» 을 돌고, 발동 중에 서 있으면
지형이 피해를 준다 — 보스 패턴이 아니므로 `battle.hazard()` 라는 별도 경로로 들어간다.

| 아레나 | 광란 페이즈의 변화 | 구역 |
|---|---|---|
| d01 훈련장 | 비상등이 들어온다 (분위기만) | **없음** — 가르치는 곳이다 |
| d02 갈대습지 | 늪이 끓어오른다 | 3곳, 주기 4.4~5.0초, 피해 7~8% |
| d03 정화장 | 배수구가 터진다 | 3곳, 주기 4.0~4.6초, 피해 7~8% |
| d04 변전소 | 바닥 모선에 전압이 걸린다 | 4곳, 주기 3.6초, 피해 7% |

`dx/dy` 는 **보스 자리 기준 오프셋**이라 맵이 달라도 같은 형식으로 쓴다. `damage` 는
최대 체력 비율, 판정 간격은 0.9초, **회피 중에는 맞지 않는다.**

**솔로·온라인 같은 데이터, 같은 규칙.** 서버(`server/raid.cjs`)가 `arenaPhase()` 로 위상을
계산해 피해를 주고 스냅샷에 `arena.hazards[].phase` 를 실어 보내면, 클라이언트는 그대로
그린다. 두 화면의 «켜지는 시점» 이 어긋나지 않는다.
