# 황혼 · 쉘터와 인력사무소 / 100명 접속 구조

## 사용자 확정 범위

- 세계 전체 목표 동시 접속은 100명, 던전은 파티별 최대 4명입니다.
- 별도의 공동 마을 지도·건물·이동 캐릭터를 만들지 않습니다. 이번 작업 중 만들어 보던 마을 3D 코드는 제거했습니다.
- **쉘터**는 길드 소속·접속 상태·초대 코드·길드 채팅을 이용하는 텍스트형 쉼터입니다.
- **인력사무소**는 공개 모집 목록, 코드 참가, 준비, 2–4인 출정과 귀환 화면입니다.
- 기존 던전의 아인·보스 화면은 계속 사용합니다. 새로운 로비 캐릭터·직업·외형은 만들지 않았습니다.

## 로그인과 캐릭터 이름

계정 생성 또는 로그인 → 처음 접속한 캐릭터의 이름 지정 → 쉘터·인력사무소 이용 순서입니다. 계정 ID는 영문·숫자·밑줄 4–32자, 비밀번호는 10자 이상 128바이트 이하입니다. 캐릭터 이름은 한글 등 문자·숫자·밑줄 2–16자로, Unicode NFKC 정규화 후 대소문자를 구분하지 않고 전 서버 중복을 검사합니다. 이름을 정하기 전에는 모집·출정·채팅을 할 수 없습니다. 현재 이름 변경 기능은 없습니다.

체험 접속도 가능하며, 이후 계정 등록을 하면 같은 캐릭터의 이름·재료·장비·보상을 그대로 계정에 연결합니다. 다른 기기에서는 계정 ID/비밀번호로 로그인합니다. 한 캐릭터는 한 접속만 조작할 수 있고 새 로그인은 이전 접속을 대체합니다. 비밀번호는 salt를 사용한 scrypt 해시로, 접속 키는 SHA-256 해시로 저장합니다. 로그인 시 접속 키를 교체하고 로그아웃 시 폐기합니다. 계정 가입 후 비밀번호 재설정·이메일 인증·관리자 복구 UI는 아직 없습니다.

## 채팅과 길드

| 채널 | 받는 사람 | 이용 장소 |
|---|---|---|
| 월드 | 접속 중인 모든 유저 | 쉘터·인력사무소·던전 |
| 길드 | 서버 DB에 같은 길드로 등록된 유저 | 쉘터·인력사무소·던전 |
| 파티 | 현재 같은 파티의 멤버 | 인력사무소·던전 |

클라이언트가 임의로 보내는 길드 ID나 발신자 이름은 사용하지 않습니다. 서버가 실제 소속과 캐릭터 이름을 결정합니다. 길드·파티 탈퇴 후 해당 비공개 채널을 보낼 수 없고 재조회 기록에도 포함되지 않습니다. 클라이언트에는 채널 선택과 던전 중 열 수 있는 채팅 패널이 있습니다.

메시지는 160자, 전송 간격은 1초입니다. HTML을 실행하지 않고 텍스트로 표시합니다. 채널별 최근 50개를 서버 메모리에 유지하며 서버 재시작 시 대화 기록은 지워집니다. 신고·차단·운영자 제재 도구는 후속 범위입니다.

계정에 연결한 캐릭터는 길드를 만들거나 초대 코드로 합류할 수 있습니다. 한 캐릭터는 한 길드에만 속하며 길드 정원은 100명입니다. 길드장 탈퇴 시 남은 멤버에게 길드장을 넘기고, 마지막 멤버 탈퇴 시 길드를 정리합니다. 길드 소속·이름·초대 코드는 DB에 저장됩니다.

## 영구 저장과 거래

기존 JSON 저장을 단일 프로세스 SQLite DB(`DATA_DIR/world.sqlite`)로 전환했습니다. WAL과 FULL 동기화를 사용하며 계정, 캐릭터 이름, 장비·성장·재료, 길드, 보상 영수증, 거래소 물품 및 거래 내역을 저장합니다. 기존 `profiles.json`은 처음 실행할 때 한 번 읽어 이전하며 원본을 삭제하지 않습니다. 이전 저장의 이름은 첫 접속 시 중복 검사를 거쳐 다시 확정합니다.

재료 거래는 등록 시 수량을 보관하고, 구매 시 구매자 골드·판매자 골드·물품·거래 내역을 하나의 트랜잭션으로 처리합니다. 동시에 같은 물품을 구매해도 한 거래만 성공합니다. 등록 취소는 등록자만 할 수 있습니다. 재료만 거래 가능하며 한 캐릭터당 10건, 서버 전체 200건까지 등록합니다. 계정 등록 전에는 거래와 장비 변경을 제한합니다.

보급 화면에서 기존 데이터의 재료·방어구·악세서리를 구매하고 보유 장비를 착용할 수 있습니다. 장비의 체력·방어, XP에 따른 소폭 체력·공격 성장은 서버가 계산한 스탯으로 다음 출정에 반영됩니다. 레벨 공식은 `1 + floor(XP/1200)`, 레벨당 HP +150 / 공격 +15의 초기 조정값입니다. 방어구 방어의 피해 감소는 최대 25%입니다. 치명·출혈·특수 장비 효과·강화·제작 전체를 온라인 서버로 옮긴 것은 아닙니다. 기존 싱글 저장과 온라인 계정은 자동 합치지 않습니다.

## 파티와 전투

공개 파티는 인력사무소 모집 목록에 나타나고, 비공개 파티는 코드로만 참가합니다. 전원 준비 후 파티장이 출격합니다. 출정 때 서버가 확정한 장비 스탯을 사용하고, 장비를 바꾸면 준비 상태를 해제합니다. 던전과 보스 상태는 파티별로 분리되어 있습니다. 완료/전멸 후 파티장이 귀환하면 파티는 유지되고 준비를 다시 합니다.

게임 로직은 기존처럼 10ms 단위, 전투 상태는 최대 초당 20회 전달합니다. `party-wire.js`가 이전에 전송한 상태와 다른 값만 전달하고 클라이언트가 복원합니다. 수신자가 밀려 중간 전송을 생략했다면 다음에는 전체 상태를 보내 기준을 복구합니다. 채팅은 이 전투 전송과 별도 메시지로 처리합니다.

## 자동 검증

현재 `npm test`: **70개 통과 / 실패 0개**. 계정 업그레이드·재로그인·영구 저장, 이름 중복·정규화·변경 차단, 동시 계정 생성, 기존 JSON 이전, 길드·파티 채널과 기록의 외부 노출 차단, 4인 한도·비공개 모집·귀환, 장비 스탯, 거래 보존·중복 구매·실패 롤백, 전투 상태 차이 복원을 검증했습니다. 기존 싱글 전투·던전·리그 검사도 통과했습니다.

## 100개 실제 WebSocket 연결 부하 측정

재현 명령: `npm run test:load`. 별도 서버 프로세스와 부하 클라이언트 프로세스를 같은 개발 머신에서 실행하고, 임시 SQLite 파일을 사용합니다. 계측 원본: `docs/validation/party-load-100.json`.

| 측정 | 쉘터·인력사무소 + 월드 채팅 | 25개 4인 보스전 + 월드 채팅 |
|---|---:|---:|
| 접속 | 100 | 100 |
| 측정 시간 | 4.0초 | 10.0초 |
| 서버 메모리 RSS | 58.6 MiB | 89.1 MiB |
| 단일 코어 기준 CPU | 6.7% | 31.5% |
| 왕복 지연 p95, 로컬 | 11.8ms | 10.0ms |
| 서버 송신량 | 0.74 MiB/s | 2.27 MiB/s |
| 접속 끊김 / 프로토콜 오류 | 0 / 0 | 0 / 0 |
| 100ms 이상 지연으로 생략된 10ms 스텝 | 2 | 0 |

101번째 새 접속은 정원 초과로 거절했습니다. 보스전 부하를 바로 만들기 위해 테스트 전용 IPC로 시작 위치만 고정했으며, 이후 이동·공격은 실제 WebSocket 입력으로 전송합니다. 이 IPC는 운영 서버 프로토콜에 노출되지 않습니다. 비밀번호 해시 부하는 별도 기능 테스트에 포함되며, 위 부하 측정은 게스트 접속 키 세션입니다.

위 결과는 **100명의 사람, 모바일 기기, 인터넷 지연, 장시간 운영, Render 인스턴스 성능을 보장하지 않습니다.** CPU 모델은 AMD EPYC 9V74 80-Core Processor, 실행 환경에 제공된 논리 CPU는 8개입니다. 전투 기간의 최대 로컬 왕복 지연은 101.3ms였으므로 40ms 퍼펙트 판정 체감에는 별도 인터넷 지연 검수가 필요합니다. 짧은 평균치만으로 서비스 등급을 주장하지 않습니다.

## 배포 상태

소스와 테스트·실행 패키지를 준비했습니다. GitHub 업로드는 앞선 연결의 403 상태로 인해 완료되지 않았습니다. Render 플러그인의 서비스 도구는 이제 노출되어 있으며, 확인된 작업 공간은 `다민's workspace`입니다. Render 도구가 사용자의 명시적인 작업 공간 선택을 요구하므로 이 대상을 확인하기 전에는 서비스를 생성하지 않습니다.

`render.yaml`은 무료 플레이테스트용으로 계정·진행 DB가 재시작/재배포/유휴 종료 시 지워집니다. 화면에 초기화 가능성을 표시합니다. 상시 운영은 영구 디스크 또는 별도 DB, HTTPS 및 운영 부하 측정이 필요합니다. Render의 무료 요금제 지침에 따라 유료 자원을 임의로 생성하지 않았습니다. 로컬/Docker의 데이터 볼륨에서는 재시작 후 저장이 유지됩니다. 서버를 재시작하면 파티·진행 중 던전·채팅 기록은 종료되지만 영구 볼륨의 계정·보상·길드는 유지됩니다.

이번 변경의 화면 캡처·실제 모바일 터치 QA, Docker 이미지 실행, 공개 서비스 배포는 미완료입니다.

기술 근거: [Node SQLite](https://nodejs.org/api/sqlite.html), [Node scrypt](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback), [Render 무료 인스턴스](https://render.com/docs/free).
