# 시트대로 화면 맞추기 — 1차 (레이아웃 예산)

「시트대로 화면을 다시 맞춰라 — 구현이 시트에서 벗어난 부분을 찾아 고치기.」

`design-sheets/` 14장을 구현 화면과 같은 좌표계(1672×941, 터치 모드)에서
한 장씩 겹쳐 봤다. 가장 큰 어긋남은 «어떤 패널이 몇 px 다르다» 가 아니었다.

## 1. 네 화면이 시트보다 길어서 «화면 전체» 가 줄어 있었다

설계 시트는 **1672×952 한 장**이다. `.stage` 는 그걸 `min-height:952px` 로만
잡아 뒀는데, min 이라 패널이 늘어나면 스테이지가 같이 늘어난다. 그러면
`fitStage` 가 높이에 맞춰 **화면 전체를 축소**한다.

| 화면 | 스테이지 높이 | 실제 배율 |
|---|---|---|
| 인력사무실 | 1162px | **0.810** |
| 제작 | 1144px | 0.822 |
| 컨셉 보드 | 1093px | 0.861 |
| 의뢰 상세 | 1059px | 0.889 |
| 전투 결과 | 1027px | 0.916 |
| 나머지 9장 | 952px | 0.989 |

**인력사무실이 0.81배였다.** 시트가 설계한 글자보다 19% 작게, 좌우에 159px 씩
검은 띠를 두고 나오고 있었다. 폰에서 제일 오래 보는 화면이다.

고친 것은 한 줄이다.

```css
.stage{ height:952px }   /* min-height 였다 */
```

높이를 못박으면 넘치는 것은 시트가 의도한 대로 **패널 안에서 스크롤**된다.
`html.mobile` 은 이미 `height:100dvh` 로 덮어쓰므로 폰 세로 레이아웃은 그대로다.

그 다음 네 화면을 952 안으로 들여보냈다 — 아래 §2~§5.

> 잘림 검사를 바꾸기 전후로 돌려 **완전히 같은 결과**(3화면, 같은 항목)임을
> 확인하고 적용했다. 새로 잘리는 것은 없다.

## 2. 전투 결과 — 헤더가 184px 였다 (시트는 52px)

`.sheethead` 의 오른쪽 칸이 `300px` 고정인데 메타 칩 3개가 들어간다.
`white-space` 가 없어서 한글이 **한 글자씩 세로로** 쪼개졌다.

```
작 전 모 드        난 이 도
전 투 대 기 화 면   인 원 사 무 실 …
```

시트는 「작전 모드 · 전투 대기 화면」 한 줄짜리 가로 알약이다.
`white-space:nowrap` + `b{display:inline}` + 오른쪽 칸을 `auto` 로.
**184 → 52px.** 이것만으로 스테이지가 1027 → 952 가 됐다.

### 덤 — 같은 문장이 화면에 두 번 나오고 있었다

`art/char-result.webp` 가 시트에서 오려낸 것인데 **아래에 구워진 자막
「황혼은 끝이 아니다.」 까지 같이 잘려 들어가 있었다.** 구현은 그 문장을
UI 로 한 번 더 그린다. 바탕에 흐릿하게 반쪽 걸친 같은 문장이 겹쳐 보였다.
아트에서 자막을 잘라 냈다 (456 → 430px). 나머지 둘(`char-profile`,
`char-inventory`)은 깨끗했다.

## 3. 인력사무실 — 우측 레일의 던전 목록이 344px

시트에서 그 칸은 「전투 준비 / 훈련용 허수아비」 **한 줄**이다.
구현은 던전 01·02·03 카드 세 장으로 자라 있었다. 내용은 실제로 쓰는 것이라
지우지 않고, 시트의 칸 높이에 맞춰 `max-height:150px` + 스크롤로 묶었다.

## 4. 의뢰 상세 — 3분할 표가 반만 보였다

가운데 열의 시트 비율은 히어로 210 / 약점 172 / 3분할 207 / 하단 179 인데,
구현은 히어로 282·약점 195 로 부풀어 3분할이 **143px** 밖에 못 받았다. 그래서

- 공격 패턴 요약: 5개 중 **3개**
- 마스터리 등급: S·A·B·C 중 **S·A**

만 보였다. 보스를 읽는 화면에서 공격 패턴이 안 보이면 화면의 목적이 없다.
히어로 아트·약점 도해·행 여백을 시트 비율로 되돌려 3분할을 **214px** 로.
이제 세 칸 모두 `need == 165` 로 딱 맞는다 — 전부 보인다.

출격 CTA 도 고쳤다. 잠긴 상태의 라벨이 26px 세리프라 **「이전 의뢰를 먼저 완 /
료해 주세요」** 로 낱자가 갈렸다. `word-break:keep-all` + 잠금 상태 17px.

## 5. 제작 — 「재료 선택」 이 찌그러져 있었다

`.cf__c` 는 자식이 **넷**인데 행 정의가 **셋**이었다.

```css
grid-template-rows: auto 1fr auto;   /* 자식: 결과 · 재료 선택 · 필요 재료 · 제작바 */
```

`재료 선택` 은 평소 `display:none` 이라 셋으로 맞다가, 변형이 있는 레시피를
고르면 나타나면서 행이 한 칸씩 밀린다. 늘어나야 할 `필요 재료` 가 `auto` 를
먹고, **`재료 선택` 이 1fr 로 찌그러져** 주재료 한 줄만 반쯤 보였다.

칸 나눔을 플렉스로 바꿨다 — `display:none` 인 자식은 애초에 끼지 않으므로
밀릴 일이 없다. 이제 주재료·보조 재료·촉매 세 줄이 다 보이고 `필요 재료` 가
스크롤한다.

## 6. 「파티 모집」 시트에는 구현이 없다

`party.html` 은 온라인 허브(계정·방 코드)로 **바뀌었다.** 03 시트가 그린
파티 찾기 화면 — 4인 카드·특성 등급표·채팅·모집 시작 — 은 구현이 없다.
`compare.html` 이 둘을 나란히 놓고 「대조」라고 부르면 거짓말이므로 탭 이름을
**「파티 모집 (미구현)」** 으로 고쳤다. 만들지 말지는 디렉터 판단이다.

## 7. 재발 방지 — `tools/screen-fit.mjs`

```
node tools/serve.cjs &
node tools/screen-fit.mjs
```

18개 화면의 스테이지 높이를 재서 952 를 넘기면 **배율까지 찍어서** 실패한다.
`height:952px` 를 `min-height` 로 되돌려 **일부러 깨뜨려 보고** 세 화면을
정확히 집어내는 것을 확인했다.

```
!! office.html   스테이지 1030px — 시트보다 78px 길다 (화면이 0.914배로 줄어든다)
!! craft.html    스테이지 1144px — 시트보다 192px 길다 (화면이 0.823배로 줄어든다)
!! board.html    스테이지 1093px — 시트보다 141px 길다 (화면이 0.861배로 줄어든다)
```

## 남은 것 (2차)

시트와 다르지만 «내용이 자란» 것이라 디렉터 판단이 필요한 것들:

- 인력사무실 우측 레일에 던전 진행 목록이 통째로 추가돼 있다 (시트에는 없다).
- 프로필의 전투 숙련도가 시트 3링(카운터·파괴·생존) → 구현 5링(등급 시스템).
- 의뢰 카드마다 「잠김」 칩이 붙는다 (시트에는 없다 — 진행 상태 표시).
- 의뢰 정보의 「주요 적」 아이콘 4개가 전부 같은 그림이다 (시트는 4종).
