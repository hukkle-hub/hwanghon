# 61 · 「공격 모션이 촐싹댄다」 — 클립을 빨리 감고 있었다

## 재 보니

배속 = 클립 길이 ÷ 행동 시간. 아인 기준(speed 1.0):

```
평1     1.125초 / 0.66초 = 1.70배
평2     1.667초 / 0.66초 = 2.53배   ← 최악
평3     0.875초 / 0.66초 = 1.33배
스매시   2.417초 / 0.96초 = 2.52배   ← 최악
카운터   1.083초 / 0.56초 = 1.93배
---
스킬1   1.042초 / 1.32초 = 0.79배
스킬3   1.083초 / 1.42초 = 0.76배
```

**스킬만 전용 박자(`characterProfiles.ain`)를 갖고 있고, 평타는 공용 `light`
를 그대로 쓴다.** 그래서 스킬은 오히려 여유가 있고 평타만 촐싹댄다. 디렉터가
「공격 모션」을 콕 집은 게 맞다.

## 해 보고 되돌린 것 — 행동 시간을 늘리기

평타에도 전용 박자를 줘 봤다. 처음엔 +27%, 다음엔 +15%.
**둘 다 d03 수문기 2페이즈에서 기준 봇이 죽는다** (`tests/expedition-flow`,
보스 HP 97,677 남기고 hp=0). 행동 시간을 늘리면 그만큼 DPS 가 빠지는데 그
던전에 그 여유가 없다.

모션 문제를 난이도 변경으로 갚는 셈이라 되돌렸다. 균형까지 같이 손보는 건
디렉터 판단이다 — 피해량을 같은 비율로 올리면 DPS 는 보존되지만 그건 전투
설계 변경이다.

## 대신 쓴 것 — 꼬리 자르기 (`clipSpan`)

배속 = **쓰는 클립 길이** ÷ 행동 시간이므로, 클립의 뒤끝을 덜 쓰면 **행동
시간을 1 초도 건드리지 않고** 배속이 내려간다. 균형에 영향이 없다.
여운은 어차피 대기 자세로 섞여 나가며 가려지는 구간이다.

```
평1  .88  1.70 → 1.50
평2  .62  2.53 → 1.57
카운터 .85  1.93 → 1.64
평3   —   1.33 (그대로)
```

### 여기서 테스트가 버그를 잡았다

`sampleAction` 은 `clipHit` 을 «넘겨받은 길이» 의 비율로 읽는다. 그래서 그냥
자르면 판정 프레임의 자세가 같은 비율로 앞당겨진다 — 49 번 문서에서 궁극기로
겪었던 «맞는 그림과 맞는 시각이 어긋나는» 문제가 평타에서 재발한다.
`clipHit` 을 `span` 으로 나눠 함께 보정해야 한다. 안 그러면 촐싹은 고치고
접점을 깨뜨리는, 더 나쁜 교환이 된다.

처음 넣은 값 `smash: .70` 은 스매시 판정(.78)보다 앞이라 **판정이 잘려
나갔다.** `tests/attack-weight.test.mjs` 가 그 자리에서 잡았다.

## 스매시는 이 방법으로 못 고친다

판정이 클립의 **.78 지점**이다. 자를 꼬리가 22% 밖에 없고, `.88` 밑으로
내리면 판정이 잘린다. **2.52 배로 남는다.** 고치려면 행동 시간(=균형)을
늘리거나 클립을 다시 구워야 한다 — 둘 다 이 문서 범위 밖이다.

## 남은 것

- 스매시 2.52 배 — 위
- 평타 전체를 1.0 배 가까이 내리려면 균형을 같이 손봐야 한다 (디렉터 판단)
- 평2 클립이 1.667 초로 유독 길다. 평1(1.125)·평3(0.875)과 맞춰 다시 구우면
  자르기에 기대지 않아도 된다
