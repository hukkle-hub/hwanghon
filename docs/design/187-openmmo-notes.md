# 187 · OpenMMO (송재경) 읽기 노트 (2026-10-06)

디렉터가 보낸 영상: «바람의 나라, 리니지 개발자가 만든 오픈소스 게임 - openmmo» (ZeroCho TV).
문서 186 에서 «리니지 개발자가 공개한 소스는 없다» 고 적었는데, 디렉터가 말한 것은 이것이었다 —
**송재경(바람의 나라·리니지·아키에이지)이 혼자(+AI) 만든 브라우저 MMO** [Julian-adv/OpenMMO](https://github.com/Julian-adv/OpenMMO).

## 0. 라이선스 — 코드는 가져오지 않는다

- **PolyForm Noncommercial 1.0.0** — 개인 공부·취미·학교·자선만 허용, **상업적 쓰임 금지**.
- 황혼은 상용 출시(안드로이드 포함) 가능성이 있으므로 **코드·데이터·에셋을 한 줄도 옮기지 않는다.**
  구조와 결정(무엇을 왜 그렇게 했나)만 읽고, 우리 것은 우리가 다시 짠다. 아이디어는 저작권 대상이 아니다.
- 저장소는 컨테이너 임시 폴더에서만 읽었다(실행하지 않음).

## 1. 한눈에

| | OpenMMO | 황혼 (지금) |
|---|---|---|
| 서버 | Rust (Tokio, tungstenite, Axum), SQLite | Node.js (`server/`), 파일 저장 |
| 클라 | Svelte 5 + Three.js(WebGPU, TSL) | 정적 HTML + Three.js(WebGL) |
| 공용 코드 | `shared` 크레이트를 **서버·브라우저(WASM)·봇** 이 같이 씀 | 서버·클라가 따로 (필드 띠 자르기 두 벌) |
| 세계 | 32 km 절차 생성, 64 m 타일, 경계 없는 한 장(X 축으로 감김) | 실측 OSM 지역 + 던전 층, 문으로 연결 |
| 카메라 | 쿼터뷰 정사영 (≈50 × 35 m) | 고정 55° 정사영 (휴대폰 화면 ≈10 m) |
| 이동 | **서버가 길을 찾고 클라는 승인된 길만 재생** (예측 없음) | 클라 이동 + 서버 속도·띠 검사 |
| 몹 AI | 서버 전용 행동 트리, 200 ms, 틱 예산 40 ms | (다음 단계) |
| 봇 | **사람과 똑같은 프로토콜**로 붙는 LLM 에이전트 NPC | 없음 |

## 2. 맵에서 받아들이는 것 (지금 단계)

1. **타일은 정적 파일, 웹소켓은 «목록과 해시» 만** — 지형 파일은 nginx 가 직접 주고, 서버는 `{path, hash}` 만 보낸다.
   클라는 SHA-256 을 확인하고 서비스워커 캐시(최대 128 MB)에 넣는다.
   → 황혼도 `map.json` 에 타일 해시를 넣고 서비스워커로 캐시하면, 지역을 오갈 때 다시 받지 않는다(다음 할 일).
2. **에셋은 저장소 밖에, 잠금 파일로 고정** — 큰 바이너리는 Hugging Face 데이터셋에 두고 `assets.lock` 으로 버전을 박는다.
   → 황혼 맵이 GitHub Pages 1 GB 에 닿는 문제(185 §6.5)의 답이 이것이다. 지역이 더 늘면 타일을 별도 저장소/CDN 으로 옮기고 `maps.lock` 으로 고정.
3. **주변 2 × 2 타일만** — 3 × 3 에서 줄였다(셰이더 컴파일 부담). 우리는 화면 + 한 장 둘레(≈3 × 3).
   휴대폰에서 끊기면 같은 방향으로 줄인다.
4. **던전은 결정적(같은 씨앗 = 같은 배치), 층은 서버만 안다** — 층 이동은 «계단 문» 을 실제로 지나간 경우만 받는다.
   → 우리 던전 층 = 별도 지역 + 문(서버 `fieldJoin.gate`). 서버가 문 반경 안에서 온 요청만 받도록 조이는 것이 다음 할 일.
5. **마을은 «몹이 안 나는 사각형»** — 우리 `areas[]` 안전 구역과 같은 생각(문서 186 §5).

## 3. 보스·몹에서 받아들이는 것 (다음 단계 — 보스)

- **장소가 곧 난이도** — 몹 레벨이 아니라 «마을에서 거리 / 던전 깊이» 로 명중 보너스가 오른다. 보상도 멀수록 크다 → 사람이 자연히 퍼진다.
  황혼은 원작 길(강남 → 고흥)이 곧 거리라서 그대로 맞는다.
- **이동하면 화면 밖 진행 방향에 몹이 난다** (걸은 거리 d 마다 `1 − 0.98^d`), 반경 32 m 안 최대 8마리, 아무도 없으면 지운다.
  → 몇 마리로도 «사는 세계» 처럼 느껴진다. 휴대폰 성능에도 맞는다.
- **몹 AI 는 처음부터 서버** — 클라 «주인» 이 AI 를 돌리던 방식을 버렸다(서버가 의도를 검증할 수 없어서).
- 던전 마지막 층 최종 보스, 5/10/15/20 층 잠긴 문 + 앞 층에서 떨어지는 열쇠, 최종 상자는 캐릭터당 하룻밤 한 번.
- 전투: 폭발하는 d20(20 이면 한 번 더 굴려 더함) + 공격 보너스 vs 방어. 황혼은 원작 전투 문법(문서 150)이 있으므로 공식은 가져오지 않고 «서버가 굴린다» 만.

## 4. 온라인에서 받아들이는 것 (디렉터: «온라인은 전부 구현해놓고 생각» — 나중)

- **목표 지점 이동** — 클라는 «여기로» 만 보내고 서버가 A* 로 길을 돌려준다. 휴대폰 «탭 이동» 에 딱 맞고 동기화 버그 한 부류가 사라진다.
- **관심 반경 하나**(32 m) + 연결마다 «보낸 것» 을 기억해 들어옴=전체·머묾=차이·나감=삭제. 메시지를 전달 범위로 분류.
- **프로토콜 버전 악수** — 첫 메시지에 버전, 다르면 바로 끊는다(하위 호환 안 함). 서버·클라·봇을 같이 올린다.
- 32초마다 바뀐 캐릭터만 묶어 저장, SIGTERM 에 다 저장하고 끝, IP 당 토큰 버킷, 전투 감사 로그.

## 5. 개발 방식

- `AGENTS.md`(= CLAUDE.md = GEMINI.md): 왜를 쓰는 짧은 주석, «5,000 동시 접속» 을 늘 전제, 에셋마다 출처·라이선스 기록.
- 설계 문서 = 결정 기록(비교한 대안, 사고, 잰 숫자, «다시 볼 때» 조건). 황혼 `docs/design/` 과 같은 습관이다.
- 서버 테스트 ≈1,000 + 클라 ≈1,300, 결정적 던전의 골든 해시, 기본으로 꺼 둔 5,000명 부하 시험.
