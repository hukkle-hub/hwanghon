# 황혼 웹/안드로이드 빌드 — 엔진·플러그인 조사 v0.1

> 작성일 2026-09-15 · 목적: 지금의 자체 캔버스 엔진(`dungeon.html`)을 상용 RPG 수준으로 끌어올리기 위한 기반 선택
> 전제: GitHub Pages 정적 호스팅, 안드로이드 PWA(가로), 원화는 2D 설정화(캐릭터 4명 3면도 + 허수아비 3면도), 본편은 PC 언리얼 프로젝트

---

## 0. 왜 지금 것이 조잡해 보이는가

| 항목 | 지금 | 상용 RPG |
|---|---|---|
| 렌더링 | 캔버스 2D 에 직접 그림, 조명·그림자 없음 | WebGL 스프라이트 배칭, 동적 조명, 노멀맵, 블룸/글로우, 파티클 |
| 타일맵 | ASCII 격자를 코드로 그림 | 타일셋 + 레벨 에디터(Tiled), 오토타일, 여러 레이어(바닥/장식/충돌/상단) |
| 캐릭터 | 3면 정지 이미지 + CSS 흔들림 | 스켈레탈 애니메이션(Spine/DragonBones)로 걷기·공격·피격·사망 클립 |
| 보스 | 자체 SVG 컷아웃 리그 (메시 변형·IK 없음) | 메시 스키닝, IK, 블렌딩, 이벤트 트리거 |
| 연출 | 화면 흔들림·플래시 | 히트 파티클, 잔상, 슬로우모션, 카메라 줌, 사운드 |
| 카메라/물리 | 자체 구현 | 엔진 내장 (충돌·트윈·타임라인) |

핵심은 **렌더러·에디터·애니메이션 런타임** 세 가지를 검증된 것으로 바꾸는 것이다. 전투 규칙(`combat.js`)과 월드 규칙(`world-sim.js`)은 DOM 없는 순수 로직이라 그대로 가져갈 수 있다.

### 1-B. 3D 웹 엔진 (아인/허수아비를 3D 로 갈 경우)

| 엔진 | 장점 | 단점 |
|---|---|---|
| **PlayCanvas** | 런타임 1~2MB, 모바일 프레임 최우수, WebGPU 가장 성숙, 클라우드 에디터 | 에디터가 클라우드 종속(무료 플랜은 공개 프로젝트) |
| Babylon.js | PBR·기능 폭 최대, 코드 중심 | 런타임 큼 |
| Three.js | 가장 널리 쓰임, 자유도 | 엔진이 아님(직접 조립) |

3D 로 가려면 모델이 필요하다. 이 세션에 연결된 Higgsfield 도구에 `generate_3d`(이미지 → GLB, 멀티뷰 → GLB, 자동 리깅 + 애니메이션 클립)가 있어 **허수아비 3면도 → GLB 리깅 모델**을 뽑을 수 있다. 다만 결과 품질과 크레딧 소모(현재 잔여 9.8 크레딧, 3D 는 이미지보다 비쌈)를 확인해야 한다.

## 2. 추천안 — **Phaser 4 + Tiled + (DragonBones → Spine) + 파티클/조명**

이유:
1. 지금 코드베이스가 JS 정적 사이트다. Phaser 는 스크립트 한 파일(약 1.5MB)로 GitHub Pages 에 그대로 올라가고 PWA·서비스워커·자동 업데이트를 그대로 쓴다.
2. `combat.js`(전투 규칙)·`world-sim.js`(존·거리·AI)·`dungeons.js`(데이터)를 **그대로 재사용**한다. 바꾸는 것은 렌더링·입력·씬 뿐이다.
3. 다크 판타지 질감에 필요한 것(횃불 동적 조명, 노멀맵, 블룸, 비네트, 히트 파티클, 잔상)을 Phaser 4 가 내장한다.
4. 허수아비 리그를 Spine/DragonBones 로 다시 만들면 메시 변형·IK 로 "살아 있는" 모션이 되고, 아인도 같은 파이프라인으로 걷기·공격·구르기·피격 클립을 만든다.
5. Godot 는 에디터가 좋지만 이 원격 환경에서 매 수정마다 실기기 검증이 어렵고, 웹 빌드가 무겁다. 3D 는 모델이 아직 없다.

### 마이그레이션 계획 (던전 01 기준)

| 단계 | 내용 | 산출물 |
|---|---|---|
| M1 부트 | Phaser 4 를 `vendor/` 에 두고 `game.html` 씬 골격(Boot → Office → Dungeon → Result). 기존 HUD 는 DOM 오버레이로 유지 | 씬 전환, 해상도·가로 고정, PWA 연동 |
| M2 타일맵 | 뒷마당을 Tiled 로 제작(바닥/장식/충돌/상단 4 레이어). 타일셋은 설정화 톤으로 생성(흙·돌담·울타리·짚·횃불) | `maps/d01.json`, `tiles/yard.png` |
| M3 조명·연출 | 횃불 포인트 라이트, 노멀맵, 비네트·블룸, 히트 파티클, 잔상, 카메라 줌·흔들림 | 다크 판타지 룩 |
| M4 캐릭터 | 아인 3면도 → DragonBones/Spine 리그(걷기·공격 3연·구르기·방어·피격·사망), 허수아비 리그 재작업(메시·IK, 3페이즈 클립) | `anim/ain.json`, `anim/dummy.json` |
| M5 전투 접합 | `combat.js`/`world-sim.js` 를 Phaser 씬에 연결, 존은 그래픽 오브젝트, 입력은 Phaser 포인터·가상 스틱 플러그인 | 던전 01 완주 |
| M6 사운드 | Phaser 오디오(공격·카운터·파괴·격추·환경음) | — |

아트 파이프라인: 타일셋·소품은 `generate_image` 로 설정화 톤에 맞춰 생성 후 슬라이스(크레딧 1/장). 리그는 자체 SVG 리그에서 DragonBones JSON 으로 옮기는 변환 스크립트를 만들면 손작업을 줄일 수 있다.

## 3. 대안 경로

- **3D 로 전환**: `generate_3d` 로 허수아비·아인 GLB 를 뽑아 PlayCanvas/Babylon 에 올린다. 언리얼 본편과 시각적 연속성은 가장 좋다. 단 모델 품질·크레딧·모바일 성능을 먼저 시험해야 한다.
- **Godot 4 로 전환**: 디렉터가 로컬 에디터로 직접 만지길 원한다면. 웹 빌드는 단일 스레드 + 서비스워커 우회로 Pages 에 올릴 수 있다.

## 4. 결정 필요

1. 엔진: **Phaser 4**(추천) / Godot 4 / 3D(PlayCanvas·Babylon)

3. 아트 생성 크레딧 사용 허용 범위(타일셋·소품 약 6~10장)
