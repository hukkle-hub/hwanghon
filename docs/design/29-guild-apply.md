# 길드 가입 신청·승인

「길드 가입 신청·승인도 서버 고쳐서 넣어.」

## 1. 왜 필요했나

길드에 들어갈 길이 **초대 코드 하나**였다. 코드는 «이미 아는 사람» 에게서 받는 것이라,
처음 들어온 사람은 길드가 있는지조차 알 수 없었다. 문서 15 의 쉘터는
「길드 소속·접속 상태·초대 코드·길드 채팅」까지만 정해 두었고 모집은 없었다.

## 2. 서버 (`server/` 변경 — **Render 재배포 필요**)

### 저장 (`rpg-store.cjs`)

표 두 개를 더했다. 기존 표는 건드리지 않았으므로 **이미 돌고 있는 DB 도 그대로 뜬다**
(`ALTER TABLE` 없음).

```sql
CREATE TABLE guild_open(guild TEXT PRIMARY KEY …);                 -- 있으면 «모집 중»
CREATE TABLE guild_applications(guild, player, message, created,
                                PRIMARY KEY(guild,player));
```

**모집은 기본이 «닫힘»** 이다. 켜는 쪽이 선택한다 — 만들자마자 모르는 사람이
들어오는 게 기본값이면 안 된다.

| 메서드 | 하는 일 | 규칙 |
|---|---|---|
| `guildOpen(id,on)` | 모집 열기·닫기 | 길드장·임원. 닫으면 **대기 중인 신청도 정리** |
| `guildBoard()` | 모집 중인 길드 목록 | 이름·인원·공지만. **초대 코드는 싣지 않는다** |
| `guildApply(id,gid,msg)` | 신청 | 이미 길드 있으면 거절, 모집 안 하면 거절, 100명·신청 50건 한도, 한마디 120자 |
| `guildCancelApply(id)` | 신청 취소 | 본인 |
| `guildDecide(id,target,ok)` | 승인·거절 | 길드장·임원. 승인 시 정원·중복 가입 재확인 |
| `guildApplications(id)` | 받은 신청 | **길드장·임원만** |

한 사람은 **한 곳만** 신청한다. 여러 곳에 뿌려 두고 잊는 것을 막고, 승인될 때
다른 신청도 함께 정리한다.

`guildDetails` 에 `open` 과 `applications` 를 실었다. 신청자 이름은
**관리자에게만** 내려간다 — 평 길드원의 화면에는 빈 배열이 간다.

### 명령 (`rpg-server.cjs`)

```
{type:'rpg', action:'guildBoard'}                       → {type:'guildBoard', guilds, mine}
{type:'rpg', action:'guildApply', guild, message}
{type:'rpg', action:'guildCancelApply'}
{type:'rpg', action:'guildDecide', target, accept}
{type:'rpg', action:'guildManage', operation:'open', value}
```

승인·거절은 **당사자에게 알린다** (「가입이 승인되었습니다」 / 「거절되었습니다」),
길드원 전원의 명단도 즉시 갱신한다.

> 서버 계층에서 SQL 을 직접 치지 않았다 — `guildMemberIds(gid)` 를 저장소에 두고
> 거기서만 쿼리한다.

## 3. 화면

가운데 칸이 상태에 따라 **두 얼굴**이다.

| 내 상태 | 가운데 칸 제목 | 내용 |
|---|---|---|
| 길드 없음 | **길드 찾기** | 모집 중인 길드 목록 (이름·공지·인원·[신청]) + 한마디 칸 + 새로고침 |
| 신청 중 | 길드 찾기 | 「○○ 에 신청했습니다. 승인을 기다리는 동안 다른 곳에 신청할 수 없습니다」 |
| 소속 | **길드 명단** | 관리자면 위에 «가입 신청 N건» + [승인][거절], 아래에 길드원 |

왼쪽 «내 길드» 에는 관리자에게만 **공개 모집 열기/닫기** 가 뜬다. 닫을 때는
대기 신청이 정리된다고 확인을 받는다. 신청 중인 사람에게는 「가입 신청 중 ○○」
와 **신청 취소** 가 뜬다.

## 4. 검수

### 서버 — `tests/guild-apply.test.cjs` 3개

1. 모집을 열어야 목록에 뜨고 신청되며, 승인하면 길드원이 된다 (+ 초대 코드가
   목록에 실리지 않는 것까지)
2. 거절하면 가입되지 않고, 모집을 닫으면 대기 신청이 정리된다
3. 권한 없는 사람은 모집을 열거나 신청을 처리할 수 없고, **평 길드원에게
   신청자 이름이 내려가지 않는다**

**일부러 깨뜨려** 확인했다 — 모집 검사 제거 → 2번 실패, 거절이 가입시킴 → 2번 실패,
신청 목록 노출 → 1·3번 실패.

### 화면 — 두 사람을 동시에 띄워서

```

닫힌 동안 목록 : 공개 모집 중인 길드가 없습니다…
모집 후 버튼   : 공개 모집 닫기 | 머리: 접속 1 / 1명 · 모집 중
지원자 모집 목록: 모집 중인 길드 · 황혼의 인력사무소 · 1 / 100 · [신청]
신청 후(지원자): 신청 중 / 황혼의 인력사무소 | 「…승인을 기다립니다」
길드장 받은함  : 가입 신청 1건 · 지원자류 · 「카운터 자신 있습니다…」 [승인][거절]
승인 후(지원자): 황혼의 인력사무소 | 「가입이 승인되었습니다」
승인 후 명단   : 접속 2 / 2명 · 모집 중
```

콘솔 오류 0. `npm test` **146/146**, 전 19화면 952px.

### 밟은 것 하나

지원자 화면의 모집 목록이 계속 비어 있었다. `welcome` 직후 `state` 와
`guildBoard` 를 **연달아** 보냈는데, rpg 명령은 **120ms 간격 제한**이 있어서
두 번째가 「잠시 후 다시 시도하세요」로 버려지고 있었다. 260ms 뒤로 미루고,
목록에 **새로고침** 버튼도 뒀다.

## 5. 온라인 반영

`server/` 를 고쳤으므로 **Render 재배포가 필요하다** (GPT 몫).
재배포 전까지 온라인 서버에서는 모집·신청 명령이 「지원하지 않는 요청입니다」로
떨어진다. 기존 기능(초대 코드 가입·채팅·귓속말·길드 관리)은 영향 없다.

## 6. 아직 없는 것

- **파티 모집 화면** (설계 시트 03).
- 신청에 대한 **조건 걸기**(최소 전투력·요원 등급 등) — 지금은 한마디만 받는다.
- 길드 **가입 이력·감사 화면** — `audit` 표에는 쌓이지만 보는 화면이 없다.
