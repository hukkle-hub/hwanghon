## 2. 전략 — 준비, 정책, 전력, 보급

### 준비 단계
침공 전 **준비 시간 = 20초 + 정찰병 10초 + 정찰 강화 정책 20초** (`PrepSeconds`).
정찰이 살아 있으면(또는 정책이 있으면) 다음 웨이브 구성이 미리 보인다 (`WavePreview`).
준비 중에 할 수 있는 일:

- **바리케이드 짓기**: 자리에서 G, 보급 3 소모. 길드 권한 `InvestFacility` 또는 `AllocateSupply` 가 필요하다.
- **기술자 명령**: 정문 → 발전기 → 통신 → 복귀 순서로 바꾼다 (`OrderNpc`).
- 침공이 시작되면 바리케이드는 더 못 짓는다.

### 정책 (관리 길드가 고른다 — 예산 10, 전부는 못 고른다)

| 정책 | 비용 | 효과 |
|---|---|---|
| 정문 강화 | 4 | 정문 체력 ×1.5 |
| 발전기 강화 | 4 | 발전기·포탑 체력 ×1.5 |
| NPC 무장 | 3 | 경비병이 정문에서 사격(150/s) |
| 정찰 강화 | 3 | 준비 +20초, 웨이브 예보 |
| 의료 비축 | 3 | 의무실 회복 ×1.6, 회복약 +3 |
| 예비 전력 | 4 | 발전기가 무너져도 90초 비상 전력 |

### 전력
포탑은 발전기 전력으로 돈다 (`EffectivePower`). 발전기가 무너지면 포탑이 멈춘다. 단, 예비 전력
정책이 있으면 90초를 버틴다. 그래서 «파괴자가 숲길로 발전동을 노린다» 가 실제 위협이 된다.

### 적의 판단
역할마다 길과 목표가 다르다 (`ChooseTarget`, `role_routes`).

- 일반·엘리트: 정면 대로. 플레이어가 600 안에 없으면 380 안의 포탑을 친다.
- 질주형: 서·동 우회로. 길 위의 바리케이드를 먼저 부순다.
- 파괴자: 동측 숲길로 가서 발전기를 노린다.
- 추적자: 서측 순환로로 돌아 NPC 를 노린다.

정문이 서 있으면 정문 줄을 넘지 못한다 (`BlockedByGate`, 플레이어 목표 포함).
목표가 바뀌면 길 그래프의 최단 경로로 간다(§8). 정문·플레이어로 곧장 가는 건 15 m 안에서만이다.

## 3. NPC — 상점이 아니라 거점의 일부

| 역할 | 하는 일 | 잃으면 |
|---|---|---|
| 기술자 | 명령받은 시설로 걸어가 400/s 수리 | 수리 없음 |
| 의무병 | 의무실(3 m)에서 초당 최대 체력 8% 회복 | 회복 없음 |
| 정찰병 | 준비 +10초, 웨이브 예보 | 예보 없음 |
| 통신병 | 구조 신호 | 구조 신호 꺼짐 |
| 경비병 | (NPC 무장 정책 시) 정문 사격 | 사격 없음 |

**대피 명령 (준비 단계, 대피 자리에서 G, `OrderNpc` 권한):** 경비와 기술자를 뺀 NPC 가 길 그래프로
중앙 포탑 둘의 사거리 안(대피 자리)으로 모인다. 한 번 더 누르면 제자리로 돌아간다. 대가는 의무실·정찰탑·통신센터를
떠난 의무병·정찰병·통신병이 **기능을 잃는다**는 것이다(회복·예보·구조 신호 꺼짐). 기술자(수리·명령)와 경비는 자리를 지킨다.
시뮬레이터에서 포로가 4 → 2 가 된다(바리케이드까지 하면 1).

**상태는 정상 → 부상 → 실종 순서로 떨어진다.** 기능은 정상 1, 부상 0.5, 구조 직후 0.6, 실종 0 이다.

- 실종된 NPC 는 포로 자리로 끌려간다.
- 플레이어가 그 자리에서 G 를 누르면 구조된다. 구조된 NPC 는 집으로 돌아가 60초 회복한다.
- 추적자가 NPC 를 노리는 이유가 이것이다. 지키지 못하면 거점의 기능이 하나씩 꺼진다.

## 4. 길드 — 직책은 실제 권한이다

| 직책 | 권한 |
|---|---|
| 길드장 | 전부 + 대장 임명 |
| 부길드장 (기존 «임원») | 대장 임명 빼고 전부 — 정책 선택 포함 |
| 전투대장 | 핑·집결·NPC 명령 |
| 보급대장 | 보급 배정 |
| 제작대장 | 시설 투자(바리케이드)·NPC 명령 |
| 길드원 | 없음 (싸우는 건 누구나) |

- **핑**(전투대장 이상): 15초 안에 800 cm 안에서 나온 처치가 핑을 찍은 사람의 «지휘» 공헌이 된다.
- **공헌 장부** (한 판):
  - 처치: 역할 가중 (질주 1.2 · 파괴자 2 · 추적자 1.5 · 엘리트 5).
  - 방어: 시설·NPC 1500 cm 안에서 나온 처치.
  - 수리: 수리량 ÷ 100.
  - 구조, 보급, 지휘, 보스 딜.
  - 포탑·경비병 처치는 플레이어 공헌이 아니다 (`bLastHitByPlayer`).
- **점수**: 항목마다 «그 항목 1등 대비 몇 %» × 가중치(방어·구조 1.2, 보급·지휘 0.8, 나머지 1)로 매긴다.
  그 합에 **지휘 상한**(지휘 점수는 비전투 점수의 10% 까지)과 **다양성 보너스**(4종 이상에 기여하면 ×1.1)를 건다 — GPT 패키지 GuildWorld v0.3 에서 이것만 가져왔다(문서 202 §6). 사람 단위·길드 단위 셈 둘 다, UE `CapAndBonus` 와 벡터로 같다.
  보스 딜만 많은 길드가 관리권을 가져가지 못하게 하려는 것이다.

## 5. 길드전 — 처치가 아니라 목표

8대8 또는 12대12, 15분 안에 1000점을 먼저 따는 쪽이 이긴다 (`FWarMatch`).

- 점수: 발전기·통신 지점을 쥐고 있으면 초당 1점, 코어 운반 +150, 지휘관 호위 +200, 시설 파괴 +100.
- **처치는 점수가 아니다** (통계로만 센다).
- 규칙과 시험까지만 있다. 맵·매칭은 아직 없다.

## 6. 서버 거점 상태 · 쉘터 화면

`server/node-store.cjs` 를 `store.cjs` 에 붙였다. `{type:'node', action}` 이 info / report / policy / supply / role
다섯 가지를 처리한다. 서버는 200ms 간격으로만 받는다.

- **함락은 실제 시간으로 흐른다.** 함락 후 2시간은 탈환할 수 없다. 이후 시간이 지날수록 단계가 오른다:
  기본(2h) → 엘리트 증가(6h) → 요새화(12h) → 감염 핵심지(24h). 난이도와 보상도 같이 오른다.
- **관리권은 지난 주기(1주)의 공헌으로 정한다.** 돈 입찰은 없다. 동점이면 먼저 만든 길드다.
  관리 길드가 바뀌면 정책은 비워진다.
- **관리권은 소유권이 아니다.** 누구나 거점을 보고, 누구나 쓴다. 관리 길드는 정책·보급만 정한다.
- **권한 검사:**
  - 정책: 관리 길드의 길드장·부길드장만, 예산 안에서.
  - 대장 임명: 길드장만.
  - 보급: 보급대장, 주기당 12까지. 배정한 만큼 «보급» 공헌이 쌓인다.
- **판 결과 보고:** held / fallen / retaken / retake_failed. 한 사람이 1분에 한 번만 보낼 수 있고,
  항목별 최대치에서 잘린다. UE 는 판이 끝나면 `Saved/HWNode/last_report.json` 을 이 형식으로 쓰고,
  접속 중(`-HWServer=`)이면 `UHWRaidNetworkSubsystem::SendNodeReport` 로 보낸다. 서버 답(상태·관리 길드)은
  화면 알림으로 뜬다. UE 쪽 형식 문자열이 바뀌면 `tests/node-store.test.cjs` 가 깬다.
- **이번 주기 순위:** `nodeView.standings` 는 관리권과 같은 셈으로 낸 이번 주기 길드 순위(상위 5)다.
  이번 주기 1위가 다음 주기 관리 길드가 된다. 쉘터 카드는 3위까지와 결정까지 남은 날을 보여 준다.

**쉘터 «거점 관리» 카드** (`shelter.html` · `js/shelter.js`):

- 명단 옆(372px)에 놓인다. 휴대폰에서는 명단 아래에 쌓인다.
- 표시: 상태, 점령 단계, 관리 길드, 정책, 보급, 정보 서비스, 내 직책.
- 길드장·부길드장에게만 정책 칸이 보인다. 예산을 넘기면 «넘었습니다» 가 뜨고 확정 버튼이 잠긴다.
- 보급대장에게만 «보급 +3» 이 보인다. 12/12 가 되면 버튼이 잠긴다.
- 길드장은 명단에서 대장(전투·보급·제작)을 고른다.
- 다른 길드에는 «관리 길드 아님 (보기만)» 이 뜬다. 화면을 우회해도 서버가 거절한다.

## 8. 방어전 시뮬레이터 — 언리얼 없이 «한 판» 을 잰다

UE 를 여기서 못 돌리니, 같은 맵 JSON 과 같은 규칙으로 4분 판을 헤드리스로 돌리는 도구를 만들었다.

- `tools/ue/node-sim.cjs`: 판. 적 판단(0.4초 Think, 예비 동작 → 타격 → 회복), 포탑, 웨이브, NPC 를
  `AHWNodeEnemy` / `AHWNodeDirector` 에서 줄 단위로 옮겼다. 벽·시설 충돌은 그레이박스 상자 그대로 쓴다.
- `tools/ue/node-combat-rules.cjs`: 전투 규칙 JS 판. C++ 와 **같은 벡터**로 대조한다(경계값 포함).
  양쪽을 각각 일부러 틀리게 해서 실패하는 것을 확인했다.
- `tools/ue/node-sim.html`: 위에서 본 리플레이(`node tools/ue/node-sim-shots.mjs 이름 '{옵션}' 60,120`).
- 다른 점: 적끼리 밀치지 않고 가속이 없다. 플레이어는 단순한 자동 조종이다(시설·NPC 를 치는 적 > 철갑 >
  가까운 적, 길 그래프로 찾아감, 반격 35%). 플레이어 DPS 는 UE 코드에 없어서(애셋에 있다) 인자로 받는다.

### 시뮬레이터가 찾은 UE 버그 (전부 고침, 시험으로 박음)

| # | 증상 (시뮬에서 재현) | 원인 | 고침 |
|---|---|---|---|
| 1 | 적이 정문 2 m 앞에 서서 영원히 안 친다 | 웨이포인트용 «220 cm 도착» 을 정문(사거리 140)·플레이어(170)에도 썼다 | 도착은 웨이포인트에만 |

### 탈환전 판 · 판 안 보급 (UE · 시뮬)

**탈환전 판.** `?HWRetake=시간` 을 붙이면 그 시간만큼 점령당한 거점에서 시작한다.
- 준비 단계(바리케이드·대피·기술자 명령)는 방어전과 같다. 그다음 `StartRetake` → 탈환 중(Retaking).
- 점령 단계가 판을 바꾼다 (`HWNodeRules::OccupationDifficulty` · `OccupationExtraElites`, 서버 `DIFFICULTY` · `EXTRA_ELITES` 와 벡터로 대조):

  | 점령 | 단계 | 적 체력·피해 | 마지막 웨이브 철갑 |
  |---|---|---|---|
  | 2~6h | 기본 | ×1 | +0 |
  | 6~12h | 엘리트 증가 | ×1.3 | +1 |
  | 12~24h | 요새화 | ×1.65 | +2 |
  | 24h~ | 감염 핵심지 | ×2.1 | +3 |
- 실패는 방어전의 함락과 같은 조건이다: 통신센터 파괴 또는 20초 점거 → `TickRetake` 가 Retakeable 로 돌려놓고 점령 시계는 계속 간다.
  보스를 잡으면 `RetakeEnded(true)` → 복구. 서버 보고는 `retaken` / `retake_failed`.
- 판 기록(hwnode-run/1)의 `opt` 에 `retake` · `difficulty` · `extraElites` 가 들어가고, 대조 도구가 그대로 시뮬에 넘긴다.
  결과 낱말은 시뮬과 같은 `held` / `fallen` 이다(탈환에서도) — 대조가 두 판을 같은 말로 읽게.

| 바리케이드 (준비) | 3 | 보급·제작대장, 임원 | 보급 +3 |

### PIE ↔ 시뮬 대조하는 법

수치는 정하지 않고 **PIE 와 시뮬을 맞대 가며** 맞춘다.

1. PIE 로 한 판을 한다 (`?HWNode=namsan_n01…`). 웨이브 4개를 막거나 함락되면 UE 가
   `Saved/HWNode/last_run.json`(과 `Saved/HWNode/runs/run_날짜.json`)을 쓴다.
   형식은 시뮬과 같은 `hwnode-run/1` 이다: 사건(웨이브·시설 붕괴·NPC 부상/포로/구조·플레이어 사망), 1초마다 적·시설·NPC·플레이어 위치,
   피해를 누가 냈나(플레이어·포탑·경비), 그 판의 조건(정책·지은 바리케이드·기술자 명령·대피).
2. 그 파일을 넘겨주면:
   ```
   node tools/ue/node-compare.mjs last_run.json --shots 60,120,200
   ```
   같은 조건으로 시뮬을 돌린다. 플레이어 실력은 기록에 없어서, 플레이어 피해 몫이 PIE 와 가장 가까운 DPS(300~2600, 100 간격)로 맞춘다.
   핵심 순간 표를 찍는데, ⚠ 는 한쪽에만 있거나 15초·20% 넘게 차이 나는 곳이다.
   같은 시각 좌우 리플레이(왼쪽 PIE, 오른쪽 시뮬)도 찍는다.
3. ⚠ 마다 둘 중 하나다. PIE 가 이상하면 UE 를 고치고, 시뮬이 단순하면 시뮬을 고친다. 그다음 다시 돌린다.
   수치(적 수·체력·사거리)는 «둘이 맞은 다음» 에야 만진다.

UE 의 기록 형식은 `tests/ue-node-compare.test.cjs` 가 지킨다. 소스의 형식 문자열을 그대로 읽어 기록을 만들고, JSON 으로 읽히는지와
대조 도구가 받는지를 본다. 같은 판은 어긋남 0, 정문 60초 차이는 짚는다.

### PIE 에서 시뮬과 견줄 것 (첫 Windows 실행)

시뮬레이터는 UE 판단을 줄 단위로 옮긴 것이라 PIE 가 크게 다르면 어느 한쪽이 틀린 것이다.
아래 중 하나라도 어긋나면 그 장면을 찍어 주면 된다(시뮬 리플레이와 나란히 놓고 본다).

| 볼 것 | 시뮬 예상 (아무 준비 없이, 혼자) | 어긋나면 의심할 곳 |
|---|---|---|
| 정문 앞 적이 정문을 친다 | 2 m 앞에 서서 멀뚱히 있지 않는다 | `HasWaypoint` · 도착 반경 |
| 정문이 무너지는 때 | 웨이브 2 (약 108초), 정문 강화면 웨이브 3 | 적 수·`FacilityDamage` |
| 질주형이 우회로 → 기지 안 NPC | 첫 포로 약 100초 | `BlockedByGate` 의 flanked |
| 발전기가 부서진 뒤 적이 통신센터로 간다 | 발전동 앞에 서 있지 않는다 | `PathBetween` · JSON `links` |
| 포탑이 정문 앞·중앙 대로를 쏜다 | 분홍 사격선이 정문 앞에 보인다 | 포탑 자리(±11 m · ±12 m) |
| 대피 자리(파란 바닥)에서 G | NPC 셋이 걸어와 중앙 포탑 사이에 선다 | `EvacuateTo` |
| 판 끝 알림 | 접속 중이면 «Node server: stable …» | `SendNodeReport` |
