# 58 · 카메라 회전 — 「부자연스럽다」를 숫자로 잡았다

디렉터: **「이게 카메라 회전도 부자연스럽고」** → 한 번 손보고도 **「아직 좀 어색한데」**

감으로 또 만지는 대신 **응답을 쟀다.** 달리다 90° 꺾고, 목표 요우를 카메라가 어떻게
따라오는지 본다 (`scratchpad/camstep.mjs`).

## 1. 정체 — 회전 제한이 너무 낮았다

| | 이전 | 지금 |
|---|---|---|
| 63% 따라잡기 | **2.31 초** | **1.23 초** |
| ±5° 안에 정착 | 5.76 초 | **4.80 초** |
| 넘침(오버슛) | 0° | 0° |
| 역행 표본 | 1 / 251 | 1 / 266 |
| 마지막 오차 | 2.6° | 2.3° (불감대 2.9° 안) |

> 이 컨테이너는 GPU 가 없어 프레임이 낮고, 그만큼 «게임 시간» 이 벽시계보다 느리게
> 간다 (대략 2.5배). 그래서 **절대 초는 기기와 다르다** — 같은 조건에서 잰
> **이전 대비 비율**만 뜻이 있다.

전에 회전이 휙 도는 걸 막으려고 `maxYawRate = 2.2 rad/s`(126°/s)를 넣었는데,
그게 **지수 감쇠보다 먼저 걸려 버렸다.** 90° = 1.34 rad 를 126°/s 로 돌면 그것만
0.61초다. 설계 의도(시정수 0.30초)는 한 번도 발휘되지 못했고, 카메라는
«끌려오는» 게 아니라 **«기어서»** 왔다. 그게 어색함의 정체다.

**5.0 rad/s(286°/s)** 로 올렸다. 이제 급회전만 제한에 닿고, 보통은 시정수가 일을 한다.
7.0 까지 올려 봤지만 1.17초로 이득이 거의 없어(제한이 더는 병목이 아니다) 5.0 에서 멈췄다.

## 2. 프레이밍이 «헤엄치던» 이유 — 필터가 둘이었고 서로 달랐다

카메라 위치와 주시점이 **서로 다른 시정수**로 따라가고 있었다:

```
camPos .lerp(target, 1 - 0.001^dt)    → 시정수 0.145 초
camLook.lerp(look,   1 - 0.0005^dt)   → 시정수 0.130 초
```

회전하는 동안 카메라는 «아직 도착하지 않은 자리» 에서 «이미 움직인 주시점» 을
겨눈다. 그 어긋남이 프레이밍을 흔든다. **둘을 같은 시정수(0.12초)로 묶었다.**

## 3. 남은 것

* **회전 제한이 아직 있다는 것 자체**는 옳다 — 락온 중 보스가 뒤로 돌아갈 때
  카메라가 한 바퀴 휙 도는 걸 막는다. 값만 현실적으로 올린 것이다.
* **각도가 아니라 «위치» 의 지연**은 아직 안 쟀다. 벽 슬라이드(`camClear`)와
  거리 변화(`sizeDist`·락온 간격)가 같은 필터를 타므로, 벽 근처에서 튀는지는 별도 건이다.
