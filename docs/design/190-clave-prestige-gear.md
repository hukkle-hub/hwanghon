# 190. 클레이브 명예 장비 — 죽인 보스가 몸에 남는다

> 2026-10-07 · 리니지/디아블로/LoL·와일드리프트 공식 자료를 기준으로 한 첫 수직 구현.

## 1. 목표

클레이브 처치가 가방 속 수치로 끝나지 않게 한다. 멀리서도 `셔터 가로살 · 검은 티타늄 · 붉은 절개`로 출처를 알아보고, 가까이서는 강화 단계와 1위 처치 칭호를 확인한다. 화려함은 전투 위험 신호보다 앞에 나오지 않는다.

```
클레이브의 셔터 실루엣 → 드롭 빛기둥 → 장검/판금/등 셔터 → 이름 위 명예 칭호
```

보스 체력은 이 흐름 어디에도 넣지 않는다. 서버의 `field`/`bossHit`/공개 외형 정보는 남은 체력이나 비율을 보내지 않는다.

## 3. 외형 규칙

### 클레이브 세트

- 검증된 수문지기 중갑의 핏과 모바일 LOD를 기반으로 쓴다.
- 재질은 검은 티타늄으로 낮추고, 투구 세로 슬릿·흉갑 3단 가로살·팔/다리 절개만 붉게 발광한다.
- `달아오른 장검`은 카인의 중대검 실루엣에 붉은 코어를 더한다. 칼 전체를 네온으로 만들지 않는다.
- 신화 `셔터 방패`는 등뼈에 실제 가로살·측면 레일·상단 롤러가 있는 절차형 문을 단다. 새 대용량 바이너리 없이도 후면 실루엣이 즉시 달라진다.

### 강화 광휘

| 단계 | 공개 표현 |
|---|---|
| +0~+6 | 장비 고유 절개광만. 강화 과시 없음 |
| +7~+8 | 몸 가까이 주황 불티 6개 |
| +9 | 검붉은 불티 9개와 더 선명한 등 문장 |
| +10 | 백금빛 중심을 섞은 불티 12개. 화면 전체 섬광·점광원 없음 |

4세트나 셔터 방패는 +0이어도 아주 약한 몸 부착 불티로 출처를 보인다. 바닥 원형 이펙트는 보스 텔레그래프 전용이므로 장비에는 사용하지 않는다. 원격 플레이어마다 PointLight를 만들지 않고 `MeshBasicMaterial`/`Points`만 사용한다.

직교 카메라에서 월드 단위 점 크기는 1픽셀보다 작아져 단계 차이가 사라지므로, 불티는 거리 감쇠 없는 화면 픽셀로 고정한다. `+0~6 / +7~8 / +9 / +10`은 각각 `4×1.2px / 6×1.6px / 9×2.0px / 12×2.6px`다. 색·수량·크기 세 축을 함께 올려 작은 휴대폰 화면에서도 위계가 남되, 한 캐릭터당 `Points` 한 묶음만 쓴다. 운영체제의 동작 줄이기가 켜지면 이 정체성은 남기고 불티 부유·문장 회전·검 코어 펄스만 정지한다.

## 4. 공개 명예

`boss_kills.top`은 단순 참가가 아니라 해당 처치의 기여도 1위다. 오해를 막기 위해 칭호는 이 기록만으로 파생한다.

| 클레이브 1위 처치 | 칭호 |
|---:|---|
| 1 | 클레이브 토벌자 |
| 10 | 셔터를 멈춘 자 |
| 50 | 강남의 철문 |

이름표에는 가장 높은 칭호 하나만 보인다. 공개 필드 정보는 `eq` 전체 슬롯, **장착한 슬롯별** `enh`, 칭호만 싣는다. 가방, 창고, 내구도, 재산, 보스 체력은 싣지 않는다.

## 5. 구현·검증 계약

- 온라인 본인은 `profile.equipment`와 장착 아이템 강화값을 그대로 사용한다.
- 원격 캐릭터도 `main/sub/off`뿐 아니라 머리·흉갑·장갑·각반을 포함한 전체 `eq`를 사용한다.
- 빠르게 다시 입힐 때 이전 비동기 무기 로드가 늦게 붙지 않도록 외형 세대 번호를 검사한다.
- 모델 로딩 중 새 공개 정보가 오면 마지막 값을 보존했다가 완성 직후 다시 적용한다. 제목만 바뀐 경우 장비 GLB는 다시 만들지 않는다.
- 서버는 `infos` 소켓 전송이 실제 성공한 뒤에만 해당 외형을 전달 완료로 기록한다. 모바일 백그라운드 등으로 backpressure가 걸려 패킷을 버리면 다음 0.1초 필드 틱에서 다시 보낸다.
- 온라인 외형은 실제 장착 장비가 권위다. 옛 `fieldLook` 데모 프리셋은 호환상 받아도 무시하고, 온라인 장비 바꾸기 단추도 숨긴다. 주변 사용자가 반복 패킷으로 같은 장비를 재생성하게 만들 수 없어야 한다.
- 장비 변경은 필드에서 나간 뒤 인력사무소에서만 허용한다. 장비를 다시 입히거나 원격 캐릭터가 관심 반경을 벗어날 때 외형 전용 geometry/material/texture를 명시적으로 해제하고, 늦게 끝난 비동기 로드도 즉시 버린다.
- 바닥 전리품은 같은 서버 스냅숏이 반복되어도 색 객체와 DOM 이름표를 다시 만들지 않는다. 줍기·만료로 사라질 때 빛기둥·보석·바닥 표식의 geometry/material을 모두 해제한다.
- 셔터의 9개 가로살과 양쪽 레일은 인스턴싱한다. 원격 인원마다 같은 절차형 조각의 드로콜이 선형으로 폭증하지 않게 한다.
- 1위 칭호 집계는 접속 중 캐시하고 `boss_kills(top,boss)` 인덱스를 쓴다. 보스를 잡아 최고 기여자가 바뀔 때만 그 캐시를 무효화한다.
- 로컬 QA는 `viewer.html?equip=1&fit=1&char=kain&gearPreview=clave&enh=10`을 쓴다. 저장·소유권·스탯은 바꾸지 않는다.
- 데스크톱과 휴대폰 가로에서 정면/후면, 대기/보행/공격을 확인한다. 브라우저 오류, 누락 자산, 보스 HP 노출이 없어야 완료다.

2026-10-07 실제 로컬 파티 서버의 두 계정으로 본인·원격 각 6슬롯/칭호와 `+0·+7·+9·+10` 네 광휘 단계를 확인했다. 데스크톱 1280×720은 전 단계 36 draw calls·217,635 triangles, 휴대폰 가로 915×412 LOD는 전 단계 36 draw calls·75,630 triangles였고 브라우저 오류는 0건이었다. 동작 줄이기 데스크톱·휴대폰도 120 렌더 프레임 동안 동일 개체 UUID와 고정 위치·회전·불투명도를 유지했다. 셔터 인스턴싱 전 47 draw calls에서 9를 줄였고, 이번 픽셀 크기 조정은 새 조명·링·드로콜을 추가하지 않는다. 두 화면 모두 원격 캐릭터가 28m 관심 반경을 이탈→재진입→재이탈해도 장비가 복원되고 전용 GPU 해제가 두 번 호출되는 시나리오를 통과했다. 별도 소켓 시험에서는 클레이브 첫 1위 처치 뒤 본인 `fieldInfo`와 관찰자 `infos`에 같은 칭호가 즉시 도착하는 것도 검증한다.
