# 허수아비 숙련 전투 / 리그 연동 구현

기준: main `680146e` (등급 시스템 통합), 2026-09-17. 기존 Three.js 기반, 스토리·퀘스트 및 한 손 대기 자세를 유지한다. 외형·텍스처 교체는 후속 작업이다.

## 기획 근거와 적용 범위

프로젝트 원본 `Twilight_Detailed_Game_Design_v1.docx`의 §0·§2·§3 및 각수-0 항목을 확인했다. 원본의 방향은 높은 타이밍 난도, 설명 가능한 실패, 몸통 연타의 낮은 효율, 아인의 카운터·부분 파괴, 회피 후 정면 반격의 보상이다. 이 방향을 현재 구현에 적용했다.

아래 피해 배율과 체력은 **이번 구현의 조정값**이다. 원본에 확정 수치가 있었다고 간주하지 않는다. 원본의 오른팔·왼무릎·가슴 구성 대신 현재 에셋의 양쪽 견갑·가슴 사슬을 사용한다. 원본의 대칭 ±40ms 판정과 달리 이번 구현의 퍼펙트 판정은 **타격 전 마지막 40ms**이다. 원본의 중상 시스템·습관 적응·복수 타격·잡기를 전부 구현한 것은 아니다.

## 1~4 구현

| 항목 | 변경 내용 |
|---|---|
| 1. 타격 동기화 | 10ms 고정 시뮬레이션. 입력 → 준비 → 지정 타격 시점 → 후딜. 타격 순간 거리·방향 확인, 1회 피해. 각 행동의 조준 부위 고정. 히트스톱 동안 전투와 동작 시간 함께 정지. |
| 2. 전신·파지 | 기존 GLB 재사용. 골반·척추 보정, 전투/방어 중 왼손 자루 보정, 도달 불가능한 자세에서 오른손을 최대 22cm 안쪽으로 보정. 평지의 정지 공격에 발 고정 보조. |
| 3. 동작 전환 | 공격 초반 회피·방어 취소 금지, 후딜 후반 취소 허용. 마지막 160ms 입력 버퍼. 피격 시 준비 중인 공격 중단. 카운터와 회피 반격 연결. |
| 4. 허수아비 반응 | 예고와 타격/회복 클립 시간을 전투 상태에 맞춤. 공격 방향 고정, 빗나간 뒤 회복 구간. 일반 피격·부위 파괴 경직·격추·일어남·사망 연결. 부위 파괴가 공격을 끊으면 실제 판정도 중단. |

`js/combat.js`는 판정, `js/combat-motion.js`는 표시 보정, `js/dungeons.js`는 수치다. 모델을 교체할 때 리그 이름, 클립 이름과 접촉 지점을 맞추면 전투 규칙은 유지할 수 있다. 아인 접촉 지점은 기존 `tools/3d/retarget_ain.py`의 베기/내려찍기/찌르기/스매시 궤적에 맞춰 각각 0.34/0.44/0.34/0.78을 사용한다. 궁극기의 0.50은 임시값이다.

## 튜토리얼 조정값

모든 피해는 이후 약점·치명타·콤보·격추 보정을 받는다. 일반 공격 약화와 반격 배율은 중복 곱하지 않고 행동에 따라 선택한다.

| 상황 | 기준 배율 / 보상 |
|---|---|
| 일반 공격 | 공격력 × 0.22 |
| 공격 기술 | 기술 배율 × 공격력 × 0.55 |
| 카운터 / 퍼펙트 | 공격력 × 2.5 / × 3.0 (기존 배율 유지) |
| 실제 회피 성공 후 반격 | 공격력 × 2.2, 성공 뒤 0.85초 내 공격 시작 |
| 방어 후 반격 | 공격력 × 1.5, 0.8초 |
| 부위 내구도 피해 | 실제 피해 × 1.3, 카운터/반격이면 추가 × 1.6 |
| 부위 파괴 | 공격력 × 2.5 추가 피해 1회, 자세 피해와 경직 |
| 파괴된 부위 공격 | 약점 계수 1.75 |
| 격추 | 5초, 피해 × 1.5 |

회피 직전 실제 공격 범위 안에 있었고 해당 공격을 피한 경우에만 보상한다. 안전한 곳에서 구르기, 너무 일찍 구르기, 범위 밖에 가만히 있기에는 반격 보상이 없다. 보상은 공격을 시작할 때 소모되어 헛친 경우에도 다시 쓸 수 없다.

| 단계 | 체력 | 카운터 허용 구간 | 학습 |
|---|---:|---:|---|
| 눈뜬 허수아비 | 90,000 | 타격 전 180ms | 첫 단계부터 공격. 연타보다 관찰과 반격 |
| 사슬 허수아비 | 200,000 | 타격 전 160ms | 양 견갑 파괴, 보호 해제와 격추 |
| 깨어난 허수아비 | 280,000 | 타격 전 140ms | 카운터 가능 공격과 불가 공격 구별, 사슬 파괴 |

마지막 단계 회전 공격은 카운터·방어 불가, 주황색 범위와 X 상태 문구로 구별한다. 카운터 불가 공격은 카운터 등급의 분모에서 제외한다. 자동 궁극기 지급은 제거했다. 사망 화면에는 마지막 실패 이유를 하나 표시하고 기존 문 앞 재도전을 유지한다. 90/150/180초는 등급 계산 기준이며 강제 종료 제한 시간이 아니다.

## 검증

- Node 24, `npm test`: **25개 통과**. 실제 GLB의 스켈레톤과 애니메이션을 불러온다. 테스트의 텍스처 디코딩만 생략한다.
- 입력 즉시 피해 없음, 타격 시 거리 재확인, 조준 고정, 취소/버퍼, 일반/퍼펙트 카운터, 유효·무효 회피, 만료/소모, 방어 불가, 피격 중단, 파괴 중복/사망 상태, 4연타 스매시, 카운터 등급 검사.
- 30/60/120Hz로 같은 시간 구간을 진행했을 때 전투 스냅샷 동일. 이는 전투 시뮬레이션 검증이며 기기 입력 지연 측정은 아니다.
- 리그 11클립 각 40샘플: 변환 유한값·정규 쿼터니언 검사. 최대 왼손 목표 오차 0.029m, 발 보정 목표 오차 0.067m. 화면 품질이나 관절 관통에 대한 시각 검수를 대체하지 않는다.
- 전체 `js/*.js` 구문 검사 및 `git diff --check` 통과.

`node tests/balance.cjs`의 seed 7 결과:

| 자동 입력 정책 | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| 0.1초마다 몸통 공격 | 39.56초 사망 | 미진입 | 미진입 |
| 카운터·부위 파괴·회피 반격 | 23.14초 통과 | 33.33초 통과, 견갑 2개 파괴 | 70.47초 통과, 회피 17회·사슬 파괴 |

## 아직 확인할 항목

로컬 게임 주소에 브라우저가 `ERR_BLOCKED_BY_CLIENT`를 반환하여 이번 환경에서는 화면 플레이 검수를 완료하지 못했다. 검토용 초안으로 제공하며 다음 확인이 남는다.

1. `python -m http.server 8777` 후 `http://localhost:8777/game3d.html`에서 시작 → 입장 → 3단계 전투 → 사망/재도전 → 정산.
2. 이동/방어/카운터 사이 블렌딩, 손목·팔꿈치 방향, 낫과 몸 관통, 발 미끄러짐, 저사양 기기 성능.
3. 공격 판정은 **선택 부위 + 거리/방향 + 지정 접촉 시점**이다. 낫끝의 연속 스윕 충돌, 물리 기반 부위 타격, 동작 중 지형 발 IK는 후속 작업이다. `activeEnd`는 현재 동작 메타데이터이며 다중 타격 구간이 아니다.
4. 궁극기 클립 접촉 지점과 첫 승리 소요 시간을 실제 조작으로 조정한다. 메쉬/스킨 웨이트 재제작은 수행하지 않았다.
5. 공유 전투 엔진의 행동 시간/기술 분배는 구형 2D 전투 화면에도 적용된다. 이번 리그/HUD 연동의 기준 화면은 `game3d.html`이다. 갈대습지 수치 프로필은 유지하지만 공유 엔진 변화에 따른 플레이 감각은 별도 확인한다.

## 최신 등급 시스템 통합

main의 요원/기술 등급, 파티 보상, 전투 기록 저장을 유지했다. 파티의 부위 피해 배율을 지정 타격 시점에 적용한다. 카운터 등급의 추가 판정 시간(최대 90ms)은 위 표의 기본 구간에 더하며 퍼펙트 40ms는 유지한다. 반격 불가 패턴은 기술 등급의 카운터 성공률 분모에서도 제외한다. 위 자동 정책 비교는 파티 보정 없는 기준값이다. 통합 검증 3개를 추가했다.
