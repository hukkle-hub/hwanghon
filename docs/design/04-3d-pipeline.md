# 황혼 — 3D 전환 파이프라인 v0.1 (아인 · 낫 · 던전)

> 작성일 2026-09-16 · 전제: 그래픽보다 완성도. 3개월간 3번 갈아엎은 원인을 끊는 것이 목적.

## 0. 진단 — 왜 낫이 손에 안 붙었나

디렉터 쪽 파이프라인 문서(`TWILIGHT_AIN_NIGHT_RESULT_KO.md`, `AIN_HI3D_GENERATION_RESULT_KO.md`)를 읽은 결과:

- **최종 메시가 없다.** Hi3D 에서 만든 고폴리 원형은 계정에만 있고 GLB 를 내려받지 못했다(내장 브라우저의 Blob 다운로드 문제). 그 상태에서 80본 리그 템플릿, 32 액션, 98 이벤트, 언리얼 어댑터, 자동화 9개가 먼저 만들어졌다.
- **순서가 거꾸로다.** 리그·애니메이션·전투 어댑터는 메시가 있어야 검증된다. 메시 없이 쌓은 구조물은 메시가 오면 다시 맞춰야 하고, 그것이 "갈아엎기"로 보인다.
- **낫이 안 붙는 이유는 하나다.** 지금 있는 것은 뼈 없는 정적 메시(낫)뿐이고, 붙일 대상(손 뼈가 있는 아인)이 없다. 코드 문제가 아니다.

낫 GLB 판정(`art/3d/ain_scythe_v02.glb`): 정적 메시 15개(자루·소켓·칼라 7·자루끝·초승달 날·고정쇠 4), 스킨 없음, 실척(자루 0.04~1.72 m, 날 끝 2.29 m), 원점 = 자루 끝, 머티리얼 2, 텍스처 1. **그대로 쓸 수 있다.** 붙일 때는 자루의 그립 높이(약 1.0 m)를 손 원점에 맞추고 손 뼈의 자식으로 넣는다.

## 1. 최소 경로 (이것만 하면 화면에 아인이 낫을 들고 움직인다)

1. **Hi3D GLB 내려받기** — 일반 브라우저(폰 Chrome 도 됨)에서 Hi3D 기록 첫 항목 → GLB / Single file. 크레딧 안 든다.
2. **뷰어 판정** — `viewer.html` 에서 파일 선택. 높이·뼈·손 뼈·클립을 표로 보여 준다. 예상 결과: 뼈 없음(정적 메시). 그러면 3 으로.
3. **Mixamo 자동 리깅** — mixamo.com 에 GLB(또는 FBX/OBJ 로 변환) 업로드 → 관절 5점 찍기 → 리깅 완료. 같은 화면에서 애니메이션 내려받기: Idle, Walk, Run, Roll(Sprinting Forward Roll), Attack 3종(Great Sword Slash 계열), Hit Reaction, Death. FBX(with skin)으로 캐릭터 1개 + 나머지는 without skin.
4. **Blender 합치기(10분)** — 리깅된 FBX 를 열고 애니메이션 FBX 들을 가져와 NLA 로 액션 모으기 → glTF 내보내기(GLB, 애니메이션 포함, 텍스처 포함).
5. **뷰어 재판정** — 뼈 65개(mixamorig:…), 손 뼈 `mixamorig:RightHand` 자동 감지, 클립 8~10개. 낫 붙이기 → 그립·회전 슬라이더로 맞추고 **소켓 저장**(JSON).
6. **게임 반영** — 저장된 소켓 JSON 과 GLB 를 `art/3d/` 에 넣으면 3D 던전이 그대로 읽는다.

Hi3D 결과가 리깅에 부적합(찢어진 코트 조각이 분리돼 있음)하면 Mixamo 가 관절을 못 잡을 수 있다. 그때는 Blender 에서 "연결 성분 합치기 → 리메시(복셀 0.01)" 한 번으로 한 덩어리로 만든 뒤 올린다. 얼굴 유사도는 이 단계에서 따지지 않는다. **먼저 움직이게 하고, 얼굴은 나중에 교체한다.**

## 2. 규약 (네 번째 갈아엎기를 막는 계약)

| 항목 | 규약 |
|---|---|
| 단위·스케일 | 1 unit = 1 m. 아인 높이 1.68 m. 원점 = 발 사이 바닥 |
| 방향 | +Y 위, -Z 정면(glTF 기본). T 또는 A 포즈 |
| 뼈 이름 | Mixamo 표준(`mixamorig:Hips` …)을 그대로 쓴다. 손 소켓 = `mixamorig:RightHand` |
| 무기 | 별도 GLB, 원점 = 자루 끝, +Y 가 날 방향. 소켓 JSON(`{bone, grip, rot, off}`)으로 붙인다 |
| 클립 이름 | `idle walk run roll attack1 attack2 attack3 smash hit death guard` (Blender 에서 이름만 맞춘다) |
| 게임 진입 조건 | 뷰어에서 전 항목 통과(뼈·높이·손 뼈·클립) |

## 3. 3D 던전 계획 (Three.js, 같은 정적 배포)

- 렌더러만 교체한다. 전투 규칙(`combat.js`)·잡몹(`skirmish.js`)·월드 규칙(`world-sim.js`: 존·거리·AI)·저장·HUD 는 그대로.
- 3인칭 카메라(어깨 뒤, 락온 시 플레이어·보스 중간점), 스틱 이동, 구르기, 낫 소켓, 히트 판정은 존(바닥 원/직선)을 3D 바닥에 투영.
- 환경: 바닥 텍스처(이미 있음)·담·울타리·소품은 CC0 팩 또는 간단한 박스+텍스처로 시작. 조명: 횃불 포인트 라이트 + 안개 + 톤매핑.
- 허수아비: 3면도 → 이미지-3D(크레딧 필요) 또는 Mixamo 리깅 가능한 형태로 모델링 후 같은 경로.

## 4. 현실적인 기대치

- 위 최소 경로를 마치면(대부분 디렉터 쪽 30~60분 작업) 이틀 안에 "아인이 낫을 들고 뒷마당을 걷고 구르고 베는" 3D 슬라이스가 나온다.
- 얼굴 유사도·의상 디테일·고급 애니메이션은 그 뒤에 교체하면 된다. 구조는 유지된다.
