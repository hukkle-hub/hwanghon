# 174 — 타격 이펙트 2차 (붉은사막 분석 적용) + Kimodo 동작 게임 반영 (2026-10-01)

디렉터: «kimodo는 넣어보고 봐야 알것같아… 나머진 전부 진행해». 문서 173 적용안 1–6을 모두 넣었고, Kimodo 동작 세 개를 게임 세트에 넣었다.

## 1. 코드로 그리는 타격 층 — `AHWImpactFx`

팩 파티클로는 «가늘고 빠른 선 불꽃», 재질 반응, 회전 고리를 정확히 낼 수 없었다. 그래서 CPU로 시뮬레이션하고 인스턴스 메시로 그린다.

- 색·개수·시점이 정확하다.
- 휴대폰 예산은 숫자로 정한다: 동시 220개(PC 600개). 2차 QA 최대치는 187개였다.

| 종류 | 모양 | 쓰는 곳 (문서 173 장면) |
|---|---|---|
| Sparks | 속도 방향으로 늘어난 선, 중력 | 모든 타격(⑥⑦), 류 연타 샤워(⑩) |
| Needles | 수평으로 뻗었다 멈추는 바늘 고리 | 회전 매 타(③), 강타 고리(⑦), 세라 병 파편(⑨) |
| LensStreak | 화면 가로 빛줄기, 0.07 s | 맞는 순간(⑥) |
| Debris | 지푸라기 막대(허수아비) / 바위 조각(땅), 튕김·회전 | 재질 반응, 내려찍기(⑧) |
| Puff | 부드러운 원판, 커지며 사라짐 | 흙먼지, 세라 안개(⑤⑨) |
| Embers | 바닥에 깜박이는 불씨 2–2.6 s | 아인 궁극, 세라 광역(⑫) |
| Rings | 270° 가는 호 세 개가 발밑에서 돈다 | 아인·카인·류 3번 «회전/폭풍»(②) |
| Crack | 바닥 균열 데칼, 페이드 | 카인 1번·궁극, 아인 궁극 |

재료:
- 머티리얼과 고리 메시: `Scripts/ue_fx_impact_materials.py`
  - `M_HW_Streak`: 가산, 폭 감쇠 + 꼬리 감쇠, 인스턴스별 페이드는 PerInstanceCustomData[0]
  - `M_HW_Puff`, `M_HW_Flat`, `M_HW_CrackDecal`
  - `SM_HW_RingArc`: `tools/3d/make_ring_arc.py`
- 균열 텍스처: `T_HW_Crack` ← `tools/3d/make_crack_texture.py`

재질 반응:
- 맞은 보스의 메시 이름에 Training / Scarecrow / XBot이 들어 있으면 지푸라기 + 먼지 + 불꽃 조금이다.
- 아니면 불꽃(갑옷)이다.
- 기술 색은 불꽃 몇 개와 궤적·고리에만 남긴다(두 색 분리, 문서 173 §2.3).

카메라:
- 류 궁극: 스프링암 0.8배로 붙는다.
- 카인·아인의 내려찍기: 1.15배로 0.6 s 물러난다.
- QA 쇼트는 고정 카메라라 보이지 않는다. 휴대폰에서 확인한다.

궤적 폭은 0.5배로 줄였다(1차의 굵은 크림색 초승달). Countess 충격 고리(번지는 원판)는 뺐다.

## 2. 측정과 함정

1. **균열 데칼.**
   - 노멀맵에서 균열을 뽑았더니 박스 전체가 회색 사각형이 되었다.
   - Megascans «Crack» 시트는 흙 얼룩이었고, 가상 텍스처라 휴대폰에서 쓸 수 없다.
   - → 균열을 직접 그렸다(PIL).
   - QA 첫 프레임의 회색 사각형은 셰이더 컴파일 대기 화면이다. 쿡 빌드에서는 미리 컴파일된다.
2. **먼지가 흰 덩어리로 보였다.** 언릿 에미시브라 어두운 경기장에서 빛났다 → 퍼프 색 0.35배.
3. **첫 번째 액터 루프.** `for(TActorIterator…) return` 대신 `if (It(W); It)`를 쓴다(Android clang).

## 3. Kimodo 동작을 게임에

- `ue_mixamo_heroes.py`가 `art/anim/kimodo/hw_kmd_<id>.fbx`도 가져와서 세 칸을 바꿔 끼운다. `HW_KIMODO=0`이면 Mixamo로 되돌린다.
  - 바뀌는 칸: 카인 궁극, 아인 1번, 류 1번
- 함정 두 가지:
  1. **발이 바닥 아래로 −8~−13 cm 파묻혔다.**
     - Blender에서는 정상(+9.5 cm)이었는데 UE에서 몸 전체가 X축으로 90° 누워 들어왔다.
     - Blender가 아마추어 노드에 넣는 90° 회전을, 골반이 뿌리인 뼈대에서는 UE가 버린다.
     - Blender의 내보내기 축 옵션은 무엇을 바꿔도 결과가 같았다.
     - → UE `import_rotation` roll +90으로 해결했다. 단 메시가 든 FBX에서는 이 옵션이 무시되므로 **뼈대만 내보낸다**.
     - 결과: 발 12.7–14 cm(Mixamo와 같다).
  2. **뼈대만 있는 FBX는 Blender로 다시 읽으면 휴식 자세가 틀린다.** → 비교 렌더는 뼈의 월드 행렬을 그대로 복사한다. X Bot 스킨 파일에 들어 있는 T자 액션도 지운다.
- 골반 높이 비율은 다리 길이(골반−발목)로 잰다.
