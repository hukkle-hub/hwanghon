# 외형 화면 — 갈아입고 물들이기

> 기획 2단계 (`docs/design/33` §2). *"큰 3D 하나, 슬롯별 착·탈, **염색**,
> 외형 프리셋 3칸, 회전·확대·조명 각도."*

옷을 또 사고 싶게 만들려면 **입어 보는 자리**가 있어야 한다. 인벤토리의 작은
미리보기로는 «어떻게 보이는지» 를 알 수 없다. 마영전의 스타일 탭, 몬헌의 중첩
장비 화면이 하는 일이 이것이다.

## 1. 화면 구성 (`looks.html`)

| | |
|---|---|
| 왼쪽 318px | **착용 부위** 9칸. 부위 이름 · 아이템 · 염색한 곳은 색 점 |
| 가운데 | **큰 3D** + 자세 / 던전 바람 / 조명 / 자동 회전 + 아래 **소지품** 격자 |
| 오른쪽 330px | **염색** (16색 팔레트 · 자유색 · 되돌리기) + **외형 프리셋 3칸** |

부위는 **게임이 실제로 가진 9칸만** 둔다. 처음엔 「장신구 2」 칸을 넣었다가 뺐다 —
`gear.sum()` 이 `Object.keys(equipped)` 를 돌기 때문에, 화면에서 칸을 하나 늘리면
**능력치가 조용히 올라간다.** 외형 화면이 밸런스를 건드리면 안 된다.

## 2. 염색

`gear.js` 에 `dye={아이템:'#rrggbb'}` 를 저장하고, `tintOf(id)` 가 외형에 실제로
먹일 색을 돌려준다 — **염색이 먼저, 없으면 제작품 색조**. 한 번에 120 G.

섞는 세기는 `mixOf(id)` 로 나눈다. 제작품 색조는 «살짝»(0.35~0.55), 염색은
«확실히»(0.75). 같은 0.35 로 칠하면 염색했는지 알 수 없다.

`#rrggbb` 가 아닌 값은 **저장 단계에서 거절한다.** 셰이더까지 흘러가면
`new THREE.Color('빨강')` 이 조용히 검게 칠해 놓고 아무 말도 하지 않는다.

## 3. 3D 를 다시 그리는 법 — 여기서 한 번 크게 막혔다

3D 는 `viewer.html` 을 iframe 으로 띄운다. 장비를 바꾸거나 물들이면
`postMessage({t:'relook'})` 로 **다시 붙이기만** 시킨다 (모델을 다시 받으면 2 초가
걸려 염색 미리보기가 답답하다).

**처음엔 아무것도 바뀌지 않았다.** 알림은 «착용» 이라 뜨고, 슬롯 목록도 색 점도
제대로 갱신되는데, **3D 만 그대로**였다. 원인은 `save.js` 의 이 한 줄이다.

```js
var S=load();   /* 스크립트를 «읽는 순간» 딱 한 번 */
```

부모 창과 iframe 은 같은 `localStorage` 를 보지만 **각자 제 기억(`S`)을 들고 있다.**
부모가 저장을 고쳐도 iframe 의 `S` 는 옛날 장비 그대로였고, `applyEquip()` 은
성실하게 **옛 장비를 다시 입히고 있었다.**

`TW_SAVE.reload()` 를 넣고 `relook` 에서 먼저 부른다. 테스트로 못박았다 —
바깥에서 `localStorage` 를 직접 고친 뒤, `reload()` 전에는 안 보이고 후에는
보인다는 것을 확인한다.

**이 함정은 창이 둘인 곳 어디에나 있다.** 앞으로 iframe 으로 무언가를 미리 보여
줄 때마다 같은 실수가 가능하다.

## 4. 외형 프리셋

장비 구성과 염색을 통째로 3칸에 저장한다. 빈 칸을 누르면 저장, 찬 칸을 누르면 입기,
우클릭(길게 누르기)이면 비우기.

**가진 것만 입는다.** 저장한 뒤 분해했거나 잃은 장비는 건너뛰고 몇 점이 없는지
알려 준다. 없는 장비를 억지로 끼우면 인벤토리와 장착 상태가 어긋난다.

## 5. 휴대폰

세 판(슬롯 · 외형 · 염색)으로 접고, **3D 가 기본 판**이다. 바닥 바의 주 행동은
「물들이기」.

가로(412px 높이)가 빡빡하다. 처음엔 3D 최소 높이를 220px 로 잡았다가
**소지품 판 118px 중 106px 이 바닥 바에 가려졌다** — 눈으로는 «판이 좀 작네» 로
보였고, 가려진 양을 재고서야 알았다. 가로에서는 3D 최소 높이를 80px 로 풀고
소지품을 92px 로 고정한다.

선택 칸도 한 번 틀렸다. `label.field` 를 40px 로 키웠는데 **안쪽 `select` 는
14px 그대로**였다. 손가락이 닿는 것은 label 이 아니라 select 다 —
`.field select{height:100%}` 를 넣고, 테두리 1px 을 감안해 label 을 40px 로 둔다
(select 38px).

## 6. 검수

`tests/looks-dye.test.cjs` 7 개 (**203/203**).

- **염색해도 장비 능력치·전투력·강화 배율이 한 자리도 움직이지 않는다** — 이 화면의 약속
- 염색이 제작품 색조를 이긴다
- `red` · `#fff` · `2F6B5E` 같은 엉터리 색은 저장 단계에서 거절한다
- 프리셋: 저장 → 다 벗고 → 되입기. 염색까지 돌아오고, 가방에 중복으로 쌓이지 않는다
- 분해한 장비가 든 프리셋을 입어도 터지지 않고, 없는 것을 알려 준다
- 빈 칸·범위 밖 칸은 막는다
- **다른 창이 고친 저장을 `reload()` 로 다시 읽는다** (§3 의 버그)

화면은 `tools/screen-fit.mjs` 의 22번째 화면으로 들어갔다 — 952px 한 장에 들어간다.
