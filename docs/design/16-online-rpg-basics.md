# 황혼 · 온라인 RPG 기본 시스템 적용

2026-09-18. 이 문서가 온라인 기능의 최신 범위다. 전체 접속 목표 100명, 협동 던전 최대 4명, 쉘터는 길드 쉼터, 인력사무소는 의뢰·모집 화면이라는 기존 결정을 유지한다. 캐릭터·마을 아트를 추가하지 않았다. 개인 패턴 훈련만 1인 입장이 가능하다.

## 온라인 성장 규칙

- 싱글의 레벨 26 기준 장비 요구치와 온라인의 레벨 1 시작을 혼용하지 않는다. 온라인 착용 레벨은 기본 낫 1, 나머지는 `max(1, 1 + floor((원본 요구 레벨 - 10)/5))`다. 제작 레벨은 기존 제작 요구치의 1/6을 올림한 초기 조정값이다.
- 장비는 종류별 하나를 수집한다. 중복 장비 보상은 강화 합금으로 바뀐다. 재료·소모품은 수량을 보유한다. 개별 옵션이 다른 동일 장비 여러 개, 자유 재료 조합 제작, 검·창 캐릭터 추가는 이번 기본 범위가 아니다.
- 현재 원본 코드 `js/gear.js`의 강화 방침을 따르므로 +1부터 실패할 수 있고 확률은 최대 90%다. 실패 보정은 +3%p씩 최대 +30%p, 성공 시 초기화된다. 보조제는 단계 하락만 막는다. 내구도 20 미만은 강화 불가다.
- 온라인 기본 버전에서는 장비가 내구도 0으로 영구 소멸하지 않는다. 공격·체력·방어 기여도가 감소하고 수리로 복구된다. 실패로 주무기가 사라져 출정이 막히는 것을 방지한다. 화면에서 이 규칙을 명시한다.
- 제작은 즉시 완료된다. 기존 시트의 제작 대기 시간과 자유 조합 외형 생성은 사용하지 않는다.
- 치명타·기술 피해, 낫 출혈, 반지 출혈 보정, 흉갑 출혈 피해 감소, 목걸이 출혈 시간 감소, 각반 이동 속도, 건틀릿 카운터 후 공격 증가, 장화 회피 후 이동 증가를 온라인 전투에 반영한다. 주무기 모델은 기존 아인 낫을 재사용한다.
- 전투 중 소모품은 동작 중·다운·재사용 대기·부적절한 대상 상태에서 사용되지 않는다. 출혈은 보스 일반 피격 뒤 발생하며 지속 피해만으로 HP 1 아래로 떨어지지 않는다. 공격 자체는 치명 피해를 줄 수 있다.

## 접속 종료·보상 정책

출정 참가자를 기록하고, 클리어가 확정되면 개인별 보상 우편을 먼저 DB에 남긴다. 그 뒤 프로필 반영·지급 영수증·우편 지급 상태를 트랜잭션으로 확정한다. 지급 중 중단되면 다음 로그인이나 서버 시작 때 미지급 우편을 다시 처리한다. 같은 출격 보상과 최초 클리어 추가 보상을 중복 지급하지 않는다.

연결이 끊긴 참가자는 기존 90초 파티 복귀 유예가 지나도 출격 참가 기록이 유지된다. 남은 동료가 완료하면 보상을 받는다. 스스로 파티를 나가거나 로그아웃한 사람은 그 이후 확정되는 해당 출격 보상 대상에서 제외한다. 클리어가 이미 확정된 우편은 탈퇴해도 사라지지 않는다.

서버 재시작 시 진행 중인 던전은 `interrupted`로 남고 다시 출정해야 한다. 전투 자체를 재생 복원하지 않는다. 보상 우편의 최초 DB 기록조차 디스크 오류로 실패한 상태에서 서버가 꺼지는 경우까지 보상을 복구할 수 있는 것은 아니다. `rewardStatus=pending` 동안 접속된 클라이언트에 저장 재시도 상태를 표시한다.

개인 훈련은 보상·퀘스트 진행을 만들지 않는다. 훈련에서 사용한 소모품도 실제로 차감하며 화면에 알린다.

## 운영 설정

`ADMIN_IDS`는 운영 계정의 캐릭터 UUID를 쉼표로 나눈 환경 변수다. 수첩 → 계정에서 자신의 UUID를 확인할 수 있다. 비어 있으면 누구에게도 운영 권한을 주지 않는다. 클라이언트가 보낸 운영자 표시·역할로 권한을 부여하지 않는다. 설정 후 서버를 재시작하면 해당 계정의 수첩에 운영 메뉴가 나타난다. 실제 사용자 계정에 이번 작업에서 임의로 운영 권한을 주지 않았다.

자동 백업 기본 간격은 1시간(`BACKUP_INTERVAL_MS=3600000`), 기본 위치는 `DATA_DIR/backups`다. `BACKUP_DIR`로 변경 가능하다. 최근 자동 백업 5개를 보관한다. 동일 디스크의 백업은 장비·볼륨 자체의 손실을 막아주지 않으므로 장기 운영에서는 백업 파일을 별도 저장소에도 복사해야 한다.

```sh
npm run backup
node tools/party-backup.cjs verify /absolute/path/to/backup.sqlite
# 게임 서버를 종료한 상태에서 실행한다. 이전 DB는 before-restore-* 디렉터리에 보관한다.
node tools/party-backup.cjs restore /absolute/path/to/backup.sqlite --server-stopped
```

기존 Docker Compose의 `party-data` 볼륨에서 계정·백업이 유지된다. `docker compose down -v`는 볼륨을 지우므로 일반 재시작에는 사용하지 않는다.

## 검증 결과

- 자동 테스트 **92개 통과**, 실패 0. 새 테스트 22개에 의뢰 해금, 가방 보존, 제작 롤백, 장비 요구 레벨, 특성, 친구·길드 권한, 귓속말 비공개성, 차단, 훈련 무보상, 소모품 한도, 운영 권한, 코드 재사용 차단, 접속 교체, 보상 재시작 복구·최초 보상 1회, 실제 SQLite 백업·오프라인 복구를 포함한다.
- DOM 검사에서 실제 서버와 요청을 주고받으며 가입·복구 코드 표시·이름·의뢰 수락/보수·지역 해금·가방 필터/보관·제작·특성·음량 설정을 확인했다. 검사에만 jsdom 26을 별도 설치했다. 앱 런타임 의존성은 추가하지 않았다.
- 100개 실제 WebSocket, 101번째 거절, 25개 독립 4인 전투, 연결 손실 0, 프로토콜 오류 0. 10초 전투 표본에서 CPU 단일 코어 환산 30.1%, RSS 118.3 MiB, 왕복 지연 p95 9.86ms, 송신 2.67 MiB/s, 생략된 시뮬레이션 단계 0. 로컬 머신 수치이며 Render나 실제 인터넷 100명 성능을 보장하지 않는다.
- 스키마 조회 준비문과 차단 목록 조회를 재사용하여 월드 채팅 시 전투 지연을 줄였다. 최초 측정에서 발견한 긴 지연 구간을 수정한 뒤 위 결과를 측정했다.
- DOM 검사에서는 WebGL·CSS 배치·실제 휴대폰 터치를 검증하지 않는다. 실제 기기 시각·조작 검수, 인터넷 타이밍 체감, 장시간 부하 측정은 남아 있다.

검증 원본: `docs/validation/rpg-tests.txt`, `rpg-ui-dom.json`, `party-load-100.json`.

## 배포 상태

사용자가 Render `다민's workspace`를 배포 대상으로 승인했으며 연결을 확인했다. 하지만 GitHub 연결 앱의 쓰기가 `403 Resource not accessible by integration`으로 거부되어 공개 배포는 미완료다. 이번 변경 역시 로컬 커밋과 전달 패키지에 저장한다.

기존 `render.yaml`은 무료 테스트 설정으로, 재시작 시 저장 데이터가 초기화될 수 있다. 이 파일을 영구 저장 서비스라고 설명하지 않는다. 이번 구현은 영구 볼륨이 있는 로컬/Docker 저장과 백업을 준비한 것이며, 유료 Render 자원을 생성하거나 비용 설정을 변경하지 않았다.
