# 191. 클레이브 접촉과 무게 — 숫자 밖에서 맞고 걷는다

> 2026-10-07 · 클레이브 세부 전투의 두 번째 수직 개선. 판정·피해·보스 체력은 바꾸지 않고, 이미 일어난 서버 판정을 여러 사람이 같은 접촉으로 보게 한다.

## 1. 문제

필드 공격은 서버가 피해를 정확히 굴리지만, 화면에서는 공격자에게 뜨는 숫자가 거의 전부였다. 주변 사람은 클레이브가 누구에게 맞고 있는지 느끼기 어렵고, 걷기는 중심 고리와 상하 흔들림만 있어 실제 어느 발이 땅을 딛는지 약했다.

```
서버 판정 ─▶ 공격자 피해 숫자
          └▶ 같은 지역·가까운 관찰자: 접촉점 불꽃 + 짧은 몸 반응

보행 클립 ─▶ 왼발/오른발 실제 위치 ─▶ 접지 먼지 + 작은 압력 고리
```

보스 체력·남은 비율·타인의 피해량은 이 흐름에 들어가지 않는다.

## 3. 구현 계약

### 공동 접촉 사건

- 서버는 보스별 최신 접촉 사건을 최대 셋만 0.65초 보존한다. 필드 10 Hz 스냅숏에서 같은 지역이면서 관심 반경 안인 사람에게만 보낸다. 느린 저장 직후에도 최소 한 틱은 관찰자에게 도착하고, 한 틱 사이의 치명타·반격이 바로 다음 일반타에 덮이지 않으면서도 크기는 고정된다. 클라이언트는 순번으로 반복 전송을 지운다.
- 공개 값은 `보스 id · 순번 · 접촉 x/z · 치명/반격 여부 · 서버 시각`뿐이다. 타인의 피해량, 공격력, 장비, 보스 체력은 없다.
- 공격자는 즉시 `bossHit` 응답으로 반응하고, 뒤이어 오는 같은 순번의 스냅숏은 무시한다. 관찰자는 순번으로 중복을 제거한다.
- 서버 재기동으로 순번이 다시 시작되어도 더 새로운 서버 시각이면 새 세대로 받아들인다. 반대로 숨긴 탭이나 0.8초 넘게 늦은 사건은 순번만 소비하고 불꽃·소리·진동은 재생하지 않는다.
- 접촉 사건은 보스 동작을 취소하지 않는다. 일반타는 0.12초, 치명타는 0.18초 이내의 가산형 상체 흔들림만 준다. 반격만 기존 서버 `stagger`를 사용한다.
- 아주 많은 사람이 동시에 때려도 보스별 최신 사건 셋까지만 남아 화면·패킷이 폭주하지 않는다.

### 보행 무게

- 중심점이 아니라 GLB의 왼발/오른발 뼈 위치에서 접지 효과를 낸다. 벽시계가 아니라 실제 `walk` 액션 위상을 읽고, GLB에서 잰 왼발 12.1%·오른발 63.8% 최저점을 지난 프레임에 한 번씩 낸다. 0.82배속을 바꿔도 먼지가 발보다 먼저 달아나지 않는다.
- 접지 프레임에 작은 먼지와 낮은 압력 고리를 함께 내고, 가까울 때만 약한 화면 흔들림을 준다.
- 골반 하강과 좌우 무게 이동은 걷기 클립 위에 작게 더한다. 서버 이동 속도와 충돌 위치는 바꾸지 않는다.
- 보스 예고 범위는 붉은 면, 반격창은 청백색이다. 발 먼지는 낮은 갈색으로 두어 위험 신호와 경쟁하지 않는다.
- 화면 흔들림과 진동은 `prefers-reduced-motion`에서 끈다. 타격음은 14 m, 진동·화면 흔들림은 12 m 안으로 제한해 화면 밖 다른 파티의 연타가 휴대폰을 계속 울리지 않게 한다.

### 타격 계층

| 사건 | 화면 반응 |
|---|---|
| 일반타 | 접촉 불꽃 10~12개 · 0.12초 미세 반동 · 작은 금속음 |
| 치명타 | 금빛 접촉 불꽃 18~24개 · 0.18초 반동 · 조금 큰 금속음 |
| 반격 | 기존 청백 고리·서버 경직·큰 흔들림 유지 |
| 보스 강공격 | 기존 붉은 실제 판정 범위·충돌 고리 유지. 일반타보다 항상 강하다 |

`mmo.html`은 음악까지 든 전체 12종이 아니라 전투 효과음 8종만 미리 받는다(현재 WAV 합계 806,580 bytes). 첫 공격이 무음이 되지 않게 디코딩은 먼저 하되, 실제 재생은 브라우저 정책에 맞춰 첫 입력으로 AudioContext가 재개된 뒤에만 한다.

쓰러지는 마지막 타격은 먼저 사망 상태를 적용한 뒤 접촉 불꽃을 만든다. 따라서 다음 10 Hz 스냅숏의 같은 순번이 불꽃을 지우지 않는다. 죽은 뒤에는 사망 연출 또는 입자 꼬리가 남은 동안만 모션을 갱신하고, 약 0.4초 뒤에는 다음 출현까지 프레임 비용을 쓰지 않는다.

## 4. 검증

- 단위 시험은 `bossImpacts`의 허용 필드를 정확히 고정하고 `hp/maxHp/health/ratio/dmg`가 들어오면 실패한다.
- 두 실제 소켓으로 공격자는 즉시 한 번, 관찰자는 다음 필드 틱에 같은 순번을 받는지 확인한다. 관찰자에게 피해량은 없어야 한다.
- 데스크톱 1280×720과 휴대폰 가로 915×412에서 일반타·치명타·좌우 발 접지를 프레임으로 찍는다.
- 공격 반응 중에도 서버 `bossActs` 위치·기술 시각을 계속 따르고, 셔터 예고 면을 가리지 않아야 한다.
- 전체 `npm test`와 보스 HP 비공개 엄격 스키마를 통과해야 완료다.

2026-10-07 검증 결과:

- 전체 `npm test`: **707/707 성공**.
- 데스크톱 1280×720과 휴대폰 가로 915×412 시나리오가 모두 성공했다. 각각 16장을 프레임 기준으로 찍어 좌우 접지·일반타·치명타·막타·피격·사망을 확인했다.
- 30/60/120 fps 표본에서 한 루프에 왼발·오른발이 정확히 한 번씩 발생했고 실제 접점 오차는 25 ms 안이었다. 시나리오에서는 먼지 `9 → 18`, 종료 후 위치·회전 누적 오차 `0`이었다.
- 일반타 입자 12개, 치명타 22개, 막타 반격 30개와 고리 1개가 계층대로 발생했다. 같은 순번 재전송은 0개를 더 만들었고, 막타 잔상은 45프레임 뒤 입자·고리 모두 0이 됐다. 5초 늦은 사건은 순번만 소비하고 화면 효과를 만들지 않았다.
- 측정 장면은 데스크톱 52 draw calls / 557,697 triangles, 휴대폰 LOD 52 draw calls / 193,855 triangles였다. 새 접촉·먼지는 고정 크기 포인트 풀이고 보스 사망 뒤 잔상이 끝나면 프레임 갱신도 멈춘다.
