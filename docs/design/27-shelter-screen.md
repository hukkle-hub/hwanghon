# 쉘터 화면 — 설계만 있고 화면이 없었다

「전에 쉘터 구성한 것도 만들어.」

## 1. 무엇이 있었고 무엇이 없었나

`docs/design/15-shelter-social-server.md` 가 쉘터를 정해 놓았다 —
**길드 소속·접속 상태·초대 코드·길드 채팅을 쓰는 텍스트형 쉼터.**
서버는 그대로 다 있다. `server/index.cjs` 에 `guildCreate` / `guildJoin` /
`guildLeave` / `chat`(월드·길드·파티) / `board`(접속 인원)가 구현돼 있고
테스트도 붙어 있다.

**없던 것은 화면이다.** 쉘터 UI 는 `party.html` 안 `#social-area` 에
라벨·입력칸·버튼이 세로로 늘어선 맨 폼으로 들어가 있었다. 게임의 다른
화면과 아무 관계가 없는 모양이고, 로그인하기 전에는 `hidden` 이라
**로비의 「길드」 버튼을 눌러도 로그인 폼만 보였다.**

## 2. `shelter.html` — 게임 화면으로 만들었다

다른 화면과 같은 규약을 따른다: 1672×952 스테이지, 상단바, 하단 네비,
`panel--framed`, `data-mpane` (휴대폰 탭 전환).

```
┌ 쉘터 ─────────────────────────────────────────────────────┐
│ 접속 현황 1/100 ●│  아트 + 인용                │  채 팅    │
│ 내 길드          │  ───────────────────────── │  월드     │
│  문장 · 이름     │  길드 명단                  │  길드     │
│  초대 코드 [복사]│   ● 아인_디렉터    [길드장] │  파티     │
│  길드 공지       │                             │           │
│  [길드 탈퇴]     │  ───────────────────────── │  ────────│
│ 쉘터란           │  → 협동 출격                │ [입력][전송]│
└ 로비 · 인력사무소 · 쉘터 · 협동 출격 · 상점 · 창고 ───────┘
```

접속 상태에 따라 왼쪽 패널이 네 얼굴로 바뀐다:
**접속 전**(계정/체험) → **이름 미정** → **길드 없음**(만들기/코드 합류) → **소속**.

채팅은 월드·길드·파티 세 채널을 탭으로 나눠 보여 준다. 채널마다 색이 다르고,
받은 글은 전부 이스케이프해서 텍스트로만 넣는다.

## 3. 서버는 한 줄도 안 건드렸다

`js/shelter.js` 는 `party.html` 과 **같은 WebSocket 프로토콜**을 쓴다.
서버 주소 규칙(`?server=` → `localStorage`)과 접속 키(`tw:party-token:<host>`)도
같다 — 한쪽에서 로그인해 두면 다른 쪽에서 바로 붙는다.

정적 호스팅(GitHub Pages)에는 파티 서버가 없다. 그때는 **빈 화면을 주지 않고**
설계된 화면을 그대로 띄운 뒤 「서버를 실행한 주소로 열거나 `?server=주소` 를
붙이세요」라고만 알린다.

> **온라인 반영 시점**: `server/` 를 바꾸지 않았으므로 Render 재배포는 필요 없다.
> 정적 파일만 올라가면 바로 열린다.

## 4. 검수 — 실제로 돌려 봤다

로컬 파티 서버(`node server/index.cjs`)를 띄우고 헤드리스로 끝까지 밟았다.

1. 계정 만들기 → `welcome`
2. 캐릭터 이름 「아인_디렉터」 → `profile`, 왼쪽 패널이 «길드 없음» 으로
3. 「황혼의 인력사무소」 길드 생성 → `guild`, 초대 코드 `B7827C8B54`
4. 명단에 초록 점 + 「길드장」 배지
5. 월드 채팅 전송 → 되돌아온 `chat` 이 월드 탭에만 보임
6. 길드 탭으로 바꿔 전송 → 길드 탭에만 보임 (채널 분리 확인)

콘솔 오류 0, 스테이지 952px.

한 가지 밟은 것: 캐릭터 이름은 **전 서버 중복 불가**라 앞 세션이 쓴 이름으로는
다음 단계가 안 넘어간다. 서버가 의도한 동작이고(문서 15), 화면은 그 오류를
왼쪽 아래 상태 줄에 빨갛게 보여 준다.

## 5. 연결

- 로비(`index.html`)의 **길드 / GUILD** → `party.html` 이던 것을 `shelter.html` 로.
- 하단 네비에 「쉘터」 추가, 「협동 출격」(`party.html`)과 나란히.
- `sw.js` 프리캐시에 `shelter.html` · `js/shelter.js`.

## 6. 길드 관리 — 공지·임원·위임·추방

### 6.1 먼저, 내가 §6에 적었던 말이 틀렸다

「길드 공지 편집·길드장 위임·추방은 **서버에 명령이 없다**」고 적었다. **있었다.**
`server/rpg-store.cjs` 의 `guildManage(id, action, target, value)` 가
`notice` / `kick` / `transfer` / `officer` / `member` 를 전부 처리하고,
`server/rpg-server.cjs` 가 `{type:'rpg', action:'guildManage', …}` 로 이미
연결해 두었다. 권한 규칙까지 들어 있다:

| | 공지 | 임원 임명·해제 | 길드장 위임 | 추방 |
|---|---|---|---|---|
| 길드장 | ○ | ○ | ○ | 길드장 외 전원 |
| 임원 | ○ | ✕ | ✕ | 평 길드원만 |
| 길드원 | ✕ | ✕ | ✕ | ✕ |

`tests/rpg-store.test.cjs` 에 이 규칙의 테스트도 이미 있었다.
**소스를 안 읽고 «없다» 고 적었다.** 확인하고 말했어야 했다.

### 6.2 그래서 실제로 없던 것 — 당사자에게 알리지 않았다

명령은 다 도는데, **추방당한 쪽이 아무 말도 못 들었다.** 길드가 조용히 사라지기만
해서 「내가 나간 건가, 쫓겨난 건가」를 화면으로 구분할 수 없었다. 임원이 되거나
길드장을 넘겨받은 쪽도 마찬가지였다.

`rpg-server.cjs` 의 `guildManage` 에 알림을 붙였다.

| 조작 | 당사자 | 나머지 길드원 |
|---|---|---|
| 공지 | 「길드 공지를 저장했습니다.」 | 「[길드] ○○ 님이 공지를 바꿨습니다.」 |
| 추방 | **「길드에서 추방되었습니다.」** | 「[길드] ○○ 님이 추방되었습니다.」 |
| 위임 | 「길드장이 되었습니다.」 | 「[길드] ○○ 님이 새 길드장입니다.」 |
| 임원 | 「길드 임원이 되었습니다.」 | — |
| 해제 | 「길드 임원에서 내려왔습니다.」 | — |

> **온라인 반영**: `server/` 를 고쳤으므로 **Render 재배포가 필요하다.**
> 그건 GPT 몫이다. 재배포 전까지 온라인 서버에서는 알림만 안 뜨고,
> 공지·임원·위임·추방 자체는 **원래 되던 대로 된다.**

### 6.3 화면

`shelter.html` 에 붙였다. 서버의 권한 규칙을 **그대로 비춘다** — 클라이언트가
권한을 정하는 게 아니라, 서버가 `guildDetails` 로 내려 주는 `role` 을 보고
«무엇을 보여 줄지» 만 정한다.

- **길드 공지**: 길드장·임원에게는 240자 textarea + 「공지 저장」, 나머지는 읽기 전용.
- **명단 행**: 「길드장」·「임원」 배지, 그리고 권한에 맞는 버튼만.
  임원에게는 평 길드원의 「추방」 하나만 뜬다 (실측으로 확인).
- **추방·위임은 확인을 받는다** — 되돌릴 수 없다.
- 서버가 보낸 알림은 왼쪽 아래 상태 줄에 뜬다.

### 6.4 검수 — 세 명을 동시에 띄워서

브라우저 컨텍스트 셋(길드장·임원·평단원)을 붙여 끝까지 밟았다.

```
mate 가 본 공지 : 오늘 22시 갈대습지. 넷 채우면 바로 출발.
mate 상태 줄    : [길드] 길드장아인 님이 공지를 바꿨습니다.
mate 권한       : 내 권한 임원
임원이 쓸 수 있는 버튼: kick:추방          ← 위임·임명 버튼은 안 나온다
추방당한 쪽 상태: 길드에서 추방되었습니다.
추방당한 쪽 화면: 길드 없음 패널
새 길드장 권한  : 내 권한 길드장
```

`tests/guild-manage.test.cjs` 두 개를 새로 박았다 (알림 5종 / 권한 없는 사람 차단).
**일부러 깨뜨려 보고** 확인했다 — 추방 알림을 지우면 1번이, 임원 알림을 지우면
1번이 정확히 실패한다.

### 6.5 그 과정에서 찾은 버그 (내가 넣은 것)

명단의 접속 점이 전부 꺼지고 「접속 0 / 3명」으로 나왔다. 내가 방금 넣은
`type:'rpg'` 처리가 원인이었다 — 그 메시지의 `data.guild` 는 `guildDetails` 원본이라
**`online` 플래그가 없는데** 그걸로 기존 길드 상태를 통째로 덮고 있었다.
길드가 바뀌는 길은 전부 `type:'guild'` 도 같이 보내므로 `rpg` 쪽은 안 쓰기로 했다.

## 7. 아직 안 한 것

- **귓속말·차단** — `rpg-server.cjs` 에 있지만 party.html 쪽 UI 에 묶여 있다.
- **길드 가입 신청·승인** — 서버에 없다 (지금은 초대 코드만).
- 쉘터 **화면**에는 단위 테스트가 없다. DOM 에 붙은 UI 라 노드 테스트로
  의미 있게 고정하기 어려워서 헤드리스 시나리오로 대신했다.
  서버 쪽은 `tests/guild-manage.test.cjs` 로 고정했다.
