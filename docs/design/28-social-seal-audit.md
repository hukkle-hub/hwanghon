# 귓속말·차단, 봉인, 그리고 «구현된 척하던 것» 찾기

「귓속말·차단도 쉘터에 붙여. 그리고 구현 안 한 것들도 찾아서 보완하자.」

## 1. 쉘터의 귓속말·차단 — 서버는 이미 다 있었다

또 확인부터. `js/party-rpg.js` 가 **친구 요청·수락·삭제·차단·차단 해제·귓속말·신고**를
전부 쓰고 있었고 서버(`rpg-server.cjs` + `rpg-store.cjs`)도 완비돼 있었다.
없던 것은 party.html 의 맨 폼 밖, **쉘터 화면 쪽 UI** 였다.

붙인 것:

| | 어디에 | 무엇 |
|---|---|---|
| 귓속말 | 채팅 탭 4번째 | 받는 캐릭터 칸이 그때만 열린다. 로그에 「보낸이 → 받는이」 |
| 동료·차단 | 우측 하단 패널 | 이름으로 친구 요청 / 차단 / 신고 |
| 목록 | 같은 패널 | 친구·요청·차단을 접속 점과 함께. 행마다 권한에 맞는 버튼만 |

행 버튼도 **서버 규칙을 그대로 비춘다**: 받은 요청만 「수락」이 뜨고, 차단은
「차단 해제」만, 친구에게는 「귓속말·삭제·차단」. 차단·삭제는 확인을 받는다.

### 검수 — 두 명을 동시에 띄워서

```
대상 칸 보임 : true
받은 귓속말  : 귓속말  아인_소셜 → 카인_소셜  혼자 가지 마라.
받은 쪽 목록 : 아인_소셜  받은 요청  [수락][취소]
수락 후      : 카인_소셜  친구  [귓속말][삭제][차단]
요약         : 친구 1 · 차단 0
차단 후      : 카인_소셜  차단  [차단 해제]
차단 중 귓속말: 귓속말을 보낼 수 없습니다.     ← 서버가 막는다
신고 결과    : 신고를 접수했습니다.
```

콘솔 오류 0. `server/` 무변경 — 이번 건은 **Render 재배포가 필요 없다.**

## 2. 「봉인」 — 시트에 있고 버튼도 있는데 «준비 중» 이었다

`forge.html` 의 오른쪽 레일 4칸 중 **봉인**만 눌러도 「잠재력 봉인은 준비 중입니다」
가 뜨고 버튼이 비활성이었다. 설계 시트(06-forge)에는 처음부터 있던 칸이다.

만들었다. **봉인한 장비는 강화·분해로 잃을 수 없다.**

- `js/gear.js` — `sealedOf(id)` / `seal(id,on)`, 저장은 `gear.sealed`.
  `enhance()` 와 `dismantle()` 가 봉인을 먼저 본다 (`err:'sealed'`).
- `forge.html` — 봉인 칸이 상태(열림/잠김)와 버튼(봉인/봉인 해제)을 보여 준다.
  강화·분해 칸에서도 **누르기 전에** 막힌 이유가 뜨고 버튼이 꺼진다.
- 가운데 큰 숫자 위의 라벨이 모드와 상관없이 「강화 성공 확률」이었다 —
  대수선·분해·봉인에 맞게 바꿨다.

`tests/gear-seal.test.cjs` 2개. **일부러 깨뜨려 보고** 확인했다 (강화 차단 제거 →
실패, 분해 차단 제거 → 실패).

> 만들면서 내가 넣은 버그도 하나 잡았다. 모드 분기에 `else if(mode==='seal')` 를
> 끼워 넣는 바람에 **봉인 패널이 영영 안 그려지는** 상태였다. 코드를 다시 읽어
> 찾았다 — 화면으로 봤으면 바로 보였을 것이고, 실제로 화면으로 확인했다.

## 3. 서비스워커가 **한 번도** 프리캐시를 한 적이 없었다

이게 이번에 찾은 것 중 제일 크다.

```
프리캐시 캐시: tw-dev      항목 수: 0        ← 282개를 담았어야 한다
```

원인:

```js
ASSETS.push('js/marsh-motion.js','art/3d/boss_marsh_v2.glb', …);
/*                                ↑ 위 ASSETS 배열에 이미 있다 */
c.addAll(ASSETS.map(…)).catch(function(){});
```

`cache.addAll` 은 **전부 아니면 전무**다. 목록에 같은 주소가 두 번 있으면
`InvalidStateError` 로 통째로 거절되는데, 그걸 `.catch(function(){})` 가
**말없이 삼켰다.** 설치는 성공한 것처럼 보이고, 캐시는 빈 채로 남는다.

그래서 「한 번 불러온 뒤에는 오프라인에서도 열립니다」는 **실제로 방문한 화면에만**
해당됐다. 나머지는 전부 오프라인에서 안 열렸다.

고친 것:

- 중복 제거 + 목록에서 한 번 더 걸러낸다.
- `addAll` → **하나씩 `add`**. 한 개가 빠져도 나머지 280개는 살아남는다.
- 실패는 삼키지 않고 개수를 콘솔에 남긴다.

```
프리캐시 항목: 0 → 281   (HTML 26장 전부 포함)
오프라인에서 office.html → status 200 · 「황혼 — 인력사무실」
```

### 덤 — `offline.html` 도 죽어 있었다

연결 없음 화면이 만들어져 있는데 **서비스워커가 한 번도 쓰지 않았다.**
프리캐시 목록에도 없었다. 넣고, 탐색 실패의 마지막 대체로 쓰게 했다.

쓰면서 또 하나: 원래 쓰려던 `r || caches.match(A) || caches.match(B)` 는
**`caches.match` 가 프로미스라 항상 참**이라 B 까지 절대 안 간다. 차례로
기다리게 고쳤다.

`tests/sw-precache.test.cjs` 3개 (중복 없음 / 파일 존재 / 대체 화면 연결).
중복을 되살리면 1번이, 대체 화면을 떼면 3번이 정확히 실패한다.

## 4. 이번엔 «찍어 보지 않고» 결론 내지 않았다

지난 두 번 「서버에 없다」고 잘못 말했다. 그래서 이번 감사는 **grep 이 아니라
실행**으로 했다.

| 검사 | 방법 | 결과 |
|---|---|---|
| 죽은 페이지 링크 | 전 HTML 의 `href` 를 파일 존재와 대조 | **0건** |
| 화면별 404·콘솔 오류 | 20화면 헤드리스 로드 | `version.json` 만 (배포 때 생성 — 정상) |
| 서버 명령 ↔ 클라이언트 | `rpg-server.cjs` 의 op 전부 vs 세 클라이언트 | **전부 연결됨** |
| 의뢰 → 던전 연결 | `routeForQuest` 를 6개 의뢰에 실행 | **전부 있음** |
| 인바운드 없는 화면 | 전 HTML + 개발 독 목록 대조 | 검수 도구 4 + 리다이렉트 1 (정상) |
| 서비스워커 프리캐시 | 실제 캐시 항목 수를 읽음 | **0개 — 고침 (§3)** |
| forge 봉인 | 눌러 봄 | **죽어 있었음 — 만듦 (§2)** |

`quest.html` 의 「준비 중 — 다음 업데이트」 가지는 의뢰 6개가 전부 루트를 가지므로
**도달하지 않는 죽은 코드**다. 사용자에게는 안 보인다 — 그대로 뒀다.

## 5. 아직 없는 것 (지시 받고 한다)

- **파티 모집 화면** (설계 시트 03). `party.html` 은 온라인 허브로 바뀌었고,
  시트가 그린 4인 카드·특성 등급표·채팅·모집 시작 화면은 구현이 없다.
- **길드 가입 신청·승인.** 지금은 초대 코드만. 서버에 명령이 없다 —
  넣으려면 `server/` 를 고치고 Render 재배포가 필요하다.
- **운영 도구 화면.** `adminState`/`moderate`/`announcement` 는 서버에 있고
  party.html 에 폼이 있지만, 쉘터에는 없다 (`ADMIN_IDS` 환경변수 필요).
- 쉘터 **화면**의 단위 테스트. DOM UI 라 헤드리스 시나리오로 대신하고 있다.
