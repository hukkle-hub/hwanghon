# 206 — 3D 필드: 구운 2D 맵의 원본 장면을 실시간 3D로 (2026-10-08)

디렉터: «일단은 지피티가 하고 있으니 겹치지 않게 맵을 좀 3d로 구현하고 뽑아보자» · «위에 사진보면 무기도 제대로 못 잡고 있네?»

## 1. 무엇을 — `world3d.html?zone=<id>&char=<id>`

2D 필드(`mmo.html`)의 맵은 원본 3D 장면(`js/mmo/env-*.js` — OSM 실측 건물·도로·소품·결정)을 55° 고정 정사영으로 **구운 그림**이다.
그 원본 장면을 굽기(`tools/2d/bake-map.html`)와 **같은 빌더**로 실시간에 세우고, 3인칭 카메라로 걷는다. 자리·충돌·보스 위치가 2D 필드와 1:1 이다.

| | |
|---|---|
| 장면 | 굽기와 같은 `ENV_FILE` 표 (시험으로 묶음) · 지역 표 `ZONES` |
| 걷기 | `js/mmo/field-collide.js` — mmo.html 의 띠·상자·건물 윤곽·강 띠 규칙을 그대로 옮김 (시험이 두 본문을 대조 — 한쪽만 고치면 실패) |
| 영웅 | 온라인 레이드와 같은 `Animated`(js/party-avatar.js): 아인 바인드·클립 교정 + 양손 쥠 리그 + 솔로와 같은 낫 장착 |
| 2급 지배형 | 같은 자리 · 같은 임시 몸 (문서 204) |
| 카메라 | 오른쪽 끌기 회전 · 휠/두 손가락 거리 · 사이에 1.2 m 넘는 것이 있으면 그 앞까지 당김 (당길 땐 빠르게, 물러날 땐 천천히) |
| 휴대폰 | 왼쪽 45% = 이동 스틱 · 나머지 = 카메라. Pixel 7 가로·세로 가로 넘침 0 |
| 안개 | 70~230 m 노을 안개 — 굽기엔 없던 지평선·띠 끝을 덮는다 |

## 3. 무기 쥠

처음엔 영웅 GLB 에 장비만 달아 낫을 **지팡이처럼 끝을 잡고 왼손이 놀았다** (디렉터 지적). 솔로·레이드는 아인 전용 교정(바인드·클립)과 양손 쥠 리그를
따로 거는데, 필드는 그걸 안 탔다. 3D 필드는 레이드 아바타를 그대로 써서 고쳤다 — 낫을 몸 앞에서 양손으로, 카인은 대검을 어깨에.
**2D 필드(mmo.html)도 고쳤다** — 영웅 생성부에 같은 층(아인 바인드·클립 교정 · 양손 쥠 리그 · 쥔 손 모프 · 팔 돌기 묶기)을 붙이고, 장비(TW_LOOKS)가 무기를 다는 바로 그 손 자리(anchor)를 리그에 넘긴다.
  공격·스킬 중엔 지금 클립·경과·접점을 리그에 넘긴다. 잰 값 — 왼손↔자루 거리: 전 0.629 m(빈손) → 후 0.055 m (3D 필드 0.062 m).

### 3.1 휴대폰 가벼운 모델에서 멈춤 (2026-10-09 새벽 발견 · 바로 고침)

무기 쥠 교정(`a83187e`) 뒤로 **휴대폰 기본(가벼운 모델, LOD)** 에서 2D 필드 그리기가 멈췄다 — 영웅이 안 나온다. 원인 둘:
- 쥔 손 모프(`gripHands`)가 가벼운 모델의 압축 꼭짓점을 실수로 보고 손을 잘게 나누다 뼈 번호를 깨뜨렸다(65535). 카인·세라 — 온라인에선 근처에 오기만 해도 멈춘다.
- 가벼운 아인 모델엔 «새로 짠 몸» 표식(meshSwap)이 빠져, 바인드 교정이 옛 몸 재가중 경로로 들어가 없는 뼈 번호(−1)를 쓸 뻔했다.
→ 쥔 손 모프·아인 바인드 교정은 정식 모델에만. 양손 쥠 리그는 둘 다. 가벼운 모델 아인: 왼손↔자루 0.089 m · 오른손 0.051 m. Pixel 7 가로에서 아인·카인 정상. 시험으로 묶음 (돌연변이 확인).
교훈: 휴대폰 경로(`?lod=1`)도 반드시 띄워 본다 — 데스크톱만 보고 올렸다.

**정정 (같은 새벽, 진짜 원인).** 위 두 원인 진단은 틀렸다. 가벼운 모델은 압축(양자화)돼 있지 않다 — 위치는 Float32 그대로다.
진짜 원인은 **끼워 넣은(interleaved) 정점 속성**: `tools/2d/make-lod.mjs`(gltf-transform)가 위치·법선·UV·뼈 번호·무게를 한 버퍼에
섞어 쓰고, three 는 그 위에 «보기» 를 만든다. 그래서 `.array` 가 버퍼 전체다(카인 skinIndex: 정점 7,895 개에 길이 221,060).
손 모프의 `Array.from(at.array)` 가 그걸 통째로 읽어 다른 속성 값이 뼈 번호로 들어갔다 → 없는 뼈 → `matrixWorld` 오류로 그리기가 멈춤.

- 「65535 · 64,490 개 깨짐」 이라고 잰 것도 같은 함정에 빠진 **잘못된 지표**였다 — 내 측정 코드가 `.array` 를 직접 돌았다.
  `getComponent` 로 다시 재면 0 이다 (CLAUDE.md §2 «지표 자체를 먼저 의심한다»).
- 아인 meshSwap 표식은 정식 모델에도 없다(지금 `ain_anim.glb` 는 옛 몸 그대로). 그 표식으로 막은 탓에 2D 필드에서는 데스크톱까지 아인 바인드 교정이 꺼져 있었다.

→ 고침: `hand-grip.js separateAttributes` 가 끼워진 속성을 떼어 내고(값·정규화 표식 그대로), 손 세분화와 `repairAinBind` 가 먼저 부른다.
2D 필드의 `!LOD` · `meshSwap` 막이는 걷어 내 정식·가벼운 모델이 같은 층을 쓴다. 3D 필드도 휴대폰에서 가벼운 모델을 받는다(`?lod=0|1`, 아인 6.2→2.1 MB · 세라 7.0→1.7 MB).
확인: Pixel 7 가로 · 3D 필드 네 캐릭터 · 2D 필드 카인·세라·아인 — 페이지 오류 0, 뼈 번호(무게 > 0) 깨짐 0. 카인·세라 손 확대: 정식 ↔ 가벼운 모델 쥠 같음
(`.node-shots/w3d/hand-lod-sheet.png`, `hand-sera-sheet.png`). 시험: 끼워진 버퍼로 손을 나눠 뼈 번호가 안 섞이는지 — 떼어 내기를 빼면 실패 (변이 확인).

## 4. 지배형과 싸우기 (순번 2)

- **AI 는 서버 파일 그대로** — `server/field-dominator.cjs` 를 브라우저에서 읽는다 (`js/mmo/cjs-browser.js`: 상대 경로 require 만 따라가는 작은 로더). 두 벌로 갈라지지 않게.
- 서버의 «필드» 자리는 작은 판(`fieldLocal`)이 맡는다: `bossStrike` 는 server/field.cjs 와 같은 규칙 — 회피 무적이면 0, 최대 체력 × 비율, 밀려남, 쓰러지면 5초 뒤 출발점(2초 보호). 방어력·버프는 시험판에 없다.
  회피 0.52초 · 간격 0.78초 · 부활 5초 · 보호 2초 — 서버 값과 같은지 시험이 대조.
- 시계는 게임 시간(ms) — 헤드리스에서도 예고·타격이 동작과 맞는다.
- 내 공격: 접점 예약·히트스톱·궤적·불꽃 (문서 205 그대로) · 지배형 움찔 · 숫자. 지배형 체력 300만(서버와 같음) — 쓰러지면 30초 뒤 제자리.
- 조작: 휴대폰 오른쪽 아래 «공격»(84 px) · «회피»(64 px) · PC J/Space · K.
- 검수 장면: 예고(바닥 부채꼴) → 0.3초 전 회피 «회피» → 내 베기 접점 → 안 피하면 −6,400 (최대 2만의 32%).

## 6. 온라인 — 2D 필드와 같은 방 (순번 다음)

- `js/mmo/field-net.js` — mmo.html 의 접속 규약을 모듈로: hello → welcome(토큰) → (캐릭터 만들기) → fieldJoin → 0.1초마다 field. 저장소 열쇠가 같아 **2D 로 놀던 캐릭터 그대로** 들어온다. 서버는 바꾸지 않았다.
- Pages 에선 기본으로 붙는다 (`?online=0` · `?offline=1` 이면 혼자 연습). 접속이 안 되면 혼자 연습으로 돌아간다.
- 붙으면: 브라우저 AI 는 쉬고 서버가 보낸 지배형 동작·생사를 서버 시계(가장 지연 적은 표본, 거꾸로 안 감)로 그린다 · 다른 사람은 레이드 아바타(양손 쥠)로, 이름표 ·
  내 공격은 `fieldHit` 로 보내고 답(`bossHit`)이 오면 접점 시각에 숫자·불꽃·히트스톱 · 회피는 동작 이름 `dodgeB` 로(서버가 그 순간 무적을 연다) · 체력·피격·부활은 서버 것 ·
  서버 자리와 3 m 넘게 어긋나면 맞춘다 (2D 필드와 같은 규칙).
- 2D 필드에서 노는 사람과 3D 필드에서 노는 사람이 **같은 방에서 서로 보인다** (좌표틀이 같다).

- 확인: 로컬 파티 서버 + 브라우저 1 · 노드 접속기 1 — 서로 보임(«근처 1명», 이름표) · 서버 가시관이 쫓아와 3연타(−7,180 · −5,833 · −11,667)로 쓰러짐 · 5초 뒤 출발점 · 내 타격 «3,954».
- 고친 것: 입장 응답보다 먼저 온 장면을 버리면 상대 정보가 영영 안 온다 (서버는 처음 한 번만 싣는다) — 넘기게 고침.
- 헤드리스 두 화면을 같이 돌리면 한쪽이 메시지를 제때 못 읽어 서버 생존 확인(5초)에 끊긴다 — 시험 환경 탓 (실기기 아님). 두 번째 사람은 노드 접속기로.
- 이 컨테이너에선 프록시 때문에 실서버 웹소켓이 막혀 «접속 실패 → 혼자 연습» 으로 돌아간다 — 실기기 확인 필요.

### 문 — 다른 지역으로

문 둘레(반지름 + 0.8 m)에 서면 «➜ 이동 · 행선지» (던전은 «⚔ 들어가기») · PC E. 열린 지역인지 먼저 묻고, 온라인이면 방을 나간 뒤 다음 지역 3D 로 넘어간다.
넘어간 쪽은 그 문 앞에서 시작한다 (`?gate=`, 온라인이면 서버에도 같은 문으로 입장). 강남대로 5번 출구 → 지하상가 B1 `up5` 자리 확인.

### 필드 보스 (클레이브 등)

2D 필드와 같은 몸 맞춤(키·발 바닥)과 같은 안무(`boss-motion.js` — 서버 시각에 맞춘 클레이브 동작·바닥 예고·접점 불꽃). 온라인이면 서버 생사·동작을 따르고 타격 대상이 된다(답이 오면 접점 시각에 숫자 + 클레이브 맞음 반응 · 반격이면 반격 연출).
혼자 연습에선 대기로 서 있다 (싸움은 지배형만). 강남역 지하상가 클레이브: 대기 · 폭풍 베기(부채꼴) · 내려찍기(원) 확인.

### 하늘 — 노을 돔

굽기는 내려다봐서 하늘이 필요 없었다. 3인칭은 늘 지평선이 보이므로 바깥 지역에만 하늘 돔: 땅 끝은 안개색 → 지평선 노을(`env.sky.horizon`) → 위 보랏빛(`env.sky.top`), 해 쪽으로 빛무리. 카메라를 따라다니고, 정적 합치기·카메라 막이에서 뺀다.
보스 갤러리: 필드 보스 11체 모두 발이 바닥(0 m) · 공중 둘은 정해진 높이(셀레스티얼 3.2 m · 3.4 m). 노바 둘레의 주황 결정 소품은 3D 눈높이에선 보스를 가린다 (위에서 보는 그림에선 작은 가시) — 정리할 일.

## 8. 남은 것

- 원본 장면은 «위에서 보는 그림» 용 로우폴리라 3인칭 가까이선 건물이 상자, 바위가 큰 다면체로 보인다 — 3D 로 갈 거면 건물 외벽·잔해 에셋이 필요하다.
- 일반 몬스터 · 가방·상점 (2D 필드에만 있다). 문(지역 넘어가기)은 들어갔다.

## 9. 노바 방 결정 숲 (view3d 만)

고흥 발사대 갱도 `core` 방은 결정 48개가 18 m 네모 안에 1.8~5.4 m 로 선다 — 위에서 보는 굽기에선 보스 그림이 위에 덮여 괜찮지만,
3D 에선 나노-노바 코어(6 m)가 결정 숲에 통째로 묻혔고, 싸우는 자리의 카메라가 결정(카메라 막이)에 걸려 영웅 등에 붙었다.
재 보니 보스 둘레 7~12 m 가 키 큰 결정 고리였다(카메라 9 m 뒤 = 그 안).

→ `view3d` 일 때만, 가운데 결정(`center`) 중 방 중심에서 10 m(`clear3d`) 안은 높이를 0.9 m 로 («무릎 높이로» — 원작 묘사와도 맞다).
자리·막이·난수 순서는 그대로라 굽기 그림·map.json 막이와 어긋나지 않는다. 10 m 밖 11개만 높게 남아 «결정 산» 테두리가 된다.
확인: `.node-shots/w3d/boss/nova-ba.png`(전) → `nova-after2.png`(후: 내려다본 것 · 6 m 앞 싸우는 시점). 시험으로 묶음(변이 확인).

## 10. 실내 천장 = 카메라 막이

view3d 로 실내에 천장을 얹었는데(§2), 천장은 두께 0.12 m 라 «키 1.2 m 넘는 것» 만 모으는 카메라 막이에서 빠졌다.
카메라를 멀리 당기면(휠·핀치, 위로 기울이기) 천장 위로 나가 천장 윗면만 찍혔다 — 2호선 선로에서 카메라 높이 8.2 m, 천장 5 m.
→ 천장 메시에 `userData.camBlock` 을 달고 `mergeStatic` 이 높이와 상관없이 막이로 모은다(실내·던전 둘 다). 고친 뒤 4.8 m 로 천장 아래에 멈춰 영웅·클레이브가 보인다
(`.node-shots/w3d/boss/ceil-ba.png`). 시험(변이 확인).

곁가지: 같은 곳 «남쪽에서 찍으면 까맣다» 는 내 검수 스크립트가 영웅을 선로 벽 속으로 순간이동시킨 탓이었다(순간이동은 충돌을 안 거친다) — 버그 아님.


## 11. 혼자 연습에서도 클레이브와 싸운다

전엔 혼자 연습(오프라인)에서 필드 보스는 대기 동작으로 서 있기만 했다(싸움은 지배형만). 2D 필드는 혼자 연습에서도 보스를 칠 수 있다.
→ 클레이브(`clave` · `clave2`)는 지배형처럼 **서버 전투 모듈을 그대로** 브라우저에서 돌린다(`loadCjs('server/field-boss-combat.cjs')`).
매 프레임 `COMBAT.tick(fieldLocal, ai, gameNow)` → `COMBAT.view(ai)` → 온라인과 같은 `applyBossAction` 이라 예고 바닥·연계·반격창·셔터 부위가 서버판과 같다.
타격은 서버 `hit()` 순서 그대로: 반격창 판정(`tryCounter`, ×1.65) → 피해 → `damageShutter`. 맞은 결과(회피했나)는 `notePlayerResult` 로 보스가 읽는다.
연습 체력은 2D 혼자 연습과 같은 30만 — 70%·35% 에서 2·3페이즈. 쓰러뜨리면 30초 뒤 다시 선다.

검수(게임 시간 1/30 초 × 1,500 프레임, 붙어서 반격창에 맞춰 치기): 기술 12번(쓸기 6 · 내려찍기 6) · 영웅 피격 12 · 경직 12(반격·셔터 파괴) ·
셔터 완파(state 2) · 2페이즈 진입(남은 체력 66%) · 페이지 오류 0. 화면 `.node-shots/w3d/boss/clave-offline.png`. 시험(변이 확인).

나머지 필드 보스(정 · 무기고 · 레비아탄 · 천상 둘 · 실험체 09 · 그림자송곳니 · 이지스 · 노바)는 서버에도 AI 가 없다 — 맞기만 한다.
혼자 연습에서도 같은 30만 연습 체력으로 맞고, 쓰러지면 숨었다가 30초 뒤 다시 선다(2D 혼자 연습과 같음). 검수: 이지스 4타 12,015 · 처치 · 29초 뒤 복귀.

## 12. 2D 필드 혼자 연습도 보스가 반격한다

2D 필드(mmo.html)는 서버가 없으면(혼자 연습 · 잠든 서버 · `?offline=1`) 지배형·클레이브가 서 있기만 했다 — 맞기만 하는 허수아비.
→ 3D 필드와 같은 방법: 서버 전투 모듈(`field-dominator.cjs` · `field-boss-combat.cjs`)을 `loadCjs` 로 그대로 돌리고, 결과는 **온라인과 같은 통로**로 그린다.
내 피격은 서버 hurt 묶음 그대로 `selfPacket` 에(체력 막대·회피·쓰러짐·부활 문구가 온라인과 같다), 보스 동작은 `applyDominatorAction` / `applyBossAction`.
판정은 server/field.cjs `bossStrike` 와 같다(회피 무적 0.52초 · 셔터 파괴 뒤 피해 배율 · 밀려남 · 5초 뒤 부활 · 부활 무적 2초) — 방어력·버프는 혼자 연습에 없다.
타격은 서버 `hit()` 순서(반격창 → ×1.65 → 셔터). 시계는 `bossNow()`(온라인과 같은 벽시계 축).

검수(헤드리스, 벽시계): 클레이브 70초 — 내려찍기·쓸기 6번 · 피격 9 · 쓰러짐 1 → 5초 뒤 부활 · 셔터 완파 · 보스 피해 20만.
2급 지배형(가시관) 60초 — 찢기·찢기2·지배 11번 · 피격 13 · 쓰러짐 1. 반격창에 맞춰 치기 5번 중 3번 반격 성공(«반격 성공» 알림·푸른 경직 고리) —
놓친 2번은 헤드리스 초당 1~2프레임이라 접점이 창이 닫힌 뒤에 왔다(실기기는 60프레임). 화면 `mmo-off-sheet.png` · `mmo-counter.png`.

## 14. 미니맵 · 사냥터 이름 띠

3D 필드엔 지도가 없었다 — 3인칭은 2D 보다 길을 잃기 쉽다. 2D 필드와 **같은 개관 그림(map.json overview)·같은 좌표식** 으로 오른쪽 위에 미니맵:
나(방향 화살표 — 앞 (sin yaw, cos yaw) 을 그림의 x 오른쪽 · z 아래로, 내려다보는 각만큼 세로를 눌러서) · 문(파랑, 던전은 빨강) · 보스·지배형(빨강, 살아 있을 때) · 다른 사람(흰 점).
누르면 크게(사냥터·쉼터 이름까지). 사냥터에 들어서면 2D 와 같은 이름 띠(«Lv 78~81 · 2급 지배형 · 포획자 · …» — 문서 207·208 의 배정).
Pixel 7 가로·세로: 제목·공격·회피 단추와 안 겹침 · 이름 띠 화면 안 · 가로 넘침 0 · 누르면 커짐 (`.node-shots/w3d/mini-*.png`). 화살표 방향은 꼭짓점을 확대해 확인(yaw 0.8 → 오른쪽 아래).

## 15. 회복약 (2D·3D)

3D 필드엔 회복약이 없었고, 2D 필드 혼자 연습은 «혼자 하기에는 회복약이 없습니다» 였다 — 보스 연습(§11·12)에 회복 수단이 없었다.
- 3D: 회피 위에 «회복약» 단추(64 px) · Q 키. 온라인 = 2D 와 같은 서버 가방(`fieldBag use c_potion`, 개수 표시 · 답 `fieldBagDone` 에 +회복).
- 혼자 연습(2D·3D): 서버 `potion()` 과 같은 규칙 — 최대 HP 35% · 1초에 한 번 · 쓰러졌거나 가득이면 안 씀 — 개수 제한 없이(«연습» 표시). 시험이 서버 값과 묶는다.
- Pixel 7 가로·세로: 공격·회피·미니맵과 안 겹침. 6,000 → 13,000(+7,000 = 2만의 35%) · 2D 5,000 → 12,000 (`potion-sheet.png`).

## 16. 카메라가 지붕·건물 속으로 — 막이 두 구멍

강남 «무너진 이면 블록» 순찰 자리에 서자 영웅이 안 보였다 — 카메라(높이 3.3 m)가 높이 2.9 m 지붕 위에 떠서 시선이 지붕을 뚫었다.
카메라 당기기(`firstHit`)는 «카메라를 막는 것» 의 감싸는 상자를 쓰는데, 구멍이 둘 있었다.

1. **머리가 상자 안이면 그 건물을 건너뛰었다** (`containsPoint(at) → continue`). ㄷ·ㅁ자 건물·마당 낀 블록은 상자 안에 걸을 수 있는 땅이 있다.
2. **재질이 여럿이거나 자식이 달린 메시는 막이에서 통째로 빠졌다** — 합치기에서 빠지는 줄(`return`)이 상자 모으기보다 앞에 있었다. 건물·나무가 대부분 여기 걸렸다.

고침 (`js/mmo/static-merge.js`): 둘 다 막이에 넣고, 4 m 넘는 것은 **실제 면**(월드 좌표 위치만, 368채 · 정점 2.2만 — 강남)을 남긴다. 상자는 후보일 뿐 — 실제 면이 있으면 면으로 확인한다(머리가 상자 안일 때도, 둥근 나무 상자의 빈 모서리일 때도).

**지표부터 틀렸다.** 처음엔 «원하는 카메라 자리 → 머리» 광선을 화면 재질 그대로(바깥면만) 쐈다. 카메라 자리가 건물 **속**이면 안쪽 면이 안 맞아 «가림 없음» 으로 셌고, 고친 뒤엔 그 당김이 전부 «괜히 당김» 으로 보였다(강남 4 → 163).
양면으로 쏘자 맞아떨어졌다 — 카메라가 건물 속인 것도 가림이다(화면은 바깥면만 그려 벽 너머로 보이긴 하지만).

걸을 수 있는 무작위 300점 × 4방향 = 1,200 시점 (Pixel 7 카메라 6 m · 숙임 0.32):

| 지역 | 영웅을 못 보는 시점 (전 → 후) | 괜히 당김 (전 → 후) |
|---|---|---|
| 강남 | 102 (8.5%) → **3 (0.3%)** | 3 → 3 |
| 서귀포 | 94 (7.8%) → **1 (0.1%)** | 3 → 4 |
| 전주 | 153 (12.8%) → **0** | 4 → 5 |
| 판교 연구소 | 150 (12.5%) → **5 (0.4%)** | 16 → 17 |
| 강남 지하 B1 | 3 → 3 (천장 막이 그대로) | 16 → 16 |

- 남은 것: 영웅 바로 앞 1.75 m 물체(차량류) · 두께 1.2 m 미만 차양. 판정 1회 0.03~0.1 ms (전 0.03~0.05).
- 그림 `.node-shots/w3d/camfix-gangnam.png` (왼쪽 전 = 지붕만, 오른쪽 후 = 영웅). 시험 `tests/cam-block.test.mjs` — ㄷ자 건물 마당에서 옆 지붕 쪽은 당기고 열린 입구 쪽은 안 당김 · 재질 둘인 건물도 막이 (고치기 전 코드로 둘 다 실패 확인).
