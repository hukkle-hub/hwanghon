| 잠금 | 하드 락온 없음. 카메라로 조준한다 | 포커스 카메라가 소프트 락온. 단 «부위» 를 노리려면 각도를 직접 잡아야 해서 상급자는 타깃을 쓴다 |

## 1. 카메라 — v0.5 에서 고친 것

**증상.** 캐릭터가 돌아도 화면이 안 따라왔다. 원인은 추적 속도였다 — 탐색 중 `dt*0.9`,
즉 **시정수 약 1.1초**. 90° 꺾으면 1초가 넘게 카메라가 뒤처진다.

시정수(tau)로 다시 잡았다. tau 는 «목표 각도의 63% 를 따라잡는 시간» 이고
`camYaw += Δ·(1−e^(−dt/tau))` 로 프레임률과 무관하게 같은 속도가 나온다.

| 상황 | 전 | 후 | 근거 |
|---|---|---|---|
| 탐색 이동 | ~1.1초 | **0.26초** | 마영전처럼 달리는 방향 뒤로 바로 붙는다 |
| 전투(락온 끔) | ~0.6초 | **0.30초** | 몬헌 «타깃» — 보스를 담되 조작은 안 뺏는다 |
| 전투(락온 켬) | ~0.22초 | **0.16초** | 몬헌 «포커스» — 계속 문다 |
| 멈춰 있을 때 | 계속 돈다 | **안 돈다** (`idleHold`) | 서 있는데 카메라가 돌면 멀미가 난다. 몬헌도 안 돌린다 |

같이 넣은 것

- **선행 주시(look-ahead) 1.1 m** — 주시점을 진행 방향으로 밀어 «가는 곳» 이 보인다 (마영전).
- **보스 크기 반영 거리** — 보스 높이 2.2 m 를 넘는 만큼 물러난다 (`sizeDist 0.55`/m). 몬헌 방식.
- **자세(pitch) 전환** — 전투 0.42 / 탐색 0.50. 싸울 때 낮게 깔아 보스가 커 보인다.
- **화각 반응** — 회피 50→57° (속도감), 큰 타격 50→46° (무게감). 시정수 0.10초로 금방 돌아온다.
- **손이 이긴다** — 드래그하면 `dragT` 동안 자동 추적이 멈춘다. 락온 중 드래그는 대상 주위를 도는 것으로 살려 뒀다(예전엔 무시했다).

검수 (헤드리스, 네 방향 각각 충분한 게임 시간 뒤 측정)

| 방향 | 캐릭터 화면 위치 | 정후방에서 벗어난 각 | 거리 |
|---|---|---|---|
| 북 | 50% / 74% | 0° | 6.5 m |
| 동 | 50% / 74% | 0° | 6.5 m |
| 남 | 50% / 74% | 2° | 6.5 m |
| 서 | 50% / 74% | 0° | 6.5 m |

화면 세로 74% = 캐릭터가 아래 1/3 에 오고 위쪽이 트인다 — 두 게임의 구도다.

> 헤드리스는 실시간의 ~10% 로 돈다. 처음에 4.2초(벽시계)만 기다려 재고 «50° 어긋난다» 는
> 오판을 했다. 게임 시간으로 기다려야 한다 — 이 함정은 세 번째다.

## 2. 이미 맞춰 둔 것

벤치마크 관점에서 이미 두 게임 규약과 같은 것들 (앞선 작업에서 들어갔다).

| 항목 | 상태 |
|---|---|
| 일반타 4연 + 스매시 마무리 | 마영전 규약대로 (`js/dungeons.js` RULES.combo) |
| 스태미나 / SP(궁극기) 게이지 | 있음 |
| 부위 파괴 → 패턴 약화 | 몬헌 규약. 부수면 그 부위가 맡던 연계 타격이 빠진다 |
| 예비동작 읽기 · 지연타(hold) | 모션으로 읽게, 게이지는 훈련장에만 |
| 히트스톱 계층 · 궤도 재개 | 몬헌식. 맞으면 멈췄다 궤도가 이어진다 |
| 락온 토글 | 몬헌 포커스/타깃에 해당 |
| 처형 · 페이즈 전환 컷 | 있음 |

## 3. 남은 격차 — 다음 순서

우선순위는 «한 판 돌렸을 때 눈에 띄는 순서» 다.

1. **카메라 충돌·벽 밀림** — 지금 `camClear` 가 거리만 줄인다. 두 게임은 벽에 닿으면
   카메라가 **미끄러진다**. 벽 법선으로 밀어내는 처리가 필요하다.
2. **타격 순간의 카메라** — 스매시·처형에 짧은 궤도 흔들림(회전 킥)이 없다. 지금은 위치 흔들림만.
3. **회피 무적 연출** — 마영전은 회피 성공 순간 잔상 + 짧은 슬로우. 우리는 잔상만.
4. **보스 «포효» 연출** — 몬헌의 시작 포효처럼 페이즈 진입에 카메라를 보스로 돌리는 짧은 컷.
   페이즈 전환 컷은 있으나 **전투 시작** 에는 없다.
5. **그래픽** — 그림자 해상도·접지 그림자(AO)·안개 깊이. 지금 캐릭터가 바닥에서 떠 보이는
   구간이 있다.
6. **모션** — 이동 시작/정지 전환 클립이 없어 달리기가 «톡» 끊긴다. 몬헌은 정지에 브레이크
   모션이 있다. CMU 143_02 «Run to Stop» 이 이미 받아져 있다.
7. **무기별 리듬** — 몬헌의 무기 개성. 우리는 캐릭터별 클립은 갈랐지만 «속도·경직» 은 공용이다.

## 4. v0.6 — 위 일곱 항목 전부 반영

「전부다 반영해」. §3 의 1~7 을 모두 넣었다. 들어간 값과 «왜 그 값인지» 를 남긴다.

### 4.1 카메라 벽 미끄러짐 (§3-1)

거리만 줄이던 `camClear` 를 **각도로 미끄러지는** 처리로 바꿨다 (`js/game3d.js`).

- `rayFree(look, yaw, dist)` — 주시점에서 그 각도로 광선을 쏴 **처음 막히는 거리** 를 돌려준다.
- `camClear(look, dist, dt)` — 원하는 각도가 막히면 ±0.16 ~ ±1.25 rad 을 훑어 **트인 쪽** 을 찾고,
  `camSlide` 를 그쪽으로 시간상수로 민다. 카메라 위치는 `yawEff = camYaw + camSlide` 로 잡는다.
- 트인 각이 없을 때만 예전처럼 거리를 줄인다 (구석에 몰렸을 때).

즉 벽을 만나면 **당겨지는 게 아니라 옆으로 돈다** — 두 게임의 감각이 이것이다.
`camYaw` 자체는 건드리지 않으므로 벽에서 떨어지면 원래 각으로 되돌아온다.

### 4.2 타격 회전 킥 (§3-2)

위치 흔들림(`shake`) 과 별개로 **궤도 회전** 을 튕긴다. 감쇠 진동자 하나:

```
ω=26, ζ=0.42      a = -ω²k - 2ζω·v
```

0.24초쯤에 잦아든다 — 한 대 칠 때마다 맞고, 연타에서도 뭉개지지 않는 길이다.
roll 은 `cam.up` 을 기울여 넣는다(화면이 «비틀린다»). 붙인 곳과 세기(yaw/pitch/roll, rad):

| 순간 | yaw | pitch | roll |
|---|---|---|---|
| 처형 | 0.050 | 0.100 | 0.075 |
| 궁극기 | 0.040 | 0.085 | 0.060 |
| 스매시 | 0.022 | 0.045 | 0.032 |
| 회피 | 0.018 | −0.030 | −0.026 |
| 전투 시작 포효 | 0.050 | 0.110 | 0.050 |

회피만 pitch 가 음수다 — 몸을 낮추는 동작이라 시선이 **내려가야** 맞는다.

### 4.3 회피 무적 연출 (§3-3)

`fxEvade()` — 지나온 자리에 가산합성 캡슐 3개를 남기고 링 하나. 여기에
`slowmo(0.30, 240)` 을 얹었다. 240ms 는 회피 무적(`rollDur`) 안에서 끝나는 길이라
**슬로우가 걷히는 순간 = 무적이 끝나는 순간** 이 된다. 마영전의 규약이다.

### 4.4 전투 시작 포효 컷 (§3-4)

배너(1700ms) 뒤로 이어 붙였다.

- **2200ms** — 카메라가 보스 머리(`bossHitPos('head')`) 로 밀고 들어간다.
- **2620ms** — 포효: `shake(0.02,700)` + 회전 킥 + 진동 `[50,40,70]` + `slowmo(0.45,420)`
  + 충격 링(반경 6.5) + 파티클.

페이즈 전환 컷과 같은 문법이라 «시작 — 전환 — 처형» 이 한 계열로 읽힌다.

### 4.5 접지 그림자 (§3-5)

그림자맵과 **별개** 인 원판 그림자. 64px 방사 그라디언트 캔버스 텍스처 하나를 공유한다.

```
y = 발 높이            k = max(0.25, 1 − y·0.55)
크기 = 1/k·0.9 + 0.1   불투명도 = 0.9·k
```

뜰수록 넓고 옅어진다. 플레이어·보스(`js/game3d.js`), 온라인 원격 캐릭터(`js/party-avatar.js`)
모두에 붙였다. 보스 반경은 `BOSS_SCALE` 을 따라간다(마시는 네발이라 2.6배, 나머지 1.7배).

> 이 텍스처를 모듈 최상단에서 만들었더니 `party-avatar.js` 를 import 하는 node 테스트가
> `document is not defined` 로 죽었다. **처음 쓸 때** 만들도록 고쳤다(`blobTex()`).

### 4.6 정지 브레이크 모션 (§3-6)

CMU **143_02** 「Run to Stop」 의 55~155 프레임(120fps) → `art/3d/mocap/mo_brake.bvh`
(24fps 20프레임, 순회전 +12°). 네 캐릭터 `*_anim.glb` 에 구워 **클립 28개** 가 됐다.

재생 조건 — 달리다 멈추는 **그 순간만**:

```
!moving && ain.base==='run' && !ain.oneshot && !ain.dead && P.rollT<=0
```

`ain.braked` 플래그로 한 번만 나가게 하고, 다시 움직이면 푼다.
브레이크는 `CARRY['run']` 을 그대로 물려받아 무기를 든 손이 흐트러지지 않는다.

### 4.7 무기별 리듬 (§3-7)

같은 클립을 쓰되 **속도·멈춤·스태미나** 를 캐릭터마다 갈랐다 (`RULES.rhythm`).

| 캐릭터 | 무기 | 동작 길이 | 히트스톱 | 회피 스태미나 |
|---|---|---|---|---|
| 아인 | 낫 | 1.00 | 1.00 | 1.00 |
| 카인 | 대검 | **1.20** | **1.28** | 1.14 |
| 류 | 쌍단검 | **0.82** | **0.74** | 0.86 |
| 세라 | 시약 | 1.06 | 0.86 | 1.04 |

카인은 느리지만 한 대가 «걸린다». 류는 빠르고 가벼워 멈춤이 짧다.
세라는 던지는 무기라 속도는 중간인데 **멈춤만 얕다** — 손맛이 맞는 쪽으로.
`js/combat.js` 에서 `rDur`(속도 나누기) · `rStop`(히트스톱 곱) · `rSt`(스태미나 곱) 로 들어간다.
시뮬레이션 안에서만 쓰므로 **온라인에서도 서버가 같은 값을 쓴다**.
