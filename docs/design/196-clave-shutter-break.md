# 196. 클레이브 셔터 부위파괴 — 작은 화면에서는 실루엣이 부서져야 한다

> 2026-10-07 · `visualH 4.2 m` 보스 체급을 기준으로, 미세한 금 대신 큰 셔터 덩어리가 실제로 떨어지는 수직 구현.

## 서버

- 셔터 내구도는 보스 HP와 별개이며 서버 밖으로 숫자를 보내지 않는다.
- 공개 상태는 `part: 0/1/2`(정상/균열/파괴)뿐이다.
- 셔터 내구도는 보스 최대 HP의 8% 상당. 아인은 부위 피해 ×1.4, 다른 영웅 ×0.75, 반격 성공은 추가 ×2.0.
- 균열은 55% 이하, 0이 되면 1.5초 경직.
- 파괴 뒤 직선 셔터 돌진은 선택하지 않는다. 보스는 0.2 m/s 빨라지고 기술 뒤 회복이 80 ms 짧아진다.
- 남은 반쪽 셔터로 쓰는 폭풍/내려찍기 피해는 각각 84%/88%로 줄어든다. 약화만 되지 않게 추적 템포는 더 공격적으로 변한다.

## 모델/화면

- Hi3D 원본에서 셔터는 이미 몸과의 경계가 잘리고 왼손 뼈에 100% 고정돼 있었다. 리깅 파이프라인에서 이 정점을 `Boss_HeldPart`라는 별도 SkinnedMesh로 실제 분리해 GLB에 내보낸다.
- 웹은 `Boss_HeldPart`의 삼각형을 긴 축 기준 약 55%만 남긴 geometry를 로드 시 미리 만든다.
- 파괴 상태가 오면 intact geometry를 반쪽 geometry로 교체한다. 즉 텍스처 균열이 아니라 실루엣이 즉시 달라진다.
- 동시에 큰 금속 박스 파편 하나가 손 위치에서 튀어 나와 중력으로 떨어지고 약 2.8초 남는다. 불꽃 42개와 큰 충격 고리를 재사용한다.
- 파괴 공지는 서버 전체, 같은 지역에서는 금속 파괴음과 짧은 화면 흔들림을 추가한다.

## 검수

데스크톱/Pixel 7 가로·세로에서 정상 → 균열 → 파괴, 파괴 전후 실루엣, 바닥 텔레그래프 가림 여부를 실제 프레임으로 확인한다. `Boss_HeldPart`가 없는 옛 GLB에서도 서버/연출은 죽지 않고 동작하되, 최종 합격은 새로 구운 GLB에서 반쪽 실루엣이 보이는 경우에만 한다.

## 2026-10-07 실제 저장소 적용

원본 Hi3D 파일이 없는 환경에서도 `tools/3d/split_clave_held_part.py`로 기존 GLB의 왼손 100% 고정 삼각형 15,032개를 분리했다. 총 59,999개 삼각형을 몸/셔터에 나눠 손실·중복 없이 보존했고, 원본 바이너리 데이터와 스킨, 애니메이션 20개의 정의는 변경하지 않았다. 셔터 경계의 소수 손 삼각형은 몸에 남긴다. 새 원본 재리깅 경로도 분리 메시를 계속 내보낸다.

패키지에서 발견된 `brokenShutterGeometry`의 `comp` 선언 오류를 수정했다. 실제 geometry 테스트에서 원본을 보존하면서 삼각형 감소를 검사하고, 감소를 고의로 없애면 테스트가 실패하는 것을 확인했다. 기존 고정 패턴 테스트는 돌진을 명시적으로 지정하고, 회피 학습 테스트는 공격 사거리 안에 배치했다. 공개 패킷 허용 목록에 숫자 내구도를 제외한 `part` 상태만 추가했다.

화면 확대 후 가로에서도 보스가 화면 밖으로 잘려 나가지 않게 플레이어/보스 공통 초점을 사용한다. 실제 GLB의 왼손 셔터는 yaw 0에서 +X에 있으므로, 서버의 부위 노출 방향도 +X에 맞췄다. 기존 패키지의 -X 판정은 반대편을 약점으로 삼는 오류였다.

정지된 mixer 클립의 캐시 때문에 idle 추가 회전이 매 프레임 누적되던 문제도 수정했다. `prepareBossMotion`에서 직전 추가 회전을 되돌린 후 mixer를 평가한다. 200회 반복 복원 테스트로 팔 회전의 누적을 막았음을 확인했다.
